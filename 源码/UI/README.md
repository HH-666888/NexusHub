## 设计主张

**一句话：白纸、蓝笔、圆角，像一件现代工具，而不是一块大屏。**

参考你给的四张图（欢迎页 / 设置页 / 画布 / 登录页），只取视觉体系，页面结构按功能重排：

- 白底 + 极淡径向渐变；卡片 12–20px 圆角、1px 浅描边；阴影只负责"浮起"，不做戏剧感
- 一个主色 `#2563eb`：主按钮、选中态、进度、链接都用它；状态色只留给「通过 / 待确认 / 未通过」
- 全部无衬线；标题 700–800 字重、`-0.02em ~ -0.03em` 字距，正文 13.5–16.5px
- 图标统一 1.6px 描边、24 的网格里画，尺寸只在 17/19/23/25 四档
- 两套主题只换值不换结构：`<html data-theme="light|dark">`

## 树型工作流 + 三栏工作台（`pages/workbench.html`）

这一页把之前定的两条并到了一起，不再是四象限：

```
┌────────────────────────────────────────────────────────────┐
│ 顶栏：项目名 · 运行中（第 3/6 道）· 预算 · 代码开关 · 暂停    │
├──────────────┬──────────────────────────────┬──────────────┤
│ 任务清单      │ 工作流树                      │ 实时代码流    │
│ 一级/二级/三级│ 一级主控 → 六道 → 三级任务     │ 可隐藏        │
│ 依次出现      │ 卡片与连线依次向下生成          │ 70ms 一行     │
├──────────────┴──────────────────────────────┴──────────────┤
│ 事件 / 终端 / 验收 · 本轮花费                                │
└────────────────────────────────────────────────────────────┘
```

**两种排布（画布右上角切换，或 `?layout=lr|td`）**

| 维度 | 左右树（`lr`） | 上下树（`td`） |
|---|---|---|
| 生长方向 | 根在左，六道竖排，三级再往右 | 根在上，六道横排，三级往下 |
| 宽度 | 三列固定 ≈660px | 一行六道 ≈684px |
| 高度 | 随分支数增长 | 随层级增长 |
| 并行分支 | 兄弟竖排，4 个以上也不挤 | 兄弟横排，3 个以内并排比较最直观 |
| 卡片宽度 | 200px，长名字放得下 | 104px，只能用短名 |
| 适合 | 分支多、层级深、屏幕窄 | 分支少、演示投屏、想看全貌 |

**树的三层**（对应我们之前约定的主控模型）：

| 层 | 内容 | 怎么出现 |
|---|---|---|
| 一级 | 主控 Agent：拆需求、派活、收口、决定要不要停下来问 | 第 0.1s |
| 二级 | 六道工序：需求拆解 → 架构定型 → 三方向生成 → 集成装配 → 自动验收 → 交付 | 0.38s 起每 0.17s 一道，每道出现后 40ms 画出它那截连接线 |
| 三级 | 主控按需分析出来的活（数据库 / 后端 / 前端，之后还有"继续分析…"占位） | 1.48s 起每 0.2s 一个，挂在第 3 道右侧 |

为什么用**竖向树**而不是横排六节点：横排在 720px 宽的中间栏里放不下六张卡，而且"依次向下生成"这句话本来就是竖的。竖向还有一个好处——以后三级、四级往下长，只需要往下滚，不用横向铺开。

**单体聚焦 × 并行**（这一版两种状态都做了：点任意工序卡进入聚焦，`?focus=3` 可直接进）

- **并行**是"同一道工序下多条分支同时跑"（当初定的并行粒度是**模块**而不是文件，因为文件级并行会产生大量合并冲突）。界面上要付三笔代价：① 顶部状态不能只写"第 3 道"，要写"第 3 道 · 2 个分支并行"；② 每个分支要有自己的进度条与"并行"徽标，不能只高亮一个节点；③ 底部成本按分支聚合，否则总数对不上。
- **单体聚焦**是"只看其中一条"，和并行不冲突：它只是把其他分支折叠起来，执行照旧。必须付三笔代价：① 顶上要有聚焦条（否则不知道自己在哪里）；② 必须写明"其余 5 道工序在后台继续"（否则会被读成"停了"）；③ 右侧代码流要跟着聚焦对象切换。
- 两者组合的选择：分支 ≤ 3 用上下树（并排比较）；分支 ≥ 4 或层级 ≥ 4 用左右树（竖排不挤），必要时再聚焦。
- 已知的取舍：聚焦会遮住其他分支的失败。现在的做法是保留顶部 Pill 与底部全局事件条，失败仍会冒出来；更彻底的做法是在聚焦条上加"其余分支 1 个失败"的红点。

**代码流**：右侧一栏，行号 + 语法高亮，每 70ms 追加一行，正在写的文件顶部标「流式写入 · N 行」，末尾有光标；顶栏「代码」按钮与面板右上角「›」都能收起，收起后中间树自动占满（`?code=off` 可直接进这个状态）。

**玻璃收力**：这一页只用很轻的一层——任务清单 `rgba(255,255,255,.72)`、树卡 `rgba(255,255,255,.86)`、代码面板 `.78`，模糊 8–12px，**没有任何外发光**；只有"当前工序"和"正在写的前端页面"两个节点有蓝圈，靠这个引导视线。

## 两种外观：素面 / 玻璃

同一份 HTML 两种皮肤，靠 URL 参数切换，便于并排比较：

| 外观 | 怎么打开 | 性格 | 适合 |
|---|---|---|---|
| **素面**（默认） | `…/welcome.html` | 白底、细边、克制的阴影 | 长时间使用、投屏、打印式清晰 |
| **玻璃态** | `…/welcome.html?style=glass` | 背景有蓝青光晕、卡片半透模糊、按钮发光 | 首屏展示、演示视频、让人"哇"一下 |

深色同理：`?theme=dark&style=glass`。

玻璃态的实现原则（`system/glass.css`）：

1. **背景必须先有颜色** —— 没有色块就没有"透"可言，所以加了四团模糊径向渐变（蓝 / 青 / 浅蓝 / 靛）；
2. **卡片半透 + backdrop-filter** —— `rgba(255,255,255,.88→.46)` 斜向渐变，内描边 1px 白色做高光，外侧只留一层柔影；
3. **光只落在会被点的东西上** —— 主按钮、当前工序、进度条才有发光；正文和表格一律不发光；
4. **工作区要安静** —— 画布区额外压一层白纱，否则色块透上来会干扰读节点。

## 五个页面各自解决什么

| 页面 | 谁在看 | 要回答的问题 | 关键元素 |
|---|---|---|---|
| **welcome** | 第一次来的人 | 这是干什么的？靠不靠谱？ | 一句话标题、需求输入 + 生成、六道工序卡、三条能力（可观测 / 可预算 / 可干预） |
| **login** | 老用户 | 怎么进去？ | 居中卡片、账号 + 密码、第三方登录、"还没有账号" |
| **projects** | 登录后 | 我造过什么？哪个在等我？ | 顶部一句新需求、四个筛选、六张状态卡（新建 / 运行中 / 待你确认 / 验收 6/6 / 验收 4/4 / 验收 4/6） |
| **canvas** | 正在等结果的人 | 现在到哪一步？花了多少？ | 左：运行历史；中：六节点流程图 + 三方向子任务 + 终端；右：事件流 / 本轮预算 / 工序详情 |
| **settings** | 要换模型或控成本的人 | 用谁的大脑、花多少、长什么样 | 模型提供商三选一、API Key、决策/执行模型、两个预算滑杆、两套主题预览、底部保存条 |

## 文案（全部重写）

首页那句话是整站的地基。参考图说"输入一句话，生成一个可运行的软件"，我保留同样的直白，只把承诺说得更实：

- 标题：**输入一句话，生成一个可运行的软件**
- 副标：Nexus 把需求拆成六道工序，由 AI 自主构建、集成并验收，最后交给你一个能打开、能点、数据存得住的完整软件。
- 输入框：描述你的软件需求，例如：做一个番茄钟网页应用
- 三块能力：**可观测**（每一步都在你眼前）/ **可预算**（签下需求前就看到预估花费）/ **可干预**（拿不准的地方它先停下来问你）

其余页面的文案原则：写"会发生什么"，不写形容词；状态用「验收 6/6」「待你确认」这种能对账的说法。
