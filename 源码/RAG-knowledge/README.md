# RAG-knowledge

这是 NexusHub 的唯一知识源目录。

## 两种状态

```
RAG-knowledge/
├─ 01-主题.md          ← 正式语料，后端会扫描、切片、入库
├─ 02-主题.md
└─ _staging/           ← 草稿区，后端不扫描
   └─ README.md
```

- **正式语料**放在本目录根下，扩展名 `.md`
- **草稿、摘录、未整理的材料**放在 `_staging/`
- 草稿整理好之后，移动到上一级目录，再执行一次重建索引

`README.md` 本身是说明文件，不参与检索。

## 数据流

```
草稿（_staging）
  → 整理成正式 markdown（本目录根下）
  → 后端按二级标题切片
  → 写入 rag_documents / rag_chunks
  → 需求分析、架构设计检索并注入提示词
  → 工作台显示“参考依据”
```

**片段不单独落成文件。** 源文档是唯一真相，片段和向量由后端生成并存入数据库。否则会出现源文档、片段文件、数据库三份副本，改一处忘一处。

## 文件格式

```markdown
# 主题

## 可以独立检索的小节

正文……一个判断一段，不要写成散文。
```

约定：

| 项 | 规定 |
|---|---|
| 编码 | UTF-8 |
| 命名 | `01-主题.md`、`02-主题.md`，按顺序编号 |
| 切片 | 按 `##` 切，512 字 / 重叠 64 |
| 大小 | 单篇 < 20KB；明显更长的拆成多篇 |
| 语言 | 中文；专有名词保留英文 |
| 禁止 | 密钥、手机号、真实用户隐私、未核实的数据 |

## 索引与更新

后端启动后第一次检索会自动建索引；也可以手动重建：

- 重建索引接口：`POST /api/rag/reindex`
- 检索测试接口：`GET /api/rag/search?q=...`

入库时按文件 sha256 比对，只重建变过的文档。换了向量模型必须整库重建，否则向量不可比。

## 当前语料

六篇：模块拆分、验收标准、数据库设计、接口契约、前端请求、测试与交付。共 30 个切片。

向量是本地字符 n-gram 哈希，不是语义大模型 embedding；技术文档里必须如实写。
