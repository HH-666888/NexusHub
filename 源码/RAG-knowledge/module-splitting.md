# 模块拆分

## 默认拆成三层
一个小型 Web 工具默认拆成数据库、后端接口、前端页面三层。数据库负责表结构与索引，后端负责路由、校验和持久化，前端负责交互与展示。三层各自有明确输入输出，不把 SQL 写进页面，也不把 HTML 拼进接口。

## 按职责拆，不按文件数量拆
模块边界看职责，不看代码行数。一个模块可以只有一个文件，也可以有多个文件；判断标准是它是否能独立说清楚“我负责什么、我依赖谁”。同一职责不要拆成两个模块，否则会出现字段和路由各写一套。

## 依赖方向必须单向
后端依赖数据库的表结构，前端依赖后端的接口契约。依赖只能从上层指向下层，不能反向。出现循环依赖时，优先合并模块，而不是加一层转发。

## 先定契约再写实现
模块拆分完成后，先写清楚每个模块的文件路径、导出内容、依赖关系和验收覆盖，再开始生成代码。契约不清时，先补契约，不要靠模型猜。

## 三个模块是默认值，不是上限
简单工具默认三个模块即可。需求确实需要更多模块时，再按职责增加；不要为了显得复杂而拆出没有独立职责的模块。
