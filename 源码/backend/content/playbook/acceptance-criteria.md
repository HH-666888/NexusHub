# 验收标准

## 一条标准只验证一件事
每条验收标准只描述一个可观察结果，例如“新增待办后列表出现该条目”，不要写成“待办功能完善”。一条标准里出现“并且”“同时”时，通常应该拆成两条。

## 必须能被 HTTP 请求或页面操作验证
验收标准要能落到具体动作：请求哪个方法、哪个路径、期望什么状态码、返回什么字段；页面点击哪个按钮、看到什么文本或状态。不能验证的描述不算验收标准。

## 写清楚状态码和字段
接口类验收至少包含方法、路径、请求体、期望状态码和关键返回字段。页面类验收至少包含操作步骤、可见文本或元素状态。只写“接口正常”无法测试。

## 覆盖空态和错误态
除了正常路径，至少考虑空列表、重复提交、缺少必填字段、资源不存在四种情况。错误态要写清楚期望状态码，不要只写“报错”。

## 验收标准要能反向约束实现
好的验收标准会让实现者知道什么不能做：不能返回假数据、不能只写 localStorage、不能在无数据时崩溃。标准越具体，后面测试和修复越省事。
