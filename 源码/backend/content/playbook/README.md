# content/playbook

RAG 语料。**这里的 markdown 就是"软件开发规划手册"本体** —— 检索到的片段会作为"依据"
注入规格化与架构定型的提示词，并在界面上显示来源（`路径 §章节`）。

## 放什么

写作对象是"做这个小工具时真正会遇到的判断"，不是通用的编程教程。例如：

- 一个需求该切成几个模块、模块边界怎么定（按功能还是按页面）
- 验收标准怎么写才可测（"能开始/暂停计时"而不是"计时功能完善"）
- 单文件 HTML 的常见坑（外链资源、localStorage 在 iframe 里的限制、CSP）
- 什么时候该拒绝需求（"要后端"的需求超出了交付形态）

## 文件格式

```markdown
# 标题

## 小节标题

正文……（一段一个判断，别写成散文）
```

约定：

| 项 | 规定 |
|---|---|
| 编码 | UTF-8 |
| 切片 | 按 `##` 切，512 字 / 重叠 64（见 `app/ai/rag/chunk.py`） |
| 命名 | `kebab-case.md`，例如 `module-splitting.md` |
| 大小 | 单篇 < 20KB；明显更长的拆成多篇 |
| 语言 | 中文；专有名词保留英文（CSP、localStorage） |

## 索引与更新

入库走 `app/ai/rag/store.py`：比对文件 `sha256`，只重建变过的文档。
`rag_chunks.model` 记录 embedding 模型名 —— **换模型必须整库重建**，否则向量不可比。
