## 一、树的组织规则

- 节点以 **【主干】 / 【扩展】** 标记：主干为第一批做深做透的分支，扩展为后续按样本复制的分支；
- **检查点（★）** 只设在工序结束处：工序② 末的组合合理性检查、工序⑤ 末的验证门；不通过不得进入下一道工序；
- **判定回流**：检查点不通过时，携带判定意见回流至产生问题的对应节点，修正后重过本检查点；
- **横切挂载**：工程约定知识不占主流程位置，横向挂载到每一个技术栈叶子节点，保证所有分支约定覆盖一致；
- **可达约束**：形态节点决定下层分支的可达性，节点组合只落在树内可达路径。
- **两种模式**：新建走完整流程；改造跳过工序② 的形态决策与工序③ 的脚手架（见 SKILL.md §0.5），树的分支结构与可达规则不变。

## 四、形态可达规则

树不是任意节点自由组合，**形态节点决定下层哪些分支可达**，这是组合合理性判定的核心规则来源：

| 形态 | 后端独立工程 | 前端独立工程 | 模板页路径 | 数据库 | 说明 |
|---|---|---|---|---|---|
| A 前后端分离 | 可达 | 可达 | 不可达 | 可达 | 前端通过 REST API 跨进程调用后端 |
| B 传统单体 | 可达 | 不可达 | 可达 | 可达 | 后端渲染页面，前端只有静态资源与少量 JS |
| C Next.js 全栈 | 不可达 | 可达（内含 API 路由） | 不可达 | 可达 | 后端能力收进 Next.js，不产生独立服务 |
| D 纯静态 | 仅轻量接口可达 | 不可达独立框架工程 | 不可达 | 通常不可达 | 以静态页面为主 |

形态 D 的「轻量接口」默认不建独立工程：优先做成同源静态页、不设后端；确需接口时，加载 `references/03-三方向开发/后端-Node-Go.md` 中的单文件服务形态，只允许一个入口文件与一个配置，不按分层工程展开。

## 五、节点层级说明

整棵树从根到交付共分为六个层级，逐级收敛：

1. **根节点层**：软件生成需求，流程唯一入口；
2. **形态决策层**：全局形态决策（工序② 步骤1），决定整体架构方向与下游可达路径；
3. **角色层**：前端、后端、数据库三大分支，对应软件的三个工程角色；
4. **语言 / 框架层**：各角色下的具体技术栈（Java / Python、Next.js / 原生 HTML、MySQL）及其框架生态；
5. **目录结构层**：框架生态内的标准分层与目录（如 Spring Boot 的 controller / service / mapper，FastAPI 的 routes / services / crud，Next.js 的 app / components / lib）；
6. **质量门与交付层**：组合合理性检查 + 验证门加判定回流构成闭环，末端交付可运行项目、接口定义与接口示例测试。

**整体闭合逻辑**：根节点分流 → 形态约束可达路径 → 沿角色 / 语言 / 框架 / 目录四层向下生长 → 横切约定在每个叶子落地 → 检查点拦截 + 判定回流 → 末端交付。

## 六、需求特征 → 形态判定表

形态决策时**必须先查本表**，命中即执行；多条命中按编号小的优先；全部不命中才按 SKILL.md §2.1 发起征询。

| 编号 | 需求特征 | 推荐形态 | 判定依据 |
|---|---|---|---|
| F1 | 纯展示型，无后端数据交互、无登录（宣传页/作品集/静态说明） | D 纯静态 | 无后端即可满足，不建工程 |
| F2 | 有数据交互但极简（少量静态数据、单文件接口即可） | D 纯静态（+轻量接口） | 见 §四 轻量接口规则 |
| F3 | 中小型管理系统/内部工具，后端渲染页面即可满足，无独立前端需求 | B 传统单体 | 模板页路径可达，交付最简 |
| F4 | 需要独立前端体验（SPA、复杂交互）、独立后端服务，或明确要求前后端分离 | A 前后端分离 | 前端独立工程可达 |
| F5 | 单团队全栈、快速交付，后端能力可收进前端框架（Next.js API Routes 能承载） | C Next.js 全栈 | 后端收口进前端，不产生独立服务 |
| F6 | 多端需求（Web + 移动端共用 API） | A 前后端分离 | API 独立供多端复用 |

**判定流程**：

1. 按 F1→F6 顺序查表，命中即确定形态；
2. 形态与需求存在矛盾（如"多端共用 API"却选了 B）→ 按更高优先级特征重选；
3. 形态确定后，用 §四 可达规则检查所选技术栈是否全部落在可达路径内；
4. 完成形态决策后进入选型对照（`references/02-架构设计/选型对照.md`）。
