## 一、工程名 / 目录名 / 文件名

| 对象 | 规则 | 正确示例 | 错误示例 |
|---|---|---|---|
| 工程名（仓库根目录名） | kebab-case，全小写，连字符分隔 | `order-management-system` | `OrderManagementSystem` / `order_management` |
| 顶层业务目录名 | kebab-case，全小写 | `user-center` / `payment-service` | `UserCenter` / `userCenter` |
| 源码文件名 | 按所选语言栈执行，本表不单独规定：Java 类/接口 UpperCamelCase、Python 模块 snake_case、JS/TS 组件 PascalCase、工具文件 kebab-case（详见本文件第二~四节） | 见各语言节 | 以 kebab-case 命名 Java 类或 Python 模块 |
| 配置文件名 | 固定小写加连字符或点分隔 | `application-dev.yml` / `.env.example` | `ApplicationDev.yml` |
| 静态资源目录名 | kebab-case | `assets/` / `public-uploads/` | `Assets/` / `publicUploads/` |

**通用要求：**

1. 工程名与目录名一律小写。
2. 单词之间用连字符 `-` 分隔，目录分隔不使用下划线。
3. 文件名只使用字母、数字、连字符、点与下划线；中文注释允许出现在文件内容中。
4. 同一层级目录与文件名风格统一，kebab-case 与 camelCase 不混用。

## 二、Java 命名规则

| 对象 | 规则 | 正确示例 | 错误示例 |
|---|---|---|---|
| 类名 / 接口名 / 枚举名 | UpperCamelCase | `UserController` / `OrderService` | `userController` / `Usercontroller` |
| 方法名 | lowerCamelCase，动词开头 | `getUserById` / `createOrder` | `GetUserById` / `get_user_by_id` |
| 变量名 | lowerCamelCase | `userName` / `orderList` | `user_name` / `UserName` |
| 常量名（`static final`） | UPPER_SNAKE_CASE | `MAX_PAGE_SIZE` / `DEFAULT_TIMEOUT` | `maxPageSize` / `max_page_size` |
| 包名 | 全小写，单词不分隔 | `com.example.order.controller` | `com.example.Order.Controller` |
| 布尔变量 / 方法 | `is` / `has` / `can` 前缀 | `isValid` / `hasPermission` | `validFlag` / `checkOk` |

**通用要求：**

1. 类名使用名词或名词短语；方法名使用动词或动词短语。
2. 命名使用英文单词；行业通用缩写（如 `DTO`、`VO`、`ID`、`URL`）保持全大写。
3. 测试类命名 = 被测类名 + `Test` 后缀。

## 三、Python 命名规则

| 对象 | 规则 | 正确示例 | 错误示例 |
|---|---|---|---|
| 模块文件名 | snake_case | `user_controller.py` / `auth_service.py` | `UserController.py` / `userController.py` |
| 类名 | UpperCamelCase | `UserController` / `OrderService` | `user_controller` / `Usercontroller` |
| 函数名 | snake_case，动词开头 | `get_user_by_id` / `create_order` | `getUserById` / `GetUserById` |
| 变量名 | snake_case | `user_name` / `order_list` | `userName` / `UserName` |
| 常量名 | UPPER_SNAKE_CASE | `MAX_PAGE_SIZE` / `DEFAULT_TIMEOUT` | `maxPageSize` / `max_page_size` |
| 私有属性 / 方法 | 单下划线前缀 | `_internal_cache` | `internalCache` |
| 受保护类属性 | 双下划线前缀（名称改写） | `__secret_key` | `secretKey` |

**通用要求：**

1. 函数与方法名使用动词或动词短语。
2. 命名使用英文单词；行业通用缩写保持全大写（如 `HTTP`、`API`、`URL`）。
3. 测试文件命名 = `test_` + 被测模块名。

## 四、JS / TS 命名规则

| 对象 | 规则 | 正确示例 | 错误示例 |
|---|---|---|---|
| React 组件文件 / 组件名 | PascalCase | `UserProfile.tsx` / `OrderCard.tsx` | `userProfile.tsx` / `order-card.tsx` |
| 普通工具文件 / 工具函数文件 | kebab-case | `auth-utils.ts` / `request-client.ts` | `authUtils.ts` / `AuthUtils.ts` |
| 函数名 | camelCase，动词开头 | `getUserById` / `createOrder` | `get_user_by_id` / `GetUserById` |
| 变量名 | camelCase | `userName` / `orderList` | `user_name` / `UserName` |
| 常量名 | UPPER_SNAKE_CASE | `MAX_PAGE_SIZE` / `API_BASE_URL` | `maxPageSize` / `max_page_size` |
| 类型名 / 接口名（TS） | PascalCase | `UserInfo` / `OrderParams` | `userInfo` / `user_info` |
| 枚举名 | PascalCase，成员 UPPER_SNAKE_CASE | `OrderStatus.PAID` | `orderStatus.paid` |
| 路由段 URL 路径 | kebab-case | `/user-profile` / `/order-detail` | `/userProfile` / `/user_profile` |
| 事件处理函数 | `handle` + 事件名 | `handleSubmit` / `handleClick` | `submitHandler` / `onSubmitClick` |

**通用要求：**

1. 组件文件与组件名保持同名，均为 PascalCase。
2. 普通 `.ts` / `.js` 工具文件使用 kebab-case 文件名，内部变量与函数使用 camelCase。
3. 布尔变量使用 `is` / `has` / `can` 前缀。

## 五、数据库命名规则

| 对象 | 规则 | 正确示例 | 错误示例 |
|---|---|---|---|
| 库名 | 全小写，snake_case | `order_center` | `OrderCenter` / `ordercenter` |
| 表名 | 全小写，snake_case，单数名词 | `sys_user` / `biz_order_item` | `users` / `OrderItem` / `order-items` |
| 字段名 | 全小写，snake_case | `user_name` / `created_at` | `userName` / `UserName` / `user-name` |
| 主键 | 固定为 `id` | `id` | `user_id`（作主键时） |
| 外键 | 关联实体名单数 + `_id` | `user_id` / `order_id` | `uid` / `userId` |
| 普通索引 | `idx_` + 表名简写 + 字段名 | `idx_sys_user_email` | `user_name_index` |
| 唯一索引 | `uk_` + 表名简写 + 字段名 | `uk_sys_user_active_username` | `email_unique` |
| 外键约束 | `fk_` + 本表名 + 关联表名 | `fk_biz_order_sys_user` | `order_user_fk` |
| 时间戳字段 | 固定 `created_at` / `updated_at` | `created_at` | `createTime` / `created_time` |
| 软删除标记 | 固定 `deleted_at`（NULL 未删除） | `deleted_at` | `is_deleted` / `delete_flag` |

**通用要求：**

1. 表名一律单数，不加复数 `s`；多词表名用下划线分隔。
2. 表名或字段名避开数据库保留字（`order`、`group`、`user` 等加业务前缀，如 `biz_order`、`sys_user`）。
3. 索引名在同一库内全局唯一。
4. 字段名不用缩写，除行业通用缩写（如 `url`、`uuid`、`ip`）。

## 六、JSON 报文字段命名规则

JSON 报文命名区分两类字段，权威定义与跨语言落地方式见 `references/横切约定/接口规范/接口规范.md` §2.1，本表是速查：

| 字段类别 | 规则 | 示例 |
|---|---|---|
| 协议字段（信封、分页、令牌、错误码） | snake_case | `code` / `message` / `data` / `page_size` / `sort_by` / `access_token` / `expires_in` |
| 业务对象字段（资源属性） | camelCase | `userId` / `userName` / `createdAt` / `orderStatus` |
| 数据库列（非 JSON 层） | snake_case | `user_id` / `created_at`（由 ORM 映射到 JSON 业务字段） |

**通用要求：**

1. 协议字段全栈统一 snake_case，各语言用注解 / 参数名对齐落地（Java 用注解、Python 用固定参数名）。
2. 业务字段在 JSON 层统一 camelCase；Java 实体天然 camelCase，Python Pydantic 模型内部 snake_case、输出用 `alias` 转 camelCase，前端对象属性直接 camelCase。
3. `sort_by` 取值与接口返回的 JSON 业务字段一致（camelCase），允许排序的白名单在接口定义中列出。

## 七、接口 URL 命名规则

| 规则项 | 约定 | 示例 |
|---|---|---|
| 全局前缀 | 一律以 `/api/v1/` 开头 | `/api/v1/users` |
| 资源名词 | 复数形式，全小写 | `/users` / `/orders` |
| 单词分隔 | 多词用连字符 `-`，不用下划线 | `/order-items` |
| 嵌套资源 | 子资源挂在父资源下 | `/api/v1/users/{id}/orders` |
| 路径参数 | 一律小写 snake_case，不随语言栈变化；主键固定 `{id}` | `/api/v1/users/{id}` / `/api/v1/orders/{order_id}` |
| 动词语义 | 用 HTTP 方法表达动作，URL 只放名词 | `/api/v1/getUserById`（动词入 URL） |
| 操作型接口 | 非 CRUD 动作放子路径 | `/api/v1/orders/{id}/cancel` |

**通用要求：**

1. URL 一律小写，路径段中不使用驼峰。
2. 路径层级不超过 3 层（`/api/v1/资源/{id}/子资源`）；过深则通过查询参数表达关联。
3. 版本号固定为 `v1`，后续大版本升级时改为 `v2`，旧版本路径保留兼容期。
