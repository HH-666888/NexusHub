# 异常处理

> 跨栈通用异常处理约定。所有后端工程必须实现全局异常拦截，统一转换为接口规范规定的统一返回体。

## 一、全局异常拦截机制

### 1.1 通用模型

全局异常拦截采用"拦截点 → 分类 → 转换"三段式模型：

1. **拦截点**：在所有请求入口的最外层设置统一拦截点（如框架级全局异常处理器、中间件、错误处理函数），确保任何未被业务代码捕获的异常都能被此处兜底。
2. **分类**：根据异常类型判断属于哪一级异常（业务异常 / 参数异常 / 系统异常 / 第三方异常），确定对应的 HTTP 状态码与业务错误码。
3. **转换**：将异常对象转换为统一返回体 JSON，写入 HTTP 响应返回给客户端；同时按日志规范记录服务端日志。

### 1.2 挂载点形态

不同技术栈的挂载点名称不同，但职责一致：

| 技术栈形态 | 挂载点名称示例 |
|---|---|
| Spring 体系 | `@RestControllerAdvice` 全局异常处理器 |
| FastAPI / Flask 体系 | 全局异常处理器 / 错误注册函数 |
| Node / Go 体系 | 中间件层错误处理函数 |

栈内具体实现以对应分支文件为准，本文件只规定职责与输出格式。

## 二、异常分级

| 异常级别 | 定义 | 典型示例 | 是否可预期 |
|---|---|---|---|
| 业务异常 | 业务规则校验不通过，属于可预期的业务错误 | 用户名已存在、订单状态不允许取消 | 可预期 |
| 参数异常 | 客户端入参不符合校验规则 | 必填缺失、类型错误、长度超限 | 可预期 |
| 系统异常 | 代码缺陷或运行时错误，属于不可预期 | 空指针、类型转换失败、数据库连接断开 | 不可预期 |
| 第三方异常 | 依赖的外部服务调用失败 | 第三方支付接口超时、短信服务不可用 | 部分可预期 |

**通用要求：**

1. 业务异常与参数异常必须在接口文档中列出可能的错误码与触发条件。
2. 系统异常必须记录完整堆栈日志；堆栈只落在服务端日志，不进入客户端响应。
3. 第三方异常需标注降级策略（超时重试、默认值兜底），具体策略由业务层决定。

## 三、标准异常返回格式

所有异常经全局拦截器转换后，一律输出接口规范规定的统一返回体：

```json
{
  "code": 10001,
  "message": "参数错误：userName 不能为空",
  "data": null
}
```

| 字段 | 说明 |
|---|---|
| `code` | 业务错误码，详见接口规范第三节 |
| `message` | 人类可读的错误描述，可直接展示给终端用户 |
| `data` | 固定为 `null` 或空对象 `{}`，失败时不携带业务数据 |

**通用要求：**

1. 异常返回的 HTTP 状态码必须与 `code` 语义对齐（见下节映射表）。
2. `message` 为中文描述，面向终端用户；内部异常类名、堆栈、SQL 语句不进入 `message`。
3. 业务异常的 `message` 应精确说明哪个字段、哪条规则不满足。

## 四、典型异常与状态码 / 错误码映射表

| 异常场景 | 异常级别 | HTTP 状态码 | code | message 示例 |
|---|---|---|---|---|
| 请求参数缺失 / 类型错误 / 长度超限 | 参数异常 | 400 | 10001 | `参数错误：page 必须大于等于 1` |
| 未登录或令牌失效 | 业务异常 | 401 | 10002 | `未认证：请先登录` |
| 已登录但无权限操作 | 业务异常 | 403 | 10003 | `无权限：无权访问该资源` |
| 目标记录不存在 | 业务异常 | 404 | 10004 | `资源不存在：用户 123 不存在` |
| 唯一约束冲突 / 状态冲突 | 业务异常 | 409 | 10005 | `冲突：用户名已被注册` |
| 业务规则不通过 | 业务异常 | 按语义（对应 4xx） | 模块错误码（11000 起） | `订单状态不允许取消` |
| 空指针 / 类型转换失败等代码缺陷 | 系统异常 | 500 | 50000 | `系统繁忙，请稍后重试` |
| 数据库连接失败 / SQL 执行失败 | 系统异常 | 500 | 50000 | `系统繁忙，请稍后重试` |
| 第三方服务超时 / 不可用 | 第三方异常 | 502 或 500 | 50001 | `支付服务暂不可用，请稍后重试` |

**通用要求：**

1. 系统异常对客户端统一返回模糊提示（`系统繁忙，请稍后重试`），详细堆栈只记服务端日志。
2. 业务模块错误码从 `11000` 起分段，具体编号由各模块自行定义，详见接口规范。
3. HTTP 状态码与 `code` 语义对齐：HTTP 200 对应 `code=0`，HTTP 500 对应系统级错误码（`50000` 起）。

## 五、堆栈泄漏防护

1. 全局异常拦截器生成响应体时，`message` 字段只取面向用户的描述，异常对象的 `stackTrace`、`cause`、`toString()` 等内部信息不进入响应体。
2. 开发环境可在服务端日志中打印完整堆栈；生产环境日志级别为 INFO 时，系统异常堆栈也必须落盘日志，但不输出到客户端。
3. 响应头不携带 `X-Exception`、`X-Debug` 等调试信息。
4. 前端 / 客户端只展示 `message` 字段内容，`code` 以外的内部字段不参与解析。
