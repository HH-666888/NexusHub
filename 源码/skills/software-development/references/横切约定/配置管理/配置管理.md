## 一、.env 与环境变量约定

1. 所有配置项通过环境变量注入，源码中不出现配置值。
2. 工程根目录放置 `.env` 文件存放默认配置；`.env` 不入库。
3. 工程根目录放置 `.env.example` 文件作为配置项样例模板，该文件入库，仅列变量名与注释说明，不填真实值。
4. 应用启动时统一从环境变量读取配置；栈内具体加载方式（如 dotenv、Spring `@Value`、Pydantic Settings）由对应分支文件规定。
5. 配置项缺失或格式非法时，应用在启动阶段直接报错退出。

---

## 二、变量命名规则

1. 所有环境变量一律使用 `UPPER_SNAKE_CASE`，全大写、下划线分隔。
2. 变量名按"模块_用途"前缀组织，全局通用项不加业务前缀。

| 类别 | 命名示例 |
|---|---|
| 服务端口 | `SERVER_PORT` |
| 数据库连接 | `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD` |
| JWT 配置 | `JWT_SECRET`、`JWT_EXPIRE_MINUTES`、`JWT_REFRESH_EXPIRE_DAYS` |
| 业务模块配置 | `ORDER_AUTO_CANCEL_MINUTES`、`USER_PASSWORD_MIN_LENGTH` |
| 第三方服务 | `REDIS_URL`、`OSS_ACCESS_KEY` |

**通用要求：**

1. 环境变量命名使用 `UPPER_SNAKE_CASE`（全大写、下划线分隔）。
2. 同一配置项在不同环境中变量名保持一致，仅值不同。
3. 布尔型变量使用字符串 `"true"` / `"false"`，由代码层解析为布尔值。

## 三、多环境配置（dev / prod）

1. 至少区分 `dev`（开发）与 `prod`（生产）两套环境配置。
2. 环境切换通过 `APP_ENV` 环境变量控制，取值为 `dev` 或 `prod`。
3. 各环境配置文件命名：
   - `.env.dev`：开发环境配置，入库作为团队共享默认值（不含密钥）。
   - `.env.prod`：生产环境配置，**不入库**，仅在部署环境手动维护。
   - `.env`：本地开发默认配置，优先级最高，不入库。
4. 配置加载优先级：环境变量 > `.env` > `.env.{APP_ENV}` > 代码内置默认值。
5. 前端框架使用自身环境文件约定时（Next.js 的 `.env.development` / `.env.production` / `.env.local`，Vite 的 `.env.[mode]`），文件命名以框架约定为准；变量命名规则、密钥不入库、`.env.example` 三项不变。

| 环境 | `APP_ENV` 值 | 用途 | 是否入库 |
|---|---|---|---|
| 本地开发 | `dev` | 开发者本机运行 | `.env.dev` 入库，`.env` 不入库 |
| 生产部署 | `prod` | 线上环境 | `.env.prod` 不入库 |

## 四、密钥与敏感信息处理

1. 数据库密码、JWT 密钥、第三方 Access Key / Secret 等敏感信息一律不入库。
2. `.env`、`.env.prod` 加入 `.gitignore`，不提交到版本库。
3. `.env.example` 只列变量名与注释，值留空或填占位符 `<your-secret-here>`。
4. 生产环境密钥由部署平台或运维系统注入。
5. 日志输出时，敏感字段脱敏（详见日志规范文件），不打印完整密钥。

## 五、配置项清单模板

每个工程必须维护一份配置项清单，写入 `.env.example`，格式如下：

```env
# ===== 服务基础 =====
APP_ENV=dev
SERVER_PORT=8000   # 示例默认值；按所选后端栈调整：Java 8080 / FastAPI 8000 / Flask 5000 / Go 8080

# ===== 数据库 =====
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=<your-db-name>
DB_USER=<your-db-user>
DB_PASSWORD=<your-db-password>

# ===== JWT 认证 =====
JWT_SECRET=<your-jwt-secret>
JWT_EXPIRE_MINUTES=120
JWT_REFRESH_EXPIRE_DAYS=7

# ===== 业务参数 =====
USER_PASSWORD_MIN_LENGTH=8
ORDER_AUTO_CANCEL_MINUTES=30
```

**通用要求：**

1. 每个配置项必须有中文注释说明用途。
2. 必填项缺失时启动报错；可选项在注释中标注默认值。
3. 敏感项的值使用占位符（如 `<your-secret-here>`），不填真实值。

---

## 六、不入库的忽略规则

`.gitignore` 必须至少包含以下条目：

```
.env
.env.prod
.env.local
```

**通用要求：**

1. `.env.dev` 可以入库（不含敏感值，仅为团队共享开发默认值）。
2. `.env.example` 必须入库，作为新人配置参考。
3. 包含真实密码、密钥的文件不入库；发现误提交后立即轮换密钥。
