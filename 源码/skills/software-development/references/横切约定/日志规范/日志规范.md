# 日志规范

> 跨栈通用日志约定。所有后端工程必须遵循统一的日志级别、字段结构与脱敏要求。

## 一、日志级别定义与使用场景

| 级别 | 使用场景 | 示例 |
|---|---|---|
| ERROR | 系统异常、第三方服务失败、需要人工介入的错误 | 数据库连接失败、支付回调验签失败、空指针导致接口 500 |
| WARN | 可预期的异常情况、需关注但不影响主流程 | 参数校验失败被拦截、令牌即将过期、第三方服务降级触发 |
| INFO | 关键业务节点的正常流转记录 | 用户登录成功、订单创建成功、接口请求入参摘要 |
| DEBUG | 开发调试用的详细信息，生产环境不输出 | SQL 语句、循环内部变量、详细请求头 |

**通用要求：**

1. 生产环境默认日志级别为 `INFO`，`DEBUG` 不输出。
2. 任何需要人工排查的问题必须打到 `ERROR` 及以上级别。
3. 业务正常流转的关键节点打 `INFO`；不要把每个函数入口都打 INFO。
4. 日志级别最低到 `DEBUG`，不使用 `TRACE` 等更低级别。

## 二、统一日志字段

每条日志输出必须包含以下五个字段，按 `时间 | 级别 | traceId | 类或模块 | 消息` 的顺序排列：

| 字段 | 说明 | 示例 |
|---|---|---|
| 时间 | 日志产生时间，精确到毫秒，ISO 8601 格式 | `2026-11-02T14:30:00.123+08:00` |
| 级别 | 日志级别，大写 | `INFO` |
| traceId | 请求链路唯一 ID，贯穿一次请求的所有日志 | `a1b2c3d4e5f6` |
| 类或模块 | 输出日志的类名或业务模块名 | `UserService` / `order-cancel` |
| 消息 | 日志正文，人类可读 | `用户 123 登录成功` |

**输出格式示例：**

```
2026-11-02T14:30:00.123+08:00 | INFO | a1b2c3d4e5f6 | UserService | 用户 123 登录成功
```

**通用要求：**

1. `traceId` 必须在请求入口生成并贯穿全链路，未认证请求也需生成 traceId。
2. 日志字段之间用竖线 `|` 分隔。
3. 消息内容为可读中文，携带上下文（如 `用户 123 登录成功`），不打印裸变量值。

## 三、输出位置与滚动策略

### 3.1 输出位置

1. 开发环境：日志输出到控制台即可。
2. 生产环境：日志输出到文件，同时控制台保留一份标准输出便于容器采集。
3. 日志文件统一存放在工程根目录下的 `logs/` 目录中。

### 3.2 滚动策略

| 策略项 | 约定 |
|---|---|
| 按天滚动 | 每天生成一个新日志文件 |
| 单文件大小上限 | 单文件超过 100MB 时触发滚动 |
| 保留天数 | 历史日志保留至少 7 天 |
| 日志文件命名 | `app-YYYY-MM-DD.log` |

**通用要求：**

1. `logs/` 目录加入 `.gitignore`，不入库。
2. 日志级别为 ERROR 的日志可单独输出到 `error.log` 便于快速检索。
3. 栈内具体日志框架与配置方式以对应分支文件为准。

## 四、敏感信息脱敏

1. 以下字段在日志中必须脱敏，打印掩码值：
   - 用户密码
   - JWT 令牌 / Access Token / Refresh Token
   - 数据库密码、API Secret、第三方 Access Key
   - 身份证号、银行卡号、手机号（中间四位打星）
2. 脱敏规则：
   - 密码 / 密钥：打印为 `******`，长度不保留。
   - 手机号：`138****1234`。
   - 身份证号：`110***********1234`。
3. 请求体日志只打印业务字段摘要，不打印包含敏感字段的完整请求体。

## 五、关键业务埋点位置

以下节点必须打印 `INFO` 级别日志：

| 埋点位置 | 日志内容要点 |
|---|---|
| 请求入口 | 请求方法、路径、traceId |
| 登录成功 / 失败 | 用户 ID、登录结果 |
| 订单创建 / 取消 / 支付 | 订单 ID、操作类型、结果 |
| 权限校验失败 | 用户 ID、目标资源、失败原因 |
| 定时任务执行开始 / 结束 | 任务名、执行时长、结果 |

**通用要求：**

1. 每个关键业务操作都要有可追溯的日志，通过 traceId 可串起完整链路。
2. 异常日志必须包含 traceId，便于与正常请求日志关联排查。
