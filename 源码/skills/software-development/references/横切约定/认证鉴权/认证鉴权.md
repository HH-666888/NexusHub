## 一、JWT 机制通用规则

### 1.1 令牌结构

JWT 令牌由三段组成，以点号 `.` 分隔：`Header.Payload.Signature`。

### 1.2 Payload 标准字段

| 字段 | 含义 | 说明 |
|---|---|---|
| `sub` | 用户 ID | 令牌所属用户的唯一标识 |
| `iat` | 签发时间 | Unix 时间戳 |
| `exp` | 过期时间 | Unix 时间戳，由 `JWT_EXPIRE_MINUTES` 配置决定 |
| `jti` | 令牌唯一 ID | 用于令牌吊销与刷新追踪 |

### 1.3 过期与刷新规则

1. 访问令牌（Access Token）有效期默认 120 分钟，由环境变量 `JWT_EXPIRE_MINUTES` 配置。
2. 刷新令牌（Refresh Token）有效期默认 7 天，由环境变量 `JWT_REFRESH_EXPIRE_DAYS` 配置。
3. 访问令牌过期后，客户端使用刷新令牌调用刷新接口获取新的访问令牌。
4. 刷新令牌一次性使用：刷新成功后旧刷新令牌立即失效，签发新的刷新令牌。
5. 登出时，当前访问令牌与刷新令牌同时吊销。
6. 「一次性」与「立即吊销」都需要服务端状态，存储方案见 §6.4；若明确选择无状态方案，在决策记录中写明「放弃即时吊销」及其代价。

**通用要求：**

1. 密钥 `JWT_SECRET` 从环境变量读取，长度不少于 32 位随机字符串。
2. Payload 仅存放用户 ID 与必要的权限标识，密码与敏感业务数据不放入 Payload。
3. 栈内具体 JWT 库与签发 / 解析方式由对应分支文件规定，本文件不写死库名。

## 二、Authorization 请求头约定

1. 所有受保护接口的请求必须携带请求头：

```
Authorization: Bearer <token>
```

2. `<token>` 为访问令牌字符串，`Bearer` 与令牌之间有一个空格。
3. 未携带该请求头、或令牌格式非法、或令牌已过期，一律返回 `401 Unauthorized`，`code=10002`。

## 三、白名单与受保护资源

### 3.1 白名单接口

以下接口无需认证即可访问，必须在配置中显式登记为白名单：

| 接口 | 方法 | 路径 |
|---|---|---|
| 登录 | POST | `/api/v1/auth/login` |
| 刷新令牌 | POST | `/api/v1/auth/refresh` |
| 健康检查 | GET | `/api/v1/health` |

### 3.2 受保护资源

白名单之外的所有接口均为受保护资源，必须携带有效访问令牌才能访问。

**通用要求：**

1. 白名单显式列举路径；默认拦截、按名单放行。
2. 新增公开接口时，必须同步更新白名单配置。
3. 白名单路径匹配规则：精确匹配或前缀匹配，由各栈实现自行决定，但必须在配置中一目了然。

## 四、挂载点模型

认证鉴权逻辑必须在请求进入业务逻辑之前执行，挂载点有以下四种通用形态，按技术栈选择其一：

| 挂载点形态 | 说明 | 典型技术栈 |
|---|---|---|
| 拦截器（Interceptor） | 在控制器执行前拦截请求，校验令牌 | Spring 体系 |
| 过滤器（Filter） | 在请求链路最外层执行鉴权 | Java 原生 / 通用 Web 容器 |
| 中间件（Middleware） | 在路由处理函数前执行鉴权 | Node / Go 体系 |
| 依赖注入（Dependency Injection） | 通过依赖注入在接口参数层面校验 | FastAPI 体系 |

**通用要求：**

1. 无论哪种挂载点，职责完全一致：解析令牌 → 校验有效性 → 注入当前用户上下文 → 放行或拒绝。
2. 令牌解析只在挂载点发生一次；业务代码中的当前用户 ID 从上下文 / 依赖注入获取。
3. 白名单路径在挂载点处直接放行，不进入令牌校验逻辑。

## 五、权限判定与越权防范

### 5.1 权限判定

1. 认证（你是谁）与授权（你能做什么）是两个独立环节：
   - 认证：校验令牌有效性，确认用户身份。
   - 授权：校验该用户是否有权操作目标资源。
2. 权限判定在业务层完成，前端隐藏按钮只作展示控制。
3. 资源归属校验：当操作某个具体资源（如 `GET /api/v1/users/{id}/orders`）时，必须校验当前登录用户是否有权访问该 `id` 对应的数据。

### 5.2 越权防范

| 越权类型 | 防范措施 |
|---|---|
| 水平越权（访问他人数据） | 每个资源请求都校验资源归属与当前用户的关系 |
| 垂直越权（普通用户操作管理员接口） | 接口层面校验角色 / 权限标识 |
| 令牌篡改 | JWT 签名校验，篡改后令牌直接失效 |
| 令牌重放 | 短有效期 + 刷新机制，降低被盗用窗口 |

**通用要求：**

1. 后端独立完成认证与授权校验，前端权限控制只是辅助展示。
2. 权限不足时返回 `403 Forbidden`，`code=10003`。

## 六、登录 / 登出 / 刷新接口约定

### 6.1 登录接口

- 路径：`POST /api/v1/auth/login`
- 白名单：是
- 请求体：

```json
{
  "username": "string",
  "password": "string"
}
```

- 成功返回（200）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "access_token": "eyJhbGciOi...",
    "refresh_token": "eyJhbGciOi...",
    "token_type": "Bearer",
    "expires_in": 7200
  }
}
```

- 失败返回（401）：

```json
{
  "code": 10002,
  "message": "用户名或密码错误",
  "data": null
}
```

> 令牌字段（`access_token` / `refresh_token` / `token_type` / `expires_in`）属协议字段，统一 snake_case，命名规则见接口规范 §2.1。

**登录实现要求：**

1. 密码以哈希形式存储：bcrypt（cost ≥ 10）或 argon2id；校验用库自带 verify。明文、MD5 / SHA1、可逆加密不用于密码存储。
2. 登录失败限制：同一账号默认 5 次失败锁定 5 分钟，阈值落成配置项（如 `LOGIN_MAX_FAILURES` / `LOGIN_LOCK_MINUTES`）并实现。
3. 登录响应只包含必要的用户信息，密码哈希、盐等敏感字段不进入响应；失败统一返回 `用户名或密码错误`，不区分账号是否存在。

### 6.2 刷新令牌接口

- 路径：`POST /api/v1/auth/refresh`
- 白名单：是
- 请求体：

```json
{
  "refresh_token": "eyJhbGciOi..."
}
```

- 成功返回：结构与登录成功一致。
- 失败返回：刷新令牌过期或无效时，`code=10002`，要求用户重新登录。

### 6.3 登出接口

- 路径：`POST /api/v1/auth/logout`
- 白名单：否（需携带有效访问令牌）
- 请求体：无
- 成功返回（200）：

```json
{
  "code": 0,
  "message": "success",
  "data": null
}
```

**通用要求：**

1. 登录接口必须做密码错误次数限制，防止暴力破解（阈值见 §6.1，必须落成配置项并实现）。
2. 登出后当前令牌立即失效。
3. 所有接口的请求头与返回体结构严格遵循接口规范。

### 6.4 令牌状态存储（刷新与吊销）

要求「刷新令牌一次性 + 登出立即失效」时，必须落一张令牌状态表（表名按命名规范，示例 `auth_refresh_token`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT UNSIGNED | 主键 |
| `user_id` | BIGINT UNSIGNED | 所属用户，建索引 |
| `token_hash` | CHAR(64) | 刷新令牌的 SHA-256 哈希值 |
| `expires_at` | DATETIME(3) | 过期时间 |
| `revoked_at` | DATETIME(3) NULL | 吊销时间，NULL 表示有效 |
| `created_at` | DATETIME(3) | 创建时间 |

该表属技术表，用 `revoked_at` 表达失效，不套业务表的 `deleted_at` 软删除；`created_at` 保留，`updated_at` 可省略。

- **刷新**：按 `token_hash` 查有效记录 → 置 `revoked_at` → 签发新令牌并插入新记录，同一事务完成。
- **登出**：吊销该用户当前刷新令牌；访问令牌按 `jti` 写入吊销表（单机可用内存，多实例必须共享存储），保留到令牌 `exp` 之后。
- **校验**：访问令牌每次校验都必须检查吊销状态；只验签名与 `exp` 等于没有登出。
- **清理**：过期记录由定时任务或登录时顺带删除，避免表无限增长。
