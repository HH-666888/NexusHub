## 一、定位与输入

- **输入**：工序③ 的三方向产物（数据库表、后端接口、前端页面）+ 接口清单 + 表结构清单。
- **输出**：装配结论（链路接通 / 断裂点清单）。
- **执行时机**：三方向代码生成完成、进入验证门之前。

**规则**：装配检查是"跨方向一致性"校验，不是重新生成；发现断裂只记录并回流，不在本工序直接改代码。

## 二、引用闭合检查

逐项核对跨方向引用是否**显式、真实、可解析**：

| 检查项 | 核对内容 | 合格线 |
|---|---|---|
| 前端 → 后端 | 前端每个 API 调用是否有对应的后端接口实现（方法/路径一致，接口清单为唯一依据） | 接口清单中每个被前端调用的接口，后端都有实现，路径与方法 1:1 |
| 后端 → 数据库 | 后端每个 ORM 实体/仓储操作是否有对应表与字段（表结构清单为唯一依据） | 实体字段与表结构逐字段一致 |
| 前端 → 数据 | 页面/组件引用的字段是否与接口出参（data 结构）一致 | 页面取数路径与接口定义出参一致，无"取不到字段" |
| 跨进程依赖 | 后端地址、端口、协议配置与前端调用一致（如 API_BASE_URL 指向后端实际地址） | 配置与实现一致，无写死错误地址 |

**检查方法**：

1. 从前端代码中提取所有 API 调用（方法 + 路径）；
2. 从接口清单反查后端实现（逐接口核对）；
3. 从后端实体反查表结构；
4. 输出**引用闭合表**：每条引用标注 已闭合 / 断裂（断裂点：文件、位置、预期）。

**合格线**：全部引用闭合，无悬空调用、无未实现接口、无字段缺失。

## 三、全栈联调检查

在真实运行环境验证链路，方法与合格线如下（执行与判定见工序⑤ 验证门·全栈联调层）：

| 链路 | 验证动作 | 合格线 |
|---|---|---|
| 前端 → 后端 → 数据库 | 启动全部服务后，从前端发起一条真实业务请求，经后端到数据库 | 至少一条端到端链路连通，返回体符合《横切约定·接口规范》，数据真实写入/读出（非 mock） |
| 认证链路 | 含登录需求时：白名单接口与受保护接口行为正确 | 登录返回 token；带 token 访问受保护接口成功，无 token 返回 401 |

**规则**：

- 联调必须走真实服务、真实请求；用 mock、假数据、跳过接口的"通过"一律视为未验证（红线 R-02）。
- 联调顺序：先数据库（表可查）→ 后端（接口可连）→ 前端（页面可操作）→ 端到端。

## 四、失败回流

装配检查或联调失败时，按 SKILL.md §2.4 携带可复现信息回流：

| 失败现象 | 回流节点 | 必须携带的信息 |
|---|---|---|
| 前端调用无后端实现、路径不一致 | 工序③ 后端 | 缺失接口的方法/路径、调用位置 |
| 实体字段与表结构不一致 | 工序③ 数据库 | 不一致的字段、两处定义位置 |
| 前端取数与出参不一致 | 工序③ 前端（或接口设计） | 字段名、期望结构、实际结构 |
| 配置地址/端口不一致 | 工序③ 对应方向 | 配置位置、期望值、实际值 |

回流后重新生成受影响部分，再重过本工序检查。连续 3 次不通过按 SKILL.md §2.5 止损。
