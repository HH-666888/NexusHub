## 一、定位与输入

- **输入**：需求规格（`docs/requirements.md`）中的需求清单 R1..Rn、角色清单、优先级。
- **输出**：页面结构清单（页面/路由 → 承载需求 → 组件 → 交互状态）。
- **执行时机**：工序③ 内、原型开发之前（页面清单是原型逐页落地的设计输入，见 `原型开发.md` §三）。必须先在页面清单中体现全部需求，才允许制作原型页面。

**规则**：页面清单是需求到前端的映射，**不允许**出现"需求存在但没有任何页面承载"或"页面存在但不服务任何需求"。

## 二、页面清单推导

**方法：需求驱动逐条映射**

1. **逐条映射**：对每条需求 R，判断它需要一个"新页面"还是"已有页面的一个功能"：

| 判断 | 处理 |
|---|---|
| 需求需要一个独立的访问入口（新 URL） | 新建页面 |
| 需求是已有页面的操作/字段/列表 | 挂到已有页面 |

2. **页面分组**：按用途分类，保证页面职责清晰：

| 页面类型 | 定义 | 示例 |
|---|---|---|
| 信息页 | 只读展示（详情、列表、统计） | 图书列表页、图书详情页 |
| 操作页 | 数据变更（新建、编辑、流程操作） | 新建图书页、借书页 |
| 管理页 | 面向管理员的配置与审核 | 用户管理页、权限配置页 |

3. **角色对齐**：每个页面标注可见角色（对接工序① 角色清单）；角色不可见的页面不生成、不暴露路由。

**页面结构清单模板**：

| 页面 | 路由（URL） | 页面类型 | 承载需求 | 可见角色 | 主要组件 |
|---|---|---|---|---|---|
| 图书列表页 | /books | 信息页 | R1, R2 | 普通用户、管理员 | 搜索栏、表格、分页 |
| … | … | … | … | … | … |

## 三、组件拆分

**复用判定**：同一结构在 **≥2 个页面**出现 → 拆为独立组件；只出现 1 次的先内联，不提前抽象。

**三层结构**：

```
页面（路由级）
└── 区块（页面的功能区域，如搜索区、列表区、弹窗）
    └── 组件（可复用最小单元，如表格、分页器、表单字段）
```

**规则**：

- 组件命名与《横切约定·命名规范》一致（语义明确、类型后缀如 `Table`/`Form`/`Modal`）。
- 组件只做展示与交互，不做业务请求；数据获取放在区块或页面层（对齐前端分支的请求封装约定）。
- 表单类组件默认包含：字段校验、提交状态（加载中/成功/失败）、重置。

## 四、交互状态定义

每类交互给出**默认约定**，页面设计时直接采用，不逐页即兴定义：

| 交互 | 默认状态 | 行为约定 |
|---|---|---|
| 表格 | 加载中 / 空态 / 有数据 / 错误 | 加载中显示占位；空态显示明确提示文案与操作入口；错误态显示重试 |
| 表单 | 初始 / 校验失败 / 提交中 / 提交成功 | 校验失败在字段旁提示；提交中禁用按钮；成功后跳转或清空并提示 |
| 弹窗 | 打开 / 确认中 / 关闭 | 确认中防重复提交；关闭不丢失已填数据（可提示） |
| 分页 | 页码 / 无数据 | 页码从 1 起，`page_size` 默认 10（对齐《横切约定·接口规范》§五） |

**状态与后端返回体一致**：成功态取 `data`，业务失败态取 `code != 0`，网络错误单独处理；成败判定看返回体的 `code`，不看 `data` 是否为空。

## 五、产出与校验

**产出**：页面结构清单（§二模板）+ 组件清单 + 交互状态说明，写入 UI 规范子产物，随前端分支生成页面。

**校验清单**（全部满足才通过）：

- [ ] 每条需求都被至少一个页面/功能承载（逐条核对 R1..Rn）
- [ ] 每个页面都有可见角色，无"人人可见"的无权限页面
- [ ] 复用结构 ≥2 处的已拆组件，无重复实现
- [ ] 交互状态覆盖 加载/空态/错误/提交中，且与统一返回体对齐
- [ ] 路由命名符合《横切约定·命名规范》（URL 命名规则）

不通过 → 回流修正页面清单，重过本工序。
