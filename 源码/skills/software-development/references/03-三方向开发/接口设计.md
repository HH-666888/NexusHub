## 一、定位与输入

- **输入**：**锁定原型**（`原型开发.md` §六，直接依据）+ 需求规格（实体清单、需求清单 R1..Rn、角色清单）。
- **输出**：接口清单（方法/路径/入参/出参/鉴权/承载需求/承载页面）。
- **执行时机**：原型判定通过（`原型开发.md` §五）后、后端代码生成之前；数据库表结构（数据建模）完成后进行。

**规则**：每个对外接口必须能回指到至少一条需求；每条需求涉及的数据变更必须由接口承载。接口与实现 **1:1**，接口定义即交付文档。

## 二、接口推导方法

**方法：原型驱动 + 实体 CRUD + 业务动作**

0. **原型驱动检查（先行）**：遍历锁定原型的每个页面，把页面上的操作逐项对应到接口——按钮/表单提交/列表加载/详情查询 → 对应 POST/GET/PUT/DELETE。页面上有操作但接口清单无对应项 → 补接口；接口清单有但任何页面都不使用 → 删接口或回流修正。接口与页面 **1:1**。

1. **标准 CRUD**：对每个需要暴露的业务实体，按需生成：

| 动作 | 方法 | 路径模式（REST，对齐《横切约定·接口规范》） | 说明 |
|---|---|---|---|
| 新增 | POST | `/api/v1/{资源}` | 创建资源 |
| 查询列表 | GET | `/api/v1/{资源}` | 分页列表（`page`/`page_size`） |
| 查询详情 | GET | `/api/v1/{资源}/{id}` | 单条详情 |
| 更新 | PUT / PATCH | `/api/v1/{资源}/{id}` | 全量/部分更新 |
| 删除 | DELETE | `/api/v1/{资源}/{id}` | 软删除（对齐审计字段约定） |

   实体不需要某动作时（如只读字典表无删除），**按需求裁剪**，不机械生成全部 CRUD。

2. **业务动作**：需求中存在非 CRUD 的业务操作（借书、审核、下单）时，单独建模：

| 业务动作 | 方法 | 路径建议 | 说明 |
|---|---|---|---|
| 借书 | POST | `/api/v1/books/{id}/borrow` | 动作语义用子路径表达，不套 CRUD 强行拼凑 |

3. **接口清单模板**：

| 编号 | 方法 | 路径 | 入参 | 出参（统一返回体 data 内） | 鉴权 | 承载需求 | 承载页面 |
|---|---|---|---|---|---|---|---|
| I1 | GET | /api/v1/books/{id} | path: id | 图书完整信息 | 登录 | R1 | 图书详情页 |
| … | … | … | … | … | … | … |

## 三、接口定义模板

每个接口的完整定义按以下模板落盘（作为接口定义交付物，对齐《横切约定·接口规范》）：

```markdown
### {方法} {路径} —— {一句话用途}
- 承载需求：{R 编号}
- 鉴权：{无需 / 需登录 / 需角色}
- 请求头：{Content-Type; Authorization（如需要）}
- 入参：
  - path / query / body：{字段：类型，必填，说明}
- 出参（统一返回体）：
  - 成功：code=0, data={结构示例}
  - 业务失败：code={错误码}, message={说明}（错误码见《横切约定·接口规范》）
  - 鉴权失败：401 / 403
- 分页：{适用时：page 从 1 起，page_size 默认 10、上限 100}
```

**强制约定**（对齐 SKILL.md §0.4 与横切约定）：

- 统一返回体 `{"code":0,"message":"success","data":{}}`；分页 data 固定 `{list,total,page,page_size}`。
- 路径、参数命名符合《横切约定·命名规范》（URL 命名、字段命名）。
- 入参必须经校验层校验（对齐后端分支的请求校验约定），不做无校验接口。

## 四、鉴权标注

- 需求含登录/鉴权（工序① 约束清单标记"有认证需求"）时，按角色标注接口权限：

| 标注 | 含义 |
|---|---|
| 无需登录 | 公开接口（如登录、注册、公开查询） |
| 需登录 | 任意登录用户可访问 |
| 需角色 | 仅特定角色可访问（如管理员），标注角色名 |

- 白名单与令牌校验规则按《横切约定·认证鉴权》落地；接口清单中的鉴权列是后端生成拦截/中间件挂载的依据。

## 五、产出与校验

**产出**：接口清单 + 每接口定义（§三模板），作为接口定义交付物，并与接口示例测试 1:1 配套（期望值先于实现确定，见 SKILL.md §4.3）。

**校验清单**（全部满足才通过）：

- [ ] 每个接口回指需求（逐条核对，无"无主接口"）
- [ ] 每条需求涉及的数据操作有接口承载
- [ ] 接口与原型页面 1:1（原型上每个操作都有接口，每个接口都有页面使用）
- [ ] 方法/路径/返回体/分页符合《横切约定·接口规范》
- [ ] 鉴权标注与需求约束清单一致（有认证需求的已全部标注）
- [ ] 接口与实现 1:1（代码生成后逐接口核对）

不通过 → 回流修正接口清单，重过本工序。
