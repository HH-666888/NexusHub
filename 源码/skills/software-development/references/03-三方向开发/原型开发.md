## 一、为什么原型先行

页面不确定是开发中反复重构的最大来源：页面中途变化，接口和表跟着改，越改牵连越大。

**原理**：把"页面该是什么样"的变更，全部逼到成本最低的原型阶段解决。原型通过判定后成为**权威依据**，后端与数据库严格照它推导，不允许半路临时添加。

**硬规则**：工序③ 内，原型未通过判定门（§五），**不得**开始后端与数据库的实现。

## 二、原型是什么（成品级标准）

原型不是线框图、不是示意图、不是一次性废品。它是**用真实前端技术栈做的完整可交互页面**，后续直接接真实数据就能用。成品级标准如下：

| 维度 | 标准 |
|---|---|
| 页面完整 | 需求中每个页面/入口都有对应原型，无遗漏 |
| 视觉完整 | 有统一设计系统（颜色/字号/间距/组件样式一致）；公共样式抽离复用，不逐页复制 |
| 交互真实 | 跳转、点击、动画、状态切换真实可用；加载/空态/错误/提交状态覆盖 |
| 数据呈现 | 占位数据真实合理（字段/列表/详情齐全），且明确标注占位性质（§四） |
| 工程可靠 | 无外部依赖或依赖明确；本地可直接打开（file:// 可运行或提供启动方式）；有索引入口把全部页面组织起来 |
| 可演化 | 结构清晰、公共资源抽离，接真实接口时只替换数据来源，不重写 |

## 三、原型开发步骤

从 0 开始，一步一步设计、拼接，最后形成**成品级完整原型**：

1. **页面结构清单**：按 `页面结构设计.md` 从需求规格推导页面清单（路由/类型/承载需求/可见角色/组件），作为原型的设计输入。
2. **逐页落地**：按清单逐页制作成品级页面（视觉 + 交互 + 占位数据），一次一个页面，页面内交互状态齐全。
3. **拼接**：全部页面完成后，把页面间的跳转、入口、导航打通（如登录 → 工作台、列表 → 详情）。
4. **索引入口**：建立原型索引页，把所有页面组织起来（可直接双击打开浏览全部原型），便于判定与展示。

**规则**：

- 页面按清单生成；设计变更回流 `页面结构设计.md` 补齐后再做。
- 占位数据只用于呈现与交互演示，不承诺接口返回结构之外的行为。

## 四、占位数据规则

| 规则 | 说明 |
|---|---|
| 真实合理 | 占位数据的字段、取值、数量应符合业务语义（如用户列表有姓名/邮箱/角色），不填无意义乱码 |
| 明确标注 | 占位数据来源处标注"占位数据"，或集中存放于单一数据区（如页面顶部 `const MOCK = {...}`），与真实业务代码分离 |
| 覆盖状态 | 占位数据要能演示 加载/空态/错误/有数据 等关键状态，供判定核验 |
| 边界 | 占位数据只用于**设计验证**（页面结构、跳转、交互状态），不构成工序⑤ 的功能验证证据；功能验证必须真实接口真实数据（对齐验证门.md 与 SKILL.md §4.2） |

## 五、原型判定门

原型完成后，对照需求规格 R1..Rn 逐条判定。**判定依据是原先的需求内容，不另造标准**。全部满足才通过：

| # | 判定项 | 核验方式 |
|---|---|---|
| 1 | 页面覆盖 | 每条需求 R 都有页面/操作承载；无"需求存在但无页面" |
| 2 | 角色对齐 | 每个页面可见角色与需求规格一致；角色不可见的路由不出现 |
| 3 | 交互完整 | 跳转/点击/状态切换真实可用；加载/空态/错误/提交状态齐全 |
| 4 | 视觉一致 | 统一设计系统，公共样式已抽离，无逐页复制 |
| 5 | 数据合理 | 占位数据真实合理且明确标注 |
| 6 | 可演化 | 结构清晰，接真实接口不需重写 |

**判定规则**：

- 不通过 → 携带具体判定意见回流步骤 2/3 修正，重过本门；连续 3 次不通过按 SKILL.md §2.5 止损。
- 通过 → 原型**锁定**为权威依据，进入 §六。

## 六、锁定与变更控制

**锁定**：判定通过的原型即权威依据。后端/数据库/接口/数据建模全部以它为直接输入推导：

| 从原型取什么 | 推导到哪 |
|---|---|
| 页面上的数据对象与字段 | 数据建模（表/字段） |
| 页面上的操作（按钮/表单/列表/详情） | 接口设计（接口与页面 1:1） |
| 页面代码 | 直接演化接真实接口（不重写前端） |

**变更控制**：

- 原型锁定后，页面/接口/表不再半路新增；确需变更时走下方回流流程。
- 确需变更：先回流改原型 → 重新过判定门 → 再改受影响的接口与表，并追加说明到需求规格 §9 决策记录。
- 与现行流程一致：判定的回流规则见 SKILL.md §2.4。

## 七、本步骤判定

- [ ] 成品级原型完整（§二 六维标准）
- [ ] 判定门 6 项全部通过（§五）
- [ ] 原型已锁定，变更控制生效（§六）
- [ ] 占位数据标注清晰，且未冒充验证证据（§四）

全部通过 → 进入工序③ 后续步骤：依原型推导数据建模与接口设计，实现后端与数据库，前端接真实数据。
