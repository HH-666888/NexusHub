## 1. 定位与适用边界

- 仅形态 B 可达；形态 A/C/D 不使用本分支。
- 单体下后端负责"页面骨架 + 首屏数据"，前端只承担：
  - 模板内的变量插值与循环/条件渲染；
  - 静态资源（CSS/JS/图片）托管；
  - 少量页面级 JS 做交互与后续 AJAX（AJAX 部分仍走统一返回体，参照横切接口规范）。
- 不引入前端构建链；模板即最终下发的 HTML。

## 2. 模板文件存放位置

按后端工程确定具体路径，模板文件一律放在后端工程约定的模板目录下，不与静态资源混放：

- **Thymeleaf（Spring Boot）**：模板放 `src/main/resources/templates/`，按功能域分子目录，如 `templates/user/list.html`、`templates/user/form.html`、`templates/layout/base.html`。
- **Jinja2（FastAPI）**：模板放工程根的 `templates/` 目录（与后端入口同层），按功能域分子目录，如 `templates/user/list.html`、`templates/layout/base.html`。
- 共享布局（顶部导航、页脚）单独抽成 `layout/base.html`，由业务模板继承。

## 3. 变量表达式与指令

### Thymeleaf

- 变量插值：`th:text="${user.name}"`；HTML 属性替换用 `th:href`、`th:src`、`th:value` 等。
- 链接与静态资源：`th:href="@{/assets/css/common.css}"`、`th:href="@{/user/list}"`。
- 条件：`th:if="${not #lists.isEmpty(orders)}"`；循环：`th:each="order : ${orders}"`，状态变量 `orderStat.index` / `orderStat.even`。
- 表达式工具：日期、数字、字符串用内置工具对象 `#dates`、`#numbers`、`#strings`，不要在模板里写复杂业务计算。
- 表单：`th:action="@{/user/save}"`、`th:object="${userForm}"`、`th:field="*{name}"`。

### Jinja2

- 变量插值：`{{ user.name }}`；转义默认开启，需原样输出用 `{{ html|safe }}`。
- 标签：`{% if orders %}...{% else %}...{% endif %}`；循环 `{% for order in orders %}...{% endfor %}`，状态变量 `loop.index`、`loop.first`、`loop.last`。
- 链接与静态资源：`{{ url_for('static', path='css/common.css') }}`（FastAPI）或 `{{ url_for('static', filename='css/common.css') }}`（Flask，扩展场景）。
- 过滤器：日期、数字、字符串用 Jinja 内置过滤器（`|date`、`|default`、`|length`），模板内不写复杂业务计算。

### 共同约束

- 模板内只做展示层逻辑（循环、条件、格式化），不写业务规则；业务规则在后端 service。
- 统一返回体不在模板层使用：模板首屏数据由后端直接渲染；后续局部 AJAX 才走 `{"code":0,"message":"success","data":{}}`，规则照横切接口规范。

## 4. 模板继承与块机制

- 共用骨架抽到 `layout/base.html`，定义可被子模板覆写的块：
  - Thymeleaf：`th:fragment` 定义块（如 `<head th:fragment="head">`、`<body th:fragment="content">`），子模板用 `th:replace="~{layout/base :: head}"`、`th:insert` 组合；或使用 `th:replace` 组合多片段。
  - Jinja2：`{% block title %}...{% endblock %}`、`{% block content %}...{% endblock %}`；子模板 `{% extends "layout/base.html" %}` 后覆写同名块。
- 业务模板只覆写差异块，公共导航、页脚、全局 CSS/JS 引入在 base 里写一次。
- 完整 HTML 骨架只在布局模板中维护一份，业务模板不重复粘贴。

## 5. 静态资源引用方式

- 静态资源目录：
  - Spring Boot：`src/main/resources/static/`（或 `public/`），下分 `css/`、`js/`、`img/`。
  - FastAPI：工程根 `static/` 目录，下分 `css/`、`js/`、`img/`，在后端入口挂载 `/static` 路由。
- 模板内引用：
  - Thymeleaf：`<link rel="stylesheet" th:href="@{/css/common.css}">`。
  - Jinja2：`<link rel="stylesheet" href="{{ url_for('static', path='css/common.css') }}">`。
- 业务页面级 CSS/JS 与页面同名，放 `static/css/<page>.css`、`static/js/<page>.js`；公共 `base.css`、`common.js` 在 base 模板里统一引入。
- 静态资源不做模板变量插值；含业务逻辑的局部交互脚本放 `static/js/<page>.js`，由对应页面模板引入。

## 6. Controller 渲染入口与模型数据传参

### Spring Boot（Thymeleaf）

- Controller 方法返回视图名（字符串），通过 `Model` 传数据：

  ```java
  @GetMapping("/user/list")
  public String list(Model model,
                     @RequestParam(name = "page", defaultValue = "1") int page,
                     @RequestParam(name = "page_size", defaultValue = "10") int pageSize) {
      model.addAttribute("page", userService.page(page, pageSize));
      return "user/list";
  }
  ```

- 重定向用 `redirect:/user/list`；表单提交成功后重定向到列表页，避免重复提交。
- 模板名与 `templates/` 下相对路径一一对应，不带 `.html` 后缀。

### FastAPI（Jinja2）

- 注入 `Jinja2Templates`，路由函数返回 `templates.TemplateResponse(...)`，上下文字典传数据：

  ```python
  @router.get("/user/list")
  def list(request: Request,
           page: int = 1,
           page_size: int = 10,
           db: Session = Depends(get_db)):
      data = user_service.page(db, page, page_size)
      return templates.TemplateResponse("user/list.html",
                                        {"request": request, "page": data})
  ```

- `request` 键为 Jinja2 模板渲染必须传入；重定向用 `RedirectResponse(url_for(...))`。

### 共同约束

- 模型数据结构与接口规范的分页结构对齐：`{"list":[], "total":0, "page":1, "page_size":10}`，模板直接消费该结构渲染表格与分页器。
- 鉴权：在 Controller/路由入口统一校验登录态，未登录重定向到登录页；具体拦截器/依赖注入落点见对应后端分支文件与 `references/横切约定/认证鉴权/认证鉴权.md`。
- 错误页：404、500 使用各自框架的错误视图机制，渲染 `error/404.html`、`error/500.html`，不暴露堆栈。

## 7. 与原生 HTML 静态资源的分工

- 模板文件：负责"带变量的页面骨架"，存放在后端 `templates/`（或 `resources/templates/`）。
- 静态资源（CSS/JS/图片）：负责"无变量的样式与交互脚本"，存放在后端 `static/`（或 `resources/static/`）。
- 分工原则：
  - 任何需要后端数据驱动的结构（表格行、菜单项、条件显示块）写在模板里。
  - 任何与后端数据无关的样式、纯客户端交互脚本（表单校验、按钮展开折叠、AJAX 局部刷新）写在 `static/`。
  - 模板内不直接写大块 CSS/JS；页面级少量内联脚本仅用于引导初始化，业务逻辑抽到 `static/js/<page>.js`。
- AJAX 局部刷新：页面已由模板渲染首屏，后续局部更新通过 `fetch` 打后端接口，返回体走统一返回体，前端封装方式与 `references/03-三方向开发/前端-原生HTML.md` 第 4 节一致。

## 8. 有序生成顺序与验证门

- 生成顺序（形态 B 整体工序③ 的前端段）：
  1. 后端工程内 `templates/layout/base.html` 骨架。
  2. `static/css/base.css`、`static/css/common.css`、`static/js/common.js`。
  3. 原型开发：按页面结构清单制作各功能域业务模板（`user/list.html`、`user/form.html` 等），先以占位数据渲染，页面视觉/跳转完整；过原型判定门（`原型开发.md` §五）后锁定为权威依据。
  4. 接真实数据：占位数据替换为后端 Controller 传参（按接口定义，见 `接口设计.md`）。
  5. 页面级 `static/css/<page>.css`、`static/js/<page>.js`。
  6. 错误页 `error/404.html`、`error/500.html`。
- 验证门具体动作（对应 SKILL.md §4.2 前端层合格线）：
  1. 后端服务按对应后端分支文件要求启动成功。
  2. 用浏览器访问受保护首页：未登录跳转登录页；已登录渲染出表格与分页器，模板变量无空白、无未渲染占位符（如 Thymeleaf 的 `??`、Jinja2 的 `{{ }}` 原样泄漏）。
  3. 所有 `<link>`、`<script>`、`<img>` 引用的静态资源均 200 可加载，无 404。
  4. 至少一条表单提交走通，成功重定向到列表页，失败展示后端返回的错误消息。
  5. 404/500 错误页可正常展示，不暴露堆栈。

任一项失败即按 SKILL.md §2.4 判定回流到工序③ 对应步骤，修复后重过本门；同一道门连续 3 次不通过按 SKILL.md §2.5 止损。
