## 一、定位与输入

- **输入**：**锁定原型**（`原型开发.md` §六，直接依据——页面展示的数据对象与字段即表与字段的来源）+ 需求规格中的实体清单及关系（工序①）、需求清单。
- **输出**：表结构清单（表/字段/类型/索引/外键），作为建表脚本与 ORM 实体的唯一来源。
- **执行时机**：原型判定通过（`原型开发.md` §五）后、后端代码生成之前；**数据库先于后端实现**（依赖顺序）。

**规则**：表结构必须能从实体清单回推；需求中"被操作的事物"必须在表结构中存在对应表；不建"预留表""无关表"。

## 二、实体 → ER 建模

0. **原型核对（先行）**：遍历锁定原型，把页面展示的每个数据对象与字段记录为候选实体/字段来源；与工序① 实体清单合并去重——原型有而实体清单无的，回流工序① 补充实体；实体清单有而原型不展示的，核对是否遗漏页面或为纯后台数据（纯后台数据单独标注，不误删）。

1. **实体 → 表**：每个业务实体对应一张表（实体清单中有独立身份的实体 → 表；属性/状态 → 字段，不单独建表）。
2. **属性 → 字段**：实体关键属性映射为字段；每个实体至少保留主键与审计字段（见 §四）。
3. **关系建模**：

| 关系 | 建模方式 | 示例 |
|---|---|---|
| 1:1 | 外键放任一侧，或用同一主键 | 用户 ↔ 用户档案（user_id 外键） |
| 1:N | 外键放"多"侧 | 用户 1:N 借阅记录（借阅记录.user_id） |
| M:N | 中间关联表 | 图书 M:N 作者（book_author 关联表） |

4. **ER 产出模板**：

```text
实体关系（文字版 ER）：
[用户] 1 ──< N [借阅记录] N >── 1 [图书]
用户: id, name, role
借阅记录: id, user_id(FK), book_id(FK), borrow_date, return_date
图书: id, isbn, title, status
```

## 三、ER → 表结构

每个实体/关联表按以下结构定义：

| 表名 | 字段 | 类型 | 约束/索引 | 说明 |
|---|---|---|---|---|
| users | id | BIGINT UNSIGNED | 主键，自增 | 用户表 |
| users | name | VARCHAR(64) | NOT NULL | 用户名 |
| … | … | … | … | … |

**表结构模板**：

```markdown
### {表名} —— {一句话用途}
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | 主键，自增 | 主键 |
| {字段} | {类型} | {NOT NULL / 默认值 / UNIQUE / 索引} | {说明} |
| created_at | DATETIME(3) | NOT NULL | 创建时间（审计字段） |
| updated_at | DATETIME(3) | NOT NULL | 更新时间（审计字段） |
| deleted_at | DATETIME(3) | NULL | 软删除（NULL=未删除） |

索引：{唯一索引/普通索引定义}
```

## 四、字段模板与全局约定

**全局默认值**（对齐 SKILL.md §0.4，分支文件不另立数值）：

| 项 | 默认值 |
|---|---|
| 主键 | 统一 `id`；BIGINT UNSIGNED 自增（PostgreSQL 用 identity/serial，SQLite 用 rowid 别名） |
| 审计字段 | `created_at` / `updated_at` / `deleted_at`（软删除，NULL=未删除），毫秒精度 DATETIME(3) / TIMESTAMP(3) |
| 字符集 | MySQL：InnoDB + utf8mb4，排序规则 utf8mb4_0900_ai_ci（旧版本回退该版本官方默认规则） |
| 命名 | 表名/字段名/索引名符合《横切约定·命名规范》（snake_case 等约定） |

**字段类型选择规则**：

- 金额/精确小数 → DECIMAL（浮点精度不足，不用于金额）。
- 枚举状态 → 短整型或定长字符串，取值在需求中定义。
- 时间 → DATETIME(3)（毫秒精度），不用字符串存时间。
- 文本长内容 → 明确长度或 TEXT 类型，按实际最大长度取。

## 五、与 ORM 衔接

- 表结构确定后，按所选 ORM 生成实体定义：
  - Java 侧（MyBatis(-Plus) / JPA）→ `数据库-ORM-Java.md`
  - Python 侧（SQLAlchemy）→ `数据库-ORM-Python.md`
  - 前端/全栈侧（Prisma）→ `数据库-ORM-Prisma.md`
- **规则**：ORM 实体字段、类型、关系必须与表结构清单**逐字段一致**；不一致以表结构清单为准并回流修正。

## 六、产出与校验

**产出**：表结构清单 + ER 说明，作为建表/迁移脚本的唯一来源（脚本执行见 SKILL.md §4.2 数据库层校验）。

**校验清单**（全部满足才通过）：

- [ ] 实体清单中每个业务实体都有对应表（无缺失、无多余）
- [ ] 需求中"被操作的事物"全部可追溯（逐条核对）
- [ ] 原型页面展示的数据对象与字段全部有对应表/字段（无"页面有数据、表里没字段"）
- [ ] 关系建模正确（1:N 外键在"多"侧，M:N 有中间表）
- [ ] 字段类型/命名/审计字段符合 §四 全局约定
- [ ] 与 ORM 实体定义逐字段一致

不通过 → 回流修正表结构，重过本工序。
