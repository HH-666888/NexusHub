# 实体角色识别（工序① · 步骤4）

## 一、输入与输出

- **输入**：需求片清单（含主题标签）。
- **输出**：实体清单 + 角色清单，回写需求规格 §2/§3。
- **规则**：识别必须基于需求片，**不凭空添加**实体或角色；切片主题标签是识别起点，不是全部依据。

## 二、实体识别

目标：找出业务中"需要被记录和操作的事物"。

**方法：名词抽取法**

1. 通读需求片，圈出所有**名词短语**。
2. 按以下规则分类：

| 类别 | 判定标准 | 示例（图书管理） |
|---|---|---|
| 业务实体 | 有独立身份、需要存储与操作 | 图书、用户、借阅记录 |
| 属性 | 描述实体的特征，不独立存在 | 书名、ISBN、借出日期 |
| 状态 | 实体在生命周期中的取值 | 在库、已借出、逾期 |
| 动作 | 对实体的操作，不是实体 | 借书、还书、查询 |
| 无关名词 | 环境词、修饰词，不进入模型 | 系统、页面、按钮 |

3. 产出**实体清单**：每个实体标注——名称、一句话定义、关键属性（至少 2 个）、与其他实体的关系（1:1 / 1:N / M:N，不确定时标"待确认"）。

**检查清单**（全部满足才通过）：

- [ ] 需求中每个"被操作的事物"都出现在实体清单
- [ ] 每个实体都有至少一条需求与之关联（无孤立实体）
- [ ] 无把"动作"或"状态"误当实体
- [ ] 实体命名与《横切约定·命名规范》一致（语义明确，不缩写）

## 三、角色识别

目标：找出"谁使用/操作这个系统"。

**方法：动作主体法**

1. 逐条需求片找动作的执行者（"管理员可以…""用户登录后…"）。
2. 分类：

| 类别 | 说明 | 示例 |
|---|---|---|
| 用户角色 | 与系统交互的人，决定页面与权限 | 普通用户、管理员 |
| 系统角色 | 自动执行的动作主体（定时任务、回调） | 定时对账任务 |

3. 合并同名角色，产出**角色清单**：每个角色标注——名称、一句话职责、可执行的需求片编号列表。

**检查清单**：

- [ ] 每个需求片都有明确的执行角色（或注明"系统自动"）
- [ ] 同名角色已合并，无一人多名的重复角色
- [ ] 角色数不超过合理规模（超 6 个时检查是否拆得过细）

## 四、本步骤判定

- [ ] 实体清单与角色清单齐全，与需求片一一可追溯
- [ ] 两类检查清单全部通过
- [ ] 命名符合《横切约定·命名规范》

全部通过 → 进入范围与约束。
