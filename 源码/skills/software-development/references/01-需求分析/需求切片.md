## 一、为什么切

需求通常是复杂的：一次描述含多个意图、表述夸张含混、解释错乱、内容过多。不切片，需求无法被分析、被推导、被验收。切片是让"复杂需求可分析"的第一层处理。

**目标**：把用户的自然语言描述转成**结构化的需求片**，不丢失信息、不添加臆测。

**前置**（对应原"需求获取"）：

1. **通读原话**：完整读取用户输入，识别"要做什么"（功能）与"不能做什么/边界"（约束）。
2. **区分事实与推测**：用户明确说出的记为需求；模型推导的先标为**假设**，经用户确认或按《需求规格模板.md》§歧义 处理后才能进入规格。
3. **必须避免**：把模型自己的设计偏好写进需求（如"用 Vue 实现"）——技术实现属于工序②，不属于本工序。

## 二、切片

把原始需求拆成**语义完整的最小可核验单元**（需求片）。

**粒度说明（重要）**：所谓"一句话一条需求"只是概括性说法，**不必死板理解为字面的一句话**。切片的唯一标准是**语义完整、可独立核验**——一片可以是一句话、一段话、或一段话中的一个完整意图，取决于原始表述的实际粒度。切片的粒度由语义完整性决定，不为凑"一句话"硬切。

**切片规则**：

| 原始情况 | 处理 |
|---|---|
| 一句话包含多个意图 | 拆成多片，每片一个意图 |
| 一个意图散落在多处 | 并成一片，记录合并来源 |
| "为什么"（背景）与"是什么"（规则）混写 | 分开：背景归背景，规则归规则 |
| 条件、动作、结果纠缠 | 一片内保留完整语义链，不拆散 |

## 三、三标签

每片必带三个标签，缺一视为切片不合格：

| 标签 | 内容 | 用途 |
|---|---|---|
| 来源 | 回指原始需求的位置（第几段/原话片段） | 复核可追溯（对应 RAG 的 source） |
| 主题 | 涉及的业务对象（实体/角色） | 支撑实体角色识别 |
| 类型 | 功能 / 约束 / 流程 / 性能 | 支撑分类处理与下游路由 |

## 四、三轴分级

按重要程度划分层级，**三轴交叉定级**，每片携带"有多重要、在哪一层、改了影响多大"的完整信息：

| 轴 | 分级 | 含义 | 用途 |
|---|---|---|---|
| 价值层 | 核心 / 重要 / 增强 | 缺了这一片系统能不能用 | 对应 P0/P1/P2，定义与验收应用见《需求规格模板.md》§优先级 |
| 依赖层 | 基础能力 / 业务能力 / 展示能力 | 谁依赖谁（登录→订单→报表） | 决定生成顺序与回流方向 |
| 牵连度 | 高 / 中 / 低 | 会牵连多少个接口/表/页面 | 决定变更成本与风险 |

**规则**：价值层是必做判定（默认把"核心业务闭环"标核心/P0）；依赖层与牵连度由切片时的引用关系推断，推断依据记入标签。

## 五、整合

处理复杂难懂、解释错乱、内容过多三类问题：

| 问题 | 处理 |
|---|---|
| 难懂 | 用大白话重述，保留原文映射（来源标签可查原句） |
| 错乱 | 按固定逻辑重排：目标 → 角色 → 流程 → 规则 → 边界 → 约束 |
| 重复 | 合并，记录合并来源（几处原文合成一片） |
| 过多 | 抽象成"规则 + 例表"（如权限规则一句话 + 角色权限矩阵表） |

**约束处理**（原"隐含约束"中与切片相关的前置检查）：需求中未明说的约束（性能/安全/并发/部署/数据规模/合规/设备）由《范围与约束.md》逐项检查，本步骤不重复；切片时发现表述不清的约束，按《需求规格模板.md》§歧义 标注待确认，不默认"没有要求"。

## 六、可分析

切片分级整合后的需求片，必须能直接支撑以下分析动作，缺一视为切片未完成：

| 分析动作 | 从切片取什么 | 落地位置 |
|---|---|---|
| 实体识别 | 每片主题标签与名词 | 实体角色识别.md |
| 角色识别 | 每片动作主体 | 实体角色识别.md |
| 接口推导 | 每片验收条件 → 接口 | 接口设计.md（工序③） |
| 页面推导 | 每片使用角色与操作 → 页面 | 页面结构设计.md（工序③） |
| 数据建模 | 每片业务对象 → 表 | 数据建模.md（工序③） |
| 变更影响 | 改一片 → 按标签查牵连 | 验收对照（工序⑥） |
| 验收 | 逐片核验，未覆盖即回流 | 交付清单.md（工序⑥） |

## 七、本步骤判定

- [ ] 每片语义完整、可独立核验（未死板按字面一句硬切）
- [ ] 每片带三标签（来源/主题/类型）
- [ ] 每片完成三轴分级（价值/依赖/牵连）
- [ ] 难懂/错乱/重复/过多内容已按 §五 处理
- [ ] 无未记录的假设

全部通过 → 产出需求片清单，进入实体角色识别。
