## 一、定位与触发

- **位置**：6 工序的第 ① 道，全流程唯一输入口。
- **输入**：用户原始描述、附件、既有资料。
- **产物**：结构化需求规格（落盘 `docs/requirements.md`）。
- **地位**：需求规格是**全流程唯一验收基线**——工序⑥ 验收交付、验证门校验、接口推导、数据建模全部以它为对照依据。
- **触发条件**：进入本工序时，必须完整读取用户提供的全部材料（含附件、图片、表格）；读不到的材料先解决读取问题，再进入后续步骤。
- **方法论**：本工序的两个核心思路见 skill 最外层《方法论.md》——**方法论1 需求切片**、**方法论2 系统提问**；本工序的 5 个子文件是这两个方法论在需求域的落地执行规则。

**本工序结束时必须交付**：需求规格，且满足——每条需求（需求片）有可核验的验收条件；实体、角色、范围、约束、优先级齐全；无未记录的假设。

## 三、流程编排

按以下顺序执行，前一步产出是后一步输入：

```
① 通读材料（附件/原话，读全为止）
   ↓
② 提问规划（方法论2）：按 11 维清单一次问清全链路决策，答复回写决策记录
   ↓
③ 需求切片（方法论1）：切片 → 三标签 → 三轴分级 → 整合 → 可分析
   ↓
④ 实体角色识别：从需求片提取业务实体与使用角色
   ↓
⑤ 范围与约束：明确做什么/不做什么，逐项检查隐含约束
   ↓
⑥ 规格落盘：按三层结构模板写入 docs/requirements.md，自检后进入工序②
```

**规则**：

- 步骤② 的提问先于步骤③~⑥ 的处理：先问清再切，避免切片后因缺决策信息返工。
- 各步骤发现缺项或需求变更：回流对应步骤修正，再重走受影响步骤。

## 四、本工序判定

| 检查项 | 合格线 |
|---|---|
| 规格完整性 | 三层结构（需求域 → 需求组 → 需求片）齐全，模板关键节完整 |
| 需求质量 | 每片有可核验的验收条件；实体/角色/范围/约束/优先级齐全 |
| 切片合规 | 每片语义完整、带三标签（来源/主题/类型）与级别；无死板按字面一句硬切 |
| 提问合规 | 11 维决策点已覆盖；未确认项按默认执行并写入决策记录 |
| 假设透明 | 无未记录的假设（每项假设有来源与影响范围） |
| 产物落盘 | docs/requirements.md 已写入并随项目提交 |

全部合格 → 进入工序② 架构设计。不通过 → 补齐后重过本工序。
