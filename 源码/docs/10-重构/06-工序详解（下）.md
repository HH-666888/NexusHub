# 六、工序详解（下）：集成装配 / 自动测试 / 验收交付

# 第 4 道：集成装配（assemble）

## 1. 这一步要解决什么

把分头写好的模块拼成一个能启动的完整应用：入口文件、路由、静态资源、数据库初始化。

## 2. 关键设计：提示词必须带**真实代码片段**

如果只给文件名，模型不知道内容，装配就退化成拼接。所以输入必须包含：

```json
{
  "files": [
    { "path": "db/schema.sql", "content": "…最多 2000 字…" },
    { "path": "api/main.py", "content": "…" },
    { "path": "web/index.html", "content": "…" }
  ],
  "entry": "api/main.py",
  "run": { "port": 8000 }
}
```

超长文件截断时保留头尾，并在提示词里注明“已截断”。

## 3. 任务

通常 1 条：`接线与配置`。

产出：
- 一个可启动的入口（如果 `api/main.py` 不满足，生成 `app.py`）
- 静态文件挂载（FastAPI `StaticFiles` 或 `http.server`）
- 数据库初始化调用（启动时建表）
- 一个 `README` 说明怎么跑（可选）

## 4. 提示词

```
你是集成工程师。下面是各模块的真实代码。请生成一个入口文件，把它们接起来。

要求：
1. 只能新增/修改下面列出的文件，不要重写模块内部逻辑。
2. 入口必须监听 0.0.0.0:PORT（PORT 从环境变量读，默认 8000）。
3. 启动时自动建表（如果 db/schema.sql 存在）。
4. 输出 JSON：{ "files": [{ "path": "...", "content": "..." }], "entry": "..." }
```

## 5. 校验

| 检查 | 不通过 |
|---|---|
| 入口文件存在 | 重试 1 次 |
| `py_compile` 通过 | 重试 1 次 |
| 端口读取正确（env 或常量） | 记 warning，不阻塞 |
| 静态文件路径存在 | 记 warning |

## 6. 事件

```
phase(saving, "集成装配")
task(created, 接线与配置)
task(started) → text("入口、路由、配置一次接好") → file(...) → task(done)
```

## 7. 界面动作

- 第 4 张卡片进行中，副标“合成中”
- 代码区出现入口文件（`file` 事件）
- 各分支向中间汇合（现有动画，无需改）

# 第 5 道：自动测试（test）

## 1. 这一步要解决什么

在交付前，用**真实请求**验证产物，而不是看“代码写完了”。

## 2. 三层检查

### 2.1 静态检查（不需要起服务）
| 项 | 方法 |
|---|---|
| 文件齐全 | 架构声明的 files 都存在 |
| 无外部依赖 | 生成物里不出现 `cdn.` `unpkg` |
| 安全 | 不含 `eval(`、`os.system(` 明显危险调用 |

### 2.2 运行检查（真起进程）
1. 在 `D:/nexus-workspace/<run_id>` 起 `python <entry>`，分配端口
2. 轮询 `/` 直到 200（最多 15s）
3. 逐条跑验收标准：
   - 页面类：`GET /` 返回 200 且包含关键文本
   - 接口类：按 spec 里描述的接口发请求（模型生成测试用例）
4. 关进程

### 2.3 跨环节探针
| 探针 | 验证 |
|---|---|
| 模块是否进了产物 | `arch.modules[].files` 的内容出现在最终文件里 |
| 表是否建了 | sqlite 里 `sqlite_master` 存在对应表 |
| 数据是否落库 | 调一次写接口后，表里多一行 |

## 3. 测试用例哪来

由模型根据 `acceptance` 生成，格式：

```json
{
  "cases": [
    {"id": "c1", "acceptance": "a2", "type": "http",
     "request": {"method": "POST", "path": "/api/checkin", "json": {"habit": "read"}},
     "expect": {"status": 200}},
    {"id": "c2", "acceptance": "a2", "type": "http",
     "request": {"method": "POST", "path": "/api/checkin", "json": {"habit": "read"}},
     "expect": {"status": 200, "note": "重复打卡不重复计数，需查库"}},
    {"id": "c3", "acceptance": "a4", "type": "page",
     "request": {"method": "GET", "path": "/"},
     "expect": {"status": 200, "contains": "连续"}}
  ]
}
```

校验：每个用例必须映射到一条 `acceptance`，覆盖不全则补。

## 4. 执行

```python
for case in cases:
    emit(task(created, case.title))
    emit(task(started))
    result = run_case(case)          # 真 HTTP
    emit(check(results=[...], summary))
    emit(task(done|failed))
```

## 5. 失败 → 回环

失败时：

1. 记录失败用例、状态码、响应片段
2. `phase(building, "回环修复")`
3. 生成 `fix` 任务：把失败信息 + 相关文件内容给模型，让它改
4. `file(replace=true)` 重写文件
5. `phase(checking, "复测")`，只重跑失败用例
6. 通过 → 继续；仍失败 → `run failed`

## 6. 事件

```
phase(checking, "自动测试")
task(created/started/done ×N)
check(results=[...], summary={passed,total,failed})
[失败] task(failed, reason="POST /api/checkin 返回 500: …")
[回环] phase(building) → task(fix) → file(replace) → phase(checking) → task(复测) → check(...)
```

## 7. 界面动作

- 第 5 张卡片进行中
- 用例节点逐条出现，绿勾/红叉
- 失败节点红，点开看到：请求、状态码、响应体
- 回环时第 3 道重新亮起（现有能力）

## 8. 验收
- [ ] 故意把某接口改坏 → 测试红，且能看到 500 与响应
- [ ] 修复后复测通过，`verdict` 3/3
- [ ] 测试请求真的打到了进程（日志里能看到）

# 第 6 道：验收交付（deliver）

## 1. 要做的事

1. 起运行时（进程），拿到预览地址
2. 汇总三层验收（db / api / ui）
3. 落最终产物（`index.html`、`spec.json`、`manifest.json`）
4. 发 `verdict` 与 `artifact`，`phase(done)`

## 2. 运行时（本机进程）

```python
files_dir = workspace/<run_id>
proc = subprocess.Popen([python, entry], cwd=files_dir, env={PORT: port})
wait_http(f"http://127.0.0.1:{port}/", timeout=15)
```

- 端口从 50000 起找空闲
- 进程句柄写 `run_runtimes` 表（已有）
- 预览地址返回前端
- 超时：杀进程，标 `RUNTIME_TIMEOUT`

> Docker 后端保留同一接口，后续买服务器再切；本机用进程实现“同样的效果”。

## 3. 三层验收

```json
{
  "layers": [
    {"layer": "db",  "passed": 3, "total": 3, "checks": [{"name": "表已建", "pass": true}]},
    {"layer": "api", "passed": 4, "total": 4, "checks": [...]},
    {"layer": "ui",  "passed": 2, "total": 2, "checks": [...]}
  ]
}
```

来源：第 5 道的真实检查结果，不是写死。

## 4. 产物

| 文件 | 内容 |
|---|---|
| `index.html` | 最终页面 |
| `spec.json` | AppSpec |
| `arch.json` | ArchSpec |
| `manifest.json` | 文件清单 + sha256 + 大小 |

全部进 `artifacts` 表（内容），同时写工作区（供运行）。

## 5. 事件

```
phase(deliver, "验收交付")
task(created, 打包产物)
verdict(layers, passed, total)
artifact(...)
task(done)
phase(done)
```

## 6. 界面动作

- 第 6 张卡片进行中 → 全部完成
- 顶栏“已完成 · 6/6”
- 预览 tab 打开真实地址
- 验收 tab 显示三层结果

## 7. 验收
- [ ] 预览地址能打开、能操作
- [ ] verdict 的 passed/total 来自真实检查
- [ ] 关掉进程后 `run_runtimes` 状态变为 exited（回收）
