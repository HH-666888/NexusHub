# 十一、方案定稿：双轨重建（/v2）

> 这一版取代之前“只重建后端”的建议。
> 结论先说：**新前端 `web-v2/` + 新后端 `app/v2/`，挂在 `/v2/` 与 `/api/v2`；旧站原样保留。**

---

## 1. 形态

```
源码/
├── web/               旧前端（一行不动，继续占 /）
├── backend/app/       旧后端（一行不动，继续占 /api/v1）
│
├── web-v2/            新前端（从 0 写，视觉与旧站一致）
└── backend/app/v2/    新后端（从 0 写，独立路由）
```

路由：

```
GET  /                 → web/          （旧站，兜底）
GET  /v2/              → web-v2/       （新站）
*    /api/v1/*         → app/          （旧接口）
*    /api/v2/*         → app/v2/       （新接口）
```

FastAPI 挂载顺序：`/api/v2` → `/v2` → `/api/v1` → `/`。互不遮挡。

---

## 2. 为什么这样最好

| 维度 | 双轨（/v2） | 原地改（单轨） |
|---|---|---|
| 演示兜底 | ★★★★★ 旧站随时能演 | ★★ 改坏就没了 |
| 新旧对比 | ★★★★★ 两个地址并排 | ★★ 只能翻 git |
| 视觉一致性 | ★★★★★ 复制同一套样式 | ★★★★ 边改边漂 |
| 前端风险 | ★★★★ 新站独立，坏了不影响旧站 | ★★ 一边改一边碎 |
| 代码重复 | ★★ 两套前端（可接受） | ★★★★★ 单套 |
| 认知负担 | ★★★ 两个入口 | ★★★★★ 一个入口 |
| “从 0”纯度 | ★★★★★ 新目录新代码 | ★★ 旧债缠身 |

结论：比赛优先，选双轨。

## 3. 新前端 `web-v2/` 怎么做

### 3.1 起点：复制旧站，再“去原型化”

```
cp -r web/ web-v2/
```

复制后**视觉一模一样**，然后逐页修掉原型遗留：

| 页面 | 原型遗留 | 修法 |
|---|---|---|
| welcome | 演示文案/固定截图 | 保留版式，文案接真实数据（可选） |
| login/register | 演示账号提示硬编码 | 保留，账号规则简化为“用户名 > 4、密码 > 6” |
| projects | 演示卡片残留、固定统计 | 只渲染真实 runs；统计由接口算 |
| workbench | 演示时间线、写死进度、假分支 | 只走事件流；无事件则空态 |
| settings | 部分控件空转 | 全部接 `/api/v1/settings`（复用旧接口） |

### 3.2 仍然保留的东西

- CSS 变量、间距、圆角、阴影：**原样**
- 页面结构、类名：**尽量原样**（减少视觉回归）
- 交互（树布局、聚焦、折叠、代码流、回放、速度）：**原样**
- 图标、字体：**原样**

### 3.3 允许的修改

- 删掉“演示态”分支（`demo.js` 不再进入 v2）
- 删掉写死的数字（13 项、46%、¥5.87）
- 加门禁弹窗、证据字段、任务定位
- 修原型期遗留的小问题（布局挤压、重复 chip、错误文案）

> 一句话：**看起来一样，逻辑全真。**

### 3.4 v2 前端与接口

| 功能 | 用哪个接口 |
|---|---|
| 登录/注册/退出 | `/api/v1/auth/*`（复用，避免重写密码与 session） |
| 设置 | `/api/v1/settings`（复用） |
| 运行列表/创建 | `/api/v2/runs` |
| 事件流 | `/api/v2/runs/{id}/stream` |
| 门禁 | `/api/v2/runs/{id}/gate` / `answers` |
| 产物/验收 | `/api/v2/runs/{id}/artifacts` / `verdict` |
| 预览 | `/api/v2/runs/{id}/runtime` |

复用 auth 的原因：账号、密码、session 是边界，不是产品核心；重写一遍只会引入新 bug。

## 4. 新后端 `app/v2/` 怎么做

```
backend/app/v2/
├── __init__.py          # APIRouter 汇总
├── runs/router.py       # 列表/创建/详情/事件/流/暂停/取消/删除
├── gate/router.py       # 提问与回答
├── artifacts/router.py  # 产物读取
├── pipeline/
│   ├── orchestrator/    # 主循环/规划/调度/检查点
│   └── stages/          # 六道工序实现
├── ai/
│   ├── model/           # 客户端、结构化输出、录制
│   └── cost/            # 定价、记账
├── tools/               # 文件/命令/预览/HTTP
└── runtime/             # 进程运行时（复用旧的 service 也可）
```

复用（不重写）：

- `app.domain.*`（事件、规格、架构模型）
- `app.db.*`（模型、SessionLocal）
- `app.config`（新增字段）
- `app.features.auth`（登录）
- `app.features.runtime.service`（进程管理）

新写：

- 编排器、六道工序、模型客户端、成本、工具、v2 路由

---

## 5. 数据

- 共用 `nexus` 库
- 共用 `users / sessions`（同源 cookie，登录一次两边都进）
- `runs / run_events / cost_records / artifacts / run_runtimes` 共用
- v2 创建的 run id 带前缀 `r2-`，v2 列表只列 `r2-%`；旧站照常显示全部（包括 v2）
- **不加表、不改字段**

---

## 6. 与“方式一（影子后端）”的关系

之前推荐的“只重建后端”仍然成立，只是范围扩大到前端。两者共同点：

- 旧代码一行不改
- 新代码从 0 写
- 用路由/开关隔离

区别只在：新前端是复制后改，还是复用旧页面。

---

## 7. 实施顺序（更新版）

```
0. 建 web-v2/（复制）+ app/v2/（空壳路由）+ 挂载 /v2
1. v2 登录/设置（复用 v1 接口）跑通
2. v2 项目页（真实列表 + 空态）
3. v2 工作台骨架（SSE 接通，空树）
4. 模型层 + 记账
5. 编排器 + 第 1 道（真 spec + 门禁）
6. 第 2–6 道逐道接
7. 测试与回环
8. 运行时与预览
9. 前端门禁/证据/定位
10. 三场景验收 + 录制回放
```

每一步：旧站不受影响，`/v2/` 可独立验证。

---

## 8. 回滚

| 出问题 | 处理 |
|---|---|
| v2 前端坏了 | 直接用 `/` 旧站演示 |
| v2 后端坏了 | 旧站与 `/api/v1` 不受影响 |
| 整个 v2 不要了 | 删 `web-v2/` 与 `app/v2/`，主应用只删两行挂载；git 历史保留 |
