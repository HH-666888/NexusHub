# 十一、两方案对比与实施路线

## 1. 两个方式，先定义清楚

### 方式一：影子重建（推荐）

```
新链路：backend/app/pipeline/orchestrator/ + stages 真实实现 + ai/ + tools/
旧链路：demo.py 原样保留
开关：  PIPELINE=real | demo
前端：  完全不复制，复用 源码/web，只加门禁弹窗与字段
```

运行：

```
POST /runs  →  PIPELINE=real 走编排器，PIPELINE=demo 走演示
```

### 方式二：原地替换

```
在现有 pipeline/ 目录里，逐层把 demo.py 的内容换成真实实现
前端同步小改
```

## 2. 对比矩阵

| 维度 | 方式一 影子重建 | 方式二 原地替换 |
|---|---|---|
| 可回退性 | ★★★★★ 改开关即可 | ★★ 靠 git 回滚 |
| 新旧对比 | ★★★★★ 可并排演示 | ★★ 只能看历史 |
| 演示兜底 | ★★★★★ demo 永远可用 | ★★★ 改坏了就是坏了 |
| 代码量 | 多一套（约 1500 行） | 少（复用目录） |
| 认知负担 | 两套并存，需开关说明 | 单一路径 |
| 前端风险 | 低（不复制 UI） | 中（边改边坏） |
| 数据兼容 | 同一套表，天然兼容 | 同 |
| 故障隔离 | 高（真链路崩了切 demo） | 低 |
| 完成速度 | 略慢（多写接口） | 略快 |
| 适合场景 | **比赛演示、要稳** | 长期单一产品 |

## 3. 为什么推荐方式一

1. **演示风险最低**：真链路一旦在评委面前挂了，`PIPELINE=demo` 一键切回，至少能完整演示。
2. **新链路从第一行就是干净的**：不会出现“改一处动全身”的原型债。
3. **前端零复制**：只加弹窗与字段，不会产生两套 UI 漂移。
4. **可对比**：同一个需求，demo 与 real 各跑一遍，能直接讲“这是之前的模板，这是现在真的规划”。
5. **删除成本低**：比赛后删掉 `demo.py` 与开关即可，不留垃圾。

## 4. 方式一的具体形态

```
backend/app/
├── pipeline/
│   ├── demo.py                  # 保留，不动
│   ├── orchestrator/            # 新增
│   │   ├── __init__.py          # start/stop/status
│   │   ├── loop.py              # 主循环
│   │   ├── planner.py           # 需求→任务
│   │   ├── scheduler.py         # 并发/重试
│   │   ├── recorder.py          # 事件/成本
│   │   └── checkpoint.py        # 检查点
│   └── stages/                  # 现有空目录，填实现
│       ├── spec/    （plan）
│       ├── arch/    （design）
│       ├── build/
│       ├── assemble/
│       └── verify/  （test）
├── ai/
│   ├── model/client.py
│   ├── cost/ledger.py + pricing.py
│   └── prompts/                 # 各阶段模板
├── tools/
│   ├── files.py  shell.py  preview.py
└── features/runs/router.py      # 只改 start 分支
```

前端改动（3 处）：

1. `live.js`：`task` 事件的 `attempts/result` 展示
2. 新增门禁弹窗（`workbench/` 下加一个组件样式 + live.js 逻辑）
3. 侧栏点击 → 树定位

## 5. 分阶段路线（每阶段可独立验收）

### 阶段 0：准备（0.5 天）
- 写入 `.env`（key、PIPELINE=demo）
- 建 `D:\nexus-workspace`
- 跑通现有 demo（基线截图）
- **验收**：三张基线截图 + 一次 demo 运行

### 阶段 1：模型客户端 + 记账（1 天）
- `ai/model/client.py`、`ai/cost/*`
- 单测：fake 调用、成本计算
- **验收**：脚本调用一次真实模型，`cost_records` 多一条

### 阶段 2：编排器骨架（1 天）
- `orchestrator` 的 start/stop/loop
- 只跑 plan 一道：真实 spec + 事件 + 任务
- **验收**：`PIPELINE=real` 新建，第 1 道真实完成，第 2 道起停止

### 阶段 3：六道工序逐道接通（3 天）
- 顺序：design → build → assemble → test → deliver
- 每道：真实提示词 + 校验 + 事件
- **验收**：每接一道跑一个需求，产物多一个文件

### 阶段 4：门禁 + 工具 + 运行时（2 天）
- 门禁事件与前端弹窗
- 文件/命令/预览工具
- 进程运行时（D 盘工作区）
- **验收**：门禁能停能继续；产物能起进程

### 阶段 5：测试与回环（1 天）
- 测试用例生成与执行
- 失败 → fix → 复测
- **验收**：注入失败能红能修

### 阶段 6：前端增强（1 天）
- 证据字段、任务定位、门禁弹窗样式
- **验收**：视觉零回退

### 阶段 7：录制回放 + 三场景验收（1 天）
- record 一遍，replay 验证
- 三个需求全跑
- **验收**：`accept.py` 输出 3/3

合计约 **10.5 天**（按有效开发时间），实际可压缩。

## 6. 回滚点

| 阶段 | 回滚方式 |
|---|---|
| 0–1 | 不影响现有功能 |
| 2 | `PIPELINE=demo` |
| 3 | 删 `orchestrator/`，`router` 改回 demo.start |
| 4+ | 同上 + 前端只保留新增元素 |

- 代码：上述目录
- 文档：本目录 12 份
- 脚本：`scripts/e2e.py`、`scripts/accept.py`、`scripts/check_consistency.py`
- 录制：`data/cassettes/` 三套
- 报告：`验收报告.md`（自动生成）

## 8. 决策结论

> **采用方式一（影子重建），前端不复制。**
>
> 理由：演示要稳、失败可退、新链路干净、前端零漂移。
> `PIPELINE=demo` 永远保留，作为答辩现场的最后一道保险。
