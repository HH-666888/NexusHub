# 二、领域模型与事件

## 1. 五个对象

### 1.1 Run（已有表）
一次完整的构建。字段沿用现状：`id / user_id / prompt / stage / status / total_cost_cny / created_at / updated_at`。

状态机：

```
running ⇄ paused
running → done | failed | cancelled
paused  → cancelled
```

### 1.2 Task（不建表，由事件重建）
一条具体的活。**不落独立表**，通过 `task` 事件流重建（符合“12 张表不动”）。

```json
{
  "id": "task-7f3a1c2e",
  "runId": "r_xxx",
  "stage": "build",
  "parent": "task-0a1b",
  "title": "写打卡接口",
  "kind": "code",
  "state": "running",
  "note": "POST /api/checkin",
  "file": "api/main.py",
  "attempts": 1,
  "startedAt": 1794221106730,
  "finishedAt": null,
  "ms": null,
  "reason": null,
  "result": { "files": ["api/main.py"], "lines": 42 }
}
```

`kind` 枚举：`clarify | spec | design | code | wire | test | fix | deliver`。

状态机：

```
pending → running → done
              └──→ failed → (retry: running again, attempts+1)
```

### 1.3 Artifact（已有表）
产物文件内容。`name / kind / content / bytes / sha256`。**代码不进事件**，只进产物表。

### 1.4 CostRecord（已有表，从未写）
```json
{ "run_id": "...", "stage": "build", "model": "deepseek-chat",
  "prompt_tokens": 1200, "completion_tokens": 300,
  "price_tier": "peak", "cost_cny": 0.0031, "latency_ms": 820, "created_at": 1794221106730 }
```

### 1.5 Gate（人工门禁）
```json
{ "id": "gate-1", "runId": "...", "stage": "plan",
  "questions": [{ "id": "q1", "text": "打卡是否需要按习惯分类？", "options": ["需要","不需要"] }],
  "answered": false, "answers": null }
```
存 `settings`-like 还是独立？**不建表**：门禁用事件 `phase(awaiting)` + `gate` 事件携带问题，用户答案走 `POST /runs/{id}/answers` 写回事件流（`gate.answered`）。

## 2. 事件清单（17 种）

| kind | 何时发 | 关键字段 |
|---|---|---|
| `phase` | 进入/离开一道工序 | `phase`, `label`, `note?` |
| `task` | 任务 created/started/done/failed | `action`, `task{}` |
| `reasoning` | 模型的思考片段 | `delta` |
| `text` | 面向用户的说明 | `delta` |
| `spec` | 需求分析产出 | `spec: AppSpec`, `gate` |
| `arch` | 架构设计产出 | `arch: ArchSpec`, `check` |
| `ui` | 界面设计产出（可选，并入 arch） | `ui: UiSpec`, `check` |
| `modules` | 并行开发的批次摘要 | `batch` |
| `file` | 代码流式输出/整文件替换 | `path/lang/delta/done/lines/replace?` |
| `usage` | 一次调用的 token 与费用 | `usage`, `costCny`, `model`, `latencyMs` |
| `check` | 一次检查汇总（可多次） | `results[]`, `summary` |
| `verdict` | 三层验收结论 | `layers[]`, `passed`, `total` |
| `artifact` | 产物落库 | `artifact` |
| `cost` | 成本累计（前端顶栏用） | `stage`, `deltaCny`, `totalCny` |
| `error` | 不可恢复错误 | `message`, `hint` |
| `tool` | 工具调用（规划/执行） | `name`, `args`, `ok`, `latencyMs` |
| `retrieval` | RAG 命中（可选） | `query`, `hits[]` |

> 现在实现里 `task` 是裸 dict 写入；重构后统一定义在 `app/domain/event.py` 的判别联合里。

## 3. 顺序约束（硬规则）

1. 一次运行以 `phase(spec)` 开始，以 `phase(done)` 或 `error` 结束。
2. 每道工序：`phase(<stage>)` → `task(created)*` → `task(started|done|failed)*` → 该道的产出事件（`spec`/`arch`/`check`/`verdict`）。
3. `task(created)` 必须先于同 id 的 `started`；`done/failed` 必须在 `started` 之后。
4. 一个任务 failed 后，若要重试：**新 id**（`-r2` 后缀）或同 id 且 `attempts+1`；二选一，全项目统一用**同 id + attempts**。
5. `file` 事件的 `path` 必须已在 `arch.modules[].files` 中出现过。
6. `verdict` 只能出现在所有 `check` 之后、`phase(deliver)` 之后。
7. 回环修复时允许 `phase(building)` 出现在 `phase(checking)` 之后——这是唯一允许的“倒退”，前端必须支持。

## 4. 事件如何驱动前端（映射表）

| 事件 | 树 | 侧栏 | 代码区 | 顶栏 |
|---|---|---|---|---|
| `phase` | 高亮当前道 | 更新道状态 | 不清空 | 第 N/6 道 |
| `task.created` | 长出新节点 | 加一行 | — | 任务数+1 |
| `task.started` | 节点转“进行中” | 行转蓝 | — | — |
| `task.done` | 节点转绿 | 行转完成 | — | 进度 |
| `task.failed` | 节点标红 | 行标红 | — | — |
| `file` | — | — | 追加/替换 | — |
| `check` | 第 5 道下加用例节点 | 加行 | — | — |
| `verdict` | 验收 tab | — | — | — |
| `cost` | — | — | — | ¥x / ¥预算 |
| `usage` | — | — | — | 调用次数 |

## 5. 重建规则（刷新/回放）

```
GET /runs/{id}          → 状态条
GET /runs/{id}/events   → 按 seq 重放，重建 tasks（Map<id, Task>）
GET /runs/{id}/artifacts→ 产物
```

重建算法：

```python
tasks = {}
for e in events:
    if e.kind == "task":
        t = e.payload["task"]
        tasks[t["id"]] = {**tasks.get(t["id"], {}), **t}
```

前端同理（已有实现），但需补：`task.failed` 后 `attempts` 累加、`result` 合并。

## 6. 任务 id 规则

- 格式：`task-<stage>-<6位hash>`，例如 `task-build-7f3a1c`
- hash 来源：`sha1(run_id + stage + title)[:6]`
- 保证：同一 run 内唯一、可读、可复算
- 不用自增：避免重放时顺序依赖

## 7. 与现有前端字段的兼容

前端现在读 `task.state`（`pending/running/done/failed`）、`title`、`file`、`note`、`ms`、`reason`。重构后字段不变，只新增 `attempts`、`result`。**前端不需要改数据结构，只加展示。**

## 8. 事件体积控制

- `reasoning` / `text` 单条 ≤ 2KB，超出截断并标 `truncated: true`
- `file.delta` 单条 ≤ 400 字符（约 80 汉字），保证流式顺滑
- 代码全文只进 `artifacts`，不进事件
- 单次运行事件总量目标：150–400 条
