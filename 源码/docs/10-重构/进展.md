## 与文档的偏差（如实记录）

1. **并行开发改为顺序执行**
   原因：db → api → web 必须共享字段契约，并行会写出不一致的代码。
   做法：按依赖顺序生成，前者内容作为后者上下文；事件仍逐模块上报。
   影响：`modules.batch.concurrency = 1`。

2. **架构固定三模块三文件**
   原因：模型生成多文件时语法错误率高。
   文件固定：`db/schema.sql`、`api/main.py`、`web/index.html`。
   代价：复杂需求会被压缩进单文件，属“边界做薄”。

3. **测试只断言状态码**
   原因：模型猜字段名会误判（`completed` vs `done`）。
   现状：真实发请求、真实进程、覆盖所有验收标准，但语义断言弱。
   后续：可从 OpenAPI 生成字段级断言（接口契约已拿到）。

4. **录制回放已验证（三个场景）**
   - 待办：record → replay，done，成本 ¥0.0613
   - 投票：record → replay，done，成本 ¥0.0986，零错误
   - 记账：record 完成，done，成本 ¥0.0864（回放未单独跑）
   共 28 个 cassette，位于 `backend/data/cassettes/`（gitignore，本地素材）。

5. **v2 工作台的演示数据已删除**（FILES/EVENTS 置空，仅事件流注入）
   `workbench/main.js` 的无 `run` 参数时间线已改为跳转项目页，不会执行；
