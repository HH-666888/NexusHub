# 九、数据、迁移与兜底

## 1. 表结构：不动

12 张表全部保留：`users / sessions / runs / run_events / cost_records / artifacts / settings / rag_documents / rag_chunks / idempotency_keys / run_databases / run_runtimes`。

| 表 | 重构后用法变化 |
|---|---|
| `runs` | `total_cost_cny` 由真实记账累加 |
| `run_events` | 事件数量上升（150–400/run），内容变为真实 |
| `cost_records` | **首次真正写入** |
| `artifacts` | 产物变多（3–6 个） |
| `run_runtimes` | 每次预览写一行 |
| 其余 | 不变 |

**不新增表**的原因：任务状态可由 `task` 事件重建；门禁用事件表达。少一张表少一处迁移风险。

## 2. 迁移策略

- 无 schema 变更 → 不需要新 Alembic 迁移
- 若后续确需（例如任务查询性能），再单独加 `0003_tasks.sql`，并写清回滚

## 3. 旧数据

现有开发库里的运行记录（演示产物）与新链路不兼容（任务 id 不同、成本为 0）。

处理：

```sql
-- 保留用户与会话，清掉演示运行（可选）
DELETE FROM run_events WHERE run_id IN (SELECT id FROM runs WHERE total_cost_cny = 0);
DELETE FROM artifacts  WHERE run_id IN (...);
DELETE FROM runs WHERE total_cost_cny = 0;
```

> 执行前先 `SELECT COUNT(*)` 确认；这条只清“演示期”数据，不影响账号。

## 4. 工作区与清理

```
D:\nexus-workspace\<run_id>\
├── db/schema.sql
├── api/main.py
├── web/index.html
└── app.db
```

- 每次运行独立目录
- 运行结束不自动删（预览需要）
- 删除运行时：`DELETE /runs/{id}` 已有逻辑会递归删目录
- 磁盘水位：> 2GB 时启动清理（删除最旧的 20 个）

## 5. 兜底：没有模型 / 没有网

### 5.1 三档模式

| 模式 | 触发 | 行为 |
|---|---|---|
| `real` | 有 key、有网 | 全真实 |
| `replay` | 无网 / 演示保险 | 读 `data/cassettes/` 的录制，走同一套事件 |
| `demo` | 显式 `PIPELINE=demo` | 现有演示发生器（保留） |

切换：

```bash
PIPELINE=real RECORD_MODE=replay
```

前端无感知——事件格式一致。

### 5.2 录制怎么来

开发期跑一遍 `RECORD_MODE=record`，把每个 (prompt_hash → reply) 存下来。
验收场景 A/B/C 各录一套，现场直接 replay。

### 5.3 录制目录

```
backend/data/cassettes/
├── <sha1(prompt)>.json
```

内容：`{ "model": "...", "reply": "...", "usage": {...} }`。大小约 200KB/场景。

## 6. 配置与密钥

- `.env` 不入库（已 ignore）
- `.env.example` 只列字段
- 设置页只存模型名，不存 key
- 日志里不得打印 key、完整 prompt（截断 200 字）

## 7. 数据一致性检查脚本

```python
# scripts/check_consistency.py
assert sum(cost_records.cost_cny for run) ≈ runs.total_cost_cny   # 误差 < 0.0001
assert every task.done has started
assert every file event path ∈ arch.modules[].files
assert verdict.passed == len([c for c in checks if c.pass])
```

每次运行结束自动跑一遍，失败写 `error` 事件（不阻塞交付）。

演示规模足够；清理策略见 §4。
