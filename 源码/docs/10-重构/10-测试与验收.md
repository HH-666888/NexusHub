# 十、测试与验收

## 1. 分层测试

| 层 | 范围 | 是否花钱 | 运行时机 |
|---|---|---|---|
| 单元 | 领域模型、事件顺序、成本计算、提示词拼装 | 否 | 每次改代码 |
| 组件 | planner / checker / tools（用假模型） | 否 | 提交前 |
| 集成 | 完整流水线（录制回放） | 否 | 提交前 |
| 端到端 | 真模型跑 3 个需求 | 是 | 里程碑 |

## 2. 单元测试清单

```
test_event_order.py        事件顺序约束 1–7 条
test_task_state.py         pending→running→done/failed/retry

```

## 3. 组件测试（假模型）

`FakeModel` 按顺序返回预设 JSON：

```python
fake = FakeModel([
    plan_reply, design_reply, build_db_reply, build_api_reply,
    build_web_reply, assemble_reply, test_reply, fix_reply,
])
```

断言：
- 事件序列符合 `02-事件` 的顺序约束
- 每个任务都有 started/done
- 失败时发的是 `task.failed` 而不是 `error`

## 5. 端到端（真模型）

```bash
python scripts/e2e.py --prompt "做一个习惯打卡，能看连续天数"
```

输出：

```
✓ 6/6 道完成
✓ 产物 4 个：db/schema.sql api/main.py web/index.html manifest.json
✓ 预览 http://127.0.0.1:50123/ 可访问
✓ 测试 4/4 通过（真实请求）
✓ 成本 ¥0.08，记录 9 条
✓ 事件 212 条，顺序合法
```

同一脚本跑三个需求，结果写入 `data/e2e-report.json`。

## 6. 验收脚本（比赛现场用）

```powershell
# 一键验收：起服务、跑三个需求、截图、生成报告
python scripts/accept.py
```

步骤：

1. 检查 `.env` / DB / key
2. 依次创建 3 个 run（A/B/C），等待完成（最多 5 分钟/个）
3. 对每个 run：起预览、curl 首页、断言关键文本
4. 截图（调用 `tools/shot.mjs`）
5. 输出 `验收报告.md`：每个需求的证据

## 7. 失败注入（演示“真实失败”）

```http
POST /api/v1/runs/{id}/inject-failure
{ "stage": "test", "case": 2, "kind": "http_500" }
```

实现：测试执行器在对应用例上返回伪造的 500，走真实回环流程。
只在 `PIPELINE=demo` 或显式开关下可用，避免污染真实测试。

## 8. 回归基线

每次改动后对比：

| 指标 | 基线 |
|---|---|
| 三个场景通过率 | 3/3 |
| 平均事件数 | 150–400 |
| 平均成本 | ¥0.05–0.20 |
| 平均耗时 | 60–180 秒 |
| 前端截图差异 | 仅允许新增元素 |

## 9. 手工验收清单（答辩前）

- [ ] 冷启动：`启动.bat` → 登录 → 新建 → 跑完
- [ ] 刷新页面：状态还原、不重复扣费
- [ ] 暂停/继续/取消 各一次
- [ ] 门禁：出现 → 回答 → 继续
- [ ] 失败：红卡 → 原因 → 修复 → 复测
- [ ] 速度：0.2× 播放完整一遍
- [ ] 预览：打开产物、点两下
- [ ] 断网：切 replay，再跑一遍
- [ ] 删除：删掉一个 run，列表与磁盘同步
