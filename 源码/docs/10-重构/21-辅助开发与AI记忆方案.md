# 二十一、辅助开发与 AI 记忆方案

> 版本 v1.0 · 2026-11-11
> 状态：**开发方案**，未动代码。
> 定位：在现有产品上加一个入口，不是做第二个产品。

---

## 0. 一句话

**工作流是 AI 替你做完整开发；辅助开发是你自己一步一步做，AI 在旁边按六道工序帮你。**
记忆只服务“辅助开发”，不进入“工作流”。

---

## 1. 边界：为什么个性化只给辅助

| | 工作流 | 辅助开发 |
|---|---|---|
| 谁写代码 | AI | 用户 |
| 输入 | 一句话 | 用户的项目与代码 |
| 记忆 | **不注入** | 注入 |
| 目标 | 可复现、可验收 | 顺手、越用越懂你 |
| 失败代价 | 产物不对 | 习惯被误导 |

工作流不注入个性的三条理由，答辩时可以直接讲：

1. **可复现**：同一个需求，不同用户、不同时间，结果应当一致，才谈得上验收。
2. **可比对**：演示时要能对比“两次生成”，个性化会让差异无法归因。
3. **正确性优先**：个性会影响默认值和表达，生成链路不应被偏好带偏。

一句话话术：

> 工作流追求正确与可复现，所以用模型的纯粹能力；
> 辅助开发面向个人习惯，所以记忆只在这一侧生效。

## 3. 辅助开发页：信息架构

```
┌──────────┬───────────────────────────────┬──────────────────┐
│ 六阶段    │ 当前阶段工作区                 │ AI 助手           │
│ 01 需求 ●│ 需求卡 / 验收清单              │ 还缺什么           │
│ 02 设计  │ 模块 / 文件 / 接口             │ 检查结果           │
│ 03 开发  │ 代码编辑器（用户写）            │ 问题单             │
│ 04 集成  │ 接线清单                      │ 下一步建议         │
│ 05 测试  │ 用例 + 运行结果                │ [让 AI 补这一步]   │
│ 06 交付  │ 上线前检查清单                 │                  │
├──────────┴───────────────────────────────┴──────────────────┤
│ 状态条：事件 / 检查 / 成本                                     │
└─────────────────────────────────────────────────────────────┘
```

原则：

- **中间是用户的主战场**，AI 在右侧，不抢键盘
- 每个阶段可停、可回退、可跳过，但跳过会留下“未完成”标记
- 所有产出可导出，项目归用户所有

## 4. 六阶段逐阶段

### 01 需求

| 项 | 内容 |
|---|---|
| 用户做 | 写一句话；补验收标准；确认范围外 |
| AI 做 | 追问歧义（不限数量，每题有默认）；把标准改写为可测 |
| 产出 | `需求卡`（目标/受众/场景）+ `验收清单` |
| 门禁 | 验收标准 < 3 条时提示补充 |

### 02 设计

| 项 | 内容 |
|---|---|
| 用户做 | 划模块、定文件、写接口 |
| AI 做 | 覆盖检查（每条验收是否有模块负责）、循环依赖检查、命名建议 |
| 产出 | `模块清单` + `文件清单` + `依赖图` |

### 03 开发

| 项 | 内容 |
|---|---|
| 用户做 | **自己写代码**，可多文件 |
| AI 做 | 解释报错、指出坏味道、检查是否偏离验收、给修改建议 |
| 产出 | 代码文件 + `问题单` |
| 约束 | AI 不自动改文件；“应用建议”需用户点确认（二期） |

### 04 集成

| 项 | 内容 |
|---|---|
| 用户做 | 写入口、挂静态资源、配端口 |
| AI 做 | 检查入口/依赖/静态挂载；给出启动命令 |
| 产出 | 可启动骨架 |

### 05 测试

| 项 | 内容 |
|---|---|
| 用户做 | 写或用 AI 生成的用例；贴运行结果 |
| AI 做 | 从验收标准生成用例；解释失败原因；判断覆盖是否足够 |
| 产出 | 用例表 + 测试记录 |

### 06 交付

| 项 | 内容 |
|---|---|
| 用户做 | 过检查清单；确认风险 |
| AI 做 | 汇总未完成项、生成交付说明与风险清单 |
| 产出 | 交付报告 |

## 5. 代码能力（不做通用 IDE）

| 做 | 不做 |
|---|---|
| 粘贴 / 上传单文件 / 多文件 | 在线运行、终端 |
| 文件树、行号、只读高亮 | 补全、跳转定义、LSP |
| 静态检查（见下） | 全仓库索引、向量检索 |
| 问题单：待办/已修/忽略 | 通用代码问答 |

静态检查第一版（Python）：

| 检查 | 归到阶段 |
|---|---|
| 语法错误、导入缺失 | 03 开发 |
| 未使用导入、重复代码、函数过长 | 03 开发 |
| TODO / pass / 假数据残留 | 05 测试 |
| 硬编码密钥、`eval`、拼接 SQL | 03 开发 |
| 缺错误处理、缺依赖声明 | 04 集成 |
| 缺测试、缺 README | 06 交付 |

编辑区第一版用“高亮文本框”（零依赖，复用现有 `hl()`），是否引入编辑器库待定。

## 6. AI 记忆（个性化）

### 6.1 生命周期

```
一次辅助开发阶段结束
  → AI 自省：有什么值得长期记住？（0~3 条）
  → 去重、合并
  → 写库：内容 / 为什么记 / 来源 / 置信度
  → 下次进入辅助开发时，按相关度取 ≤5 条注入
```

AI 自主决定记什么，不强制分类（偏好、决策、风格都行）。

### 6.2 约束（只有三条）

1. 不记敏感信息：密钥、密码、完整代码只留摘要
2. 单次推断置信度低，重复出现才升级
3. 记忆只影响默认值与表达，不影响验收标准与事实

### 6.3 条数与作用域

- 每天最多 **3 条**（配置项 `MEMORY_DAILY_LIMIT`，默认 3，可改）
- 默认**全局**生效（跨项目）
- 只在辅助开发注入；工作流不读记忆

### 6.4 注入

```
system_prompt = 阶段提示词
              + "关于这位用户（来自历史记忆，仅作默认值参考）"
              + 最多 5 条记忆
              + "不要因偏好放宽验收标准"
```

界面上显示：`参考了 2 条记忆`，点开可看具体条目。

### 6.5 记忆页（头像菜单进入）

```
AI 记忆                                    [导出] [清空]
─────────────────────────────────────────────────────
11-11  3 条   今天它记住的
              ┌────────────────────────────────────┐
              │ 你偏好先看结论，再看原因             │
              │ 因为：连续 3 次要求“直接说重点”      │
              │ 来源：11-11 需求分析 · 门禁回答      │
              │ 置信度：多次验证     [置顶] [删除]   │
              └────────────────────────────────────┘
11-10  2 条   ...
─────────────────────────────────────────────────────
今天新增 3 条 · 本周引用 12 次 · 最近一次 10 分钟前
```

功能：按天时间线、来源可点、置顶、删除、导出、清空、显示被引用次数。

## 8. 接口草案

```
POST   /api/v2/assist/projects              创建辅助项目

GET    /api/v2/assist/projects/{id}         详情（阶段、文件、问题单）

PATCH  /api/v2/assist/findings/{id}         标已修/忽略

GET    /api/v2/memory                       记忆列表（按天）
POST   /api/v2/memory                       手动新增（可选）
PATCH  /api/v2/memory/{id}                  置顶/编辑
DELETE /api/v2/memory/{id}                  删除
DELETE /api/v2/memory                       清空
```

| 期 | 内容 | 验收 |
|---|---|---|
| P1 | 导航两个 tab；辅助项目创建；六阶段侧栏；需求卡 + 验收清单 | 能建项目、能存需求 |

- [ ] 顶栏有“工作流 / 辅助开发”两个 tab，切换正常

## 12. 风险

| 风险 | 应对 |
|---|---|
| 两个入口都做浅 | 先做 P1–P3，P4 视时间 |
| 记忆编造 | 无来源不入库；置信度分级 |
| 提示词膨胀 | 注入 ≤5 条、≤300 字 |
| 编辑器体验差 | 先用高亮文本框，确认后再引库 |
| 评委误解为通用 IDE | 页面文案强调“六阶段陪跑”，不强调编辑器 |

## 13. 已定决策

1. 导航用顶栏两个 tab（方案 A）
2. 记忆页放头像菜单，不做第三个 tab
3. 记忆默认全局
4. 记忆只作用于辅助开发；工作流保持纯模型能力
5. 每天最多 3 条，可配置
6. AI 自主决定记什么，只保留三条约束
7. 纯加功能，前后端能复用就复用
