# 五、工序详解（中）：并行开发（build）

> 这是动作最密集的一道，也是“像不像真的”最关键的一道。

## 1. 输入

```json
{ "spec": {...}, "arch": {...}, "workspace": "D:/nexus-workspace/<run_id>" }
```

## 2. 任务（= 模块，每个模块一条）

```json
{ "title": "写打卡接口", "kind": "code", "file": "api/main.py",
  "dependsOn": ["写打卡数据表"], "acceptance": "POST /api/checkin 幂等" }
```

并发默认 3；有依赖的等前驱完成。

## 3. 单个任务的执行循环（Agent 循环）

这是“自主性”的落点。**不是一次生成，而是 观察 → 行动 → 检查 的循环**：

```
attempt = 1
while attempt <= 2:
    prompt = build_prompt(module, spec, arch, error=last_error)
    result = model.structured(prompt, schema=FileContent)
    write_file(path, result.content)          # 工具
    ok, error = verify(module)                # 语法 / 导入 / 运行片段
    if ok: return success
    last_error = error
    attempt += 1
return fail(error)
```

`verify` 做什么：

| 模块 | 检查 |
|---|---|
| db | SQL 能建表（sqlite3 executescript） |
| api | `python -m py_compile` + import 成功 |
| web | 含 `<html` 与至少一个交互元素 |

## 4. 提示词（system）

```
你是后端/前端工程师，只写一个文件。

规则：
1. 只输出文件内容，不要 Markdown 代码围栏，不要解释。
2. 技术栈固定：Python 3.12 + sqlite3 + FastAPI（可选）+ 原生 HTML。
3. 文件必须自包含，不依赖本工程之外的模块。
4. 必须实现该模块 covers 的验收标准。
5. 如果给了“上次错误”，必须修掉它，不要重复同样的写法。
```

user 模板：

```
需求：{spec.goal}
验收标准：{spec.acceptance}
模块职责：{module.responsibility}
要实现的接口/页面：{module.contract}
文件路径：{file}
上次错误：{error or "无"}
```

## 5. 输出契约

```json
{ "path": "api/main.py", "content": "...", "notes": "用 sqlite3，端口 8000" }
```

校验：
- `content` 非空、≥ 200 字符
- 不含 ```` ``` ````
- 不含 “TODO”
- 语法通过（见上）

失败：重试 1 次（带错误）；仍失败 → `task.failed` + 进失败清单，**不阻塞其他模块**。

## 6. 流式写文件（file 事件）

为了代码像“打字”一样出现：

```python
for chunk in split(content, 400):
    emit(file(path, delta=chunk, done=False, lines=count))
emit(file(path, delta="", done=True, lines=total))
```

- 每块 ≤ 400 字符（约 80 汉字）
- 不切断 UTF-8 字符
- `replace=true` 只在修复时用

## 7. 并发与冲突

- 同一文件同一时间只允许一个任务写（`file_locks[path]`）
- 三个模块并行时，事件按实际完成顺序交错，前端已支持

## 8. 失败处理

| 失败 | 事件 | 后续 |
|---|---|---|
| 语法错 | `task.failed` + `error.detail` | 自动重试 1 次 |
| 模型空输出 | `task.failed` | 重试 1 次 |
| 两次都失败 | `task.failed`（attempts=2） | 记入 `failed_modules`，继续其他模块；装配时跳过该模块并在 `check` 标红 |

## 9. 成本

每次调用：

```python
cost = price(model, prompt_tokens, completion_tokens)
db.add(CostRecord(...)); emit(usage(...)); emit(cost(累计))
```

## 10. 事件序列（一个模块）

```
modules(batch)                       # 一次性告知本批有哪些模块（可选）
task(created, task-build-7f3a1c)
task(started, ...)
file(db/schema.sql, delta, ...) ×N
file(done=true)
task(done, ms=..., result={files:[...], lines:42})
usage / cost
```

## 11. 界面动作

- 第 3 张卡片“进行中”，副标“N 个任务并行”
- 任务节点随 `task.created` 逐个长出（不是一次三个）
- 写文件时：代码标签出现、逐行输出、行数增长
- 失败：节点标红、侧栏标红、点开看到真实错误
