## 1. 必须改的 4 个文件

### 1.1 `backend/app/features/runs/router.py`

| 位置 | 现状 | 改成 |
|---|---|---|
| `create_run` 末尾 | `demo.mark_pace(...)` + `demo.start(...)` | 按 `PIPELINE` 分支：real → `orchestrator.start()`；demo → 原逻辑 |
| `resume_run` | `demo.start(run_id)` | 同样分支 |
| `cancel_run` | 只改状态 | 追加 `orchestrator.stop(run_id)` |
| 新增 | — | `POST /{id}/rewind`、`POST /{id}/retry-stage` |

伪代码：

```python
pipeline = settings.pipeline            # real | demo

@router.post("", status_code=201)
def create_run(...):
    run = service.create(...)
    if pipeline == "demo":
        demo.mark_pace(run.id, fast=fast)
        demo.start(run.id)
    else:
        orchestrator.start(run.id)
    return run_to_dict(run)
```

验证：`PIPELINE=demo` 行为与现在完全一致（回归截图）；`PIPELINE=real` 走新链路。

### 1.2 `backend/app/config.py`

```python
pipeline: str = "demo"          # real | demo
```

验证：`python -c "from app.config import get_settings; print(get_settings().pipeline)"`。

## 2. 新增代码与现有模块的关系

```
features/runs/router.py  ──调用──▶  pipeline/orchestrator
                                        │
                                        ├─▶ ai/model/client ──▶ DeepSeek
                                        ├─▶ ai/cost/ledger ──▶ cost_records
                                        ├─▶ pipeline/stages/* ──▶ tools
                                        └─▶ features/runtime ──▶ 进程
```

**依赖方向**：`features → pipeline → ai → domain`，符合现有 import-linter 规则。
`orchestrator` 不 import `features`；运行时通过 `features/runtime/service` 的纯函数接口，或把进程启动下沉到 `tools/preview`。
