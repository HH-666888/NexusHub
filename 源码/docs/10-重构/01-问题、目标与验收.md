# 一、问题、目标与验收

## 1. 为什么现在“像原型”

不是因为界面不好，而是因为**内容不是从需求推出来的**。七处接缝：

| # | 接缝 | 位置 | 后果 |
|---|---|---|---|
| 1 | 三套模板按关键词选 | `pipeline/demo.py` 的 `_FINANCE/_TODO/_POMODORO` | 换个需求就退回番茄钟，评委一试就穿 |
| 2 | 建运行即起演示线程 | `runs/router.py` `demo.start(run.id)` | 没有“编排器”这一层，无法插入真实决策 |
| 3 | 任务 id 写死 | `t-plan-1`、`t-build-db` | 任务不随需求变化，树是“摆”出来的 |
| 4 | 成本写死 | `_add_cost(0.02/0.03/0.09)` | 成本面板是装饰 |
| 5 | 成本表从不写入 | `cost_records` 只有模型 | “每一分钱”无从查起 |
| 6 | 验收结论写死 | `layers = [...3/3]` | 永远通过，测试是演的 |
| 7 | 模型设置没人读 | `modelDecide/modelBuild` 零引用 | “按阶段选模型”是空话 |

**结论：界面、事件、数据库都是真的，唯独“内容生产”是一个 if/else。** 在假根上加功能，只会越来越乱。

## 2. 目标

> 用户输入一句话 → 点开始 → 系统真的理解这句话 → 真的规划出任务 → 真的写代码 → 真的跑起来 → 真的测试 → 交付一个能运行的软件。全过程每个节点都有真实来源，可回放、可追查、可花费归因。

## 3. “真实”的六级定义（验收用）

### L1 需求真实
- 输入：任意一句话（不是预设关键词）
- 输出：`AppSpec`，包含 goal / audience / scenarios / acceptance[] / out_of_scope[]
- 判定：换一个没见过的需求，`acceptance` 的内容随之变化，不能是固定五条

### L2 任务真实
- 任务由规划器根据 spec 生成，`task.id` 动态（如 `task-<hash8>`）
- 每道工序的任务数量可以不同（需求简单就 1 条，复杂就 4 条）
- 判定：两个不同需求，任务树结构不同

### L3 代码真实
- 代码由模型生成，写入 `workspace/<run_id>/`
- 文件清单来自架构设计，不是固定三个文件
- 判定：`grep` 生成物里出现需求中的名词（如“打卡”“投票”）

### L4 运行真实
- 产物能起进程，端口可访问，页面能点
- 判定：`curl` 返回 200；数据库文件被创建

### L5 测试真实
- 测试用例来自 spec 的 acceptance
- 真发 HTTP 请求 / 真查库；失败就是失败
- 判定：故意写坏一处，测试必须红

### L6 成本真实
- 每次模型调用写一条 `cost_records`，金额由 `usage` 与单价算
- 判定：一次运行的 `cost_records` 之和 = `runs.total_cost_cny`

## 3.5 内容真实性红线

v2 不允许任何“看起来像真的假数据”：假统计、假状态、假代码、假成本、假时间、死控件、演示分支。
没数据时用典型占位符（`—` / `暂无` / `加载中…` / 空态文案），不得伪造。
详见 `20-内容真实性红线.md`。

## 4. 非目标（明确不做）

- 不做通用助手、不做多模态生成（截图/语音本轮不做）
- 不追求任意技术栈：先锁定 **Python + SQLite + 原生 HTML**（产物形态）
- 不做多租户隔离、不做权限体系（沿用现有单用户会话）
- 不做分布式：单进程即可

## 5. 验收场景（三个“没见过的需求”）

| # | 需求 | 期望产物 | 关键证据 |
|---|---|---|---|
| A | 习惯打卡：能每天打卡、看连续天数 | `habits` 表 + 打卡接口 + 页面 | 连续天数计算正确；连点两次不重复计 |
| B | 投票：发起一个投票、投一票、看结果 | `polls/votes` 表 + 投票接口 + 页面 | 一人一票；结果百分比正确 |
| C | 记账（带分类）：记一笔、按分类汇总 | `entries` 表 + 分类汇总接口 + 页面 | 分类合计等于总额 |

每个场景跑完必须满足：

```
6/6 道完成
产物文件 ≥ 3 个
测试用例全部来自该需求的验收标准
cost_records 条数 = 模型调用次数
预览地址可打开，页面可操作
```

## 6. 与现有系统的边界

| 层 | 处理 |
|---|---|
| 前端页面 | 复用，只加门禁弹窗、证据卡字段、任务定位 |
| 事件协议 | 复用，新增字段向后兼容 |
| 数据库 | 12 张表不动 |
| 接口 | 复用；新增 `/runs/{id}/gate` 的前端消费（接口已存在） |
| 演示流水线 | 保留为 `PIPELINE=demo` 兜底，不删除 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 模型输出不合规 | 结构化输出 + 校验 + 重试 1 次 + 降级 |
| 生成代码跑不起来 | 装配后先 `py_compile`，失败回退到模块修复 |
| 演示现场无网 | 录制回放：事件 + 产物快照 |
| 模型慢导致演示卡住 | 事件流实时展示，允许暂停/取消；单阶段超时 |
| 成本超预算 | 开跑前闸门 + 每阶段检查 + 到顶暂停 |
