# 前后端分离契约书

> 版本 v1.0 · 2026-11-01
> 状态：**目标态（binding）**。文中凡标「现状」的条目是迁移前的行为，迁移完成后以本契约为准。
> 效力：这是前后端唯一的接口事实来源。**代码与本文件冲突时，以本文件为准；要改契约先改本文件**，再动代码。

---

## 0. 一句话

浏览器只与 Next.js（React 19）同源通信；Next.js 只渲染与代理，**不持有任何业务状态**；所有运行状态、事件、成本、产物、鉴权真相都在 FastAPI + 数据库侧。

```
浏览器 ──(同源 HTTPS)── Next.js ──(内网 HTTP, /api/* rewrite)── FastAPI ── DB / 向量库 / MCP / 模型
         EventSource                                    SSE 唯一出口
```

---

## 1. 五条总则（任何实现细节都不得违反）

| # | 总则 | 含义 |
|---|---|---|
| R1 | **单一真相源** | 运行状态、事件、成本、产物、会话，只有数据库是真相。前端与服务端内存都不得成为第二份真相。 |
| R2 | **同源** | 浏览器只看到 Next 一个源。跨服务通信靠 `rewrite`，**不引入 CORS、不引入第二域名的 cookie**。 |
| R3 | **契约生成** | 后端 Pydantic 模型是唯一来源，TS 类型由 OpenAPI 生成。**禁止手写第二份类型**。 |
| R4 | **JSON 一律 camelCase** | 后端用 Pydantic alias 输出 camelCase，与现有前端字段保持一致（`runId`、`costCny`、`createdAt`）。数据库列名可以是 snake_case，**JSON 不是**。 |
| R5 | **视图状态放 URL** | `?run=`、`?focus=`、`?new=1` 是唯一的界面状态来源。前端不得把"选中的运行"存进 localStorage 或全局 store。 |

## 2. 职责矩阵（这是最容易做错的部分）

### 2.1 归属表

| 能力 | 归属 | 说明 |
|---|---|---|
| 页面、路由、布局、组件渲染 | **前端** | `app/`、`components/` |
| 画布几何：布局、视口、缩放、聚焦跟随、森林排布 | **前端** | `core/canvas/*`（约 842 行纯函数）。**搬走即毁掉交互手感** |
| 动画时序（进出场、连线、聚焦过渡） | **前端** | 依赖 rAF 与本地几何，过网络就废 |
| 客户端事件流渲染（思考/正文/检查逐段追加） | **前端** | 只消费 SSE，不做业务判断 |
| 表单校验的即时反馈（仅限"空/超长"这类本地规则） | **前端** | 与后端校验重复时，**以后端为准** |
| 主题/外观的 CSS 变量应用 | **前端** | 配置内容来自后端 `GET /settings` |
| 鉴权（会话签发、校验、过期） | **后端** | Next 只透传 cookie |
| 密码哈希、登录失败限流 | **后端** | |
| 运行状态机（spec→arch→ui→build→verify） | **后端** | 前端只读 `stage`/`status` |
| 门禁判定（要不要停、停在哪、问什么） | **后端** | 前端只渲染 `GET /gate` 的结果 |
| Prompt 拼装、模型调用、截断重试、回流上下文 | **后端** | |
| 并行构建调度、并发上限、失败汇总 | **后端** | |
| 产物检查（8 项检查与探针） | **后端** | |
| 成本记账、预算闸门、单价档位 | **后端** | |
| 产物落盘、CSP 预览、导出/导入包 | **后端** | |
| RAG 检索、Agent 编排、工具调用、MCP 客户端 | **后端** | |
| 事件投影（outline / 画布节点数据） | **后端** | 前端拿到的是"该画什么"，不是"原始事件" |

### 2.2 一条判定规则

> **需要"多次读库/多次调用模型"才能算出来的，归后端；只依赖一次响应的纯计算与绘制，归前端。**

依据这条规则：`core/canvas`（纯计算、单次）留前端；`core/planning`（投影、需读事件）去后端；`core/domain` 的**类型**两边都有名字，但**定义权在后端**（见 §9）。

### 2.3 现状 → 目标 的路径映射

| 现状（Next 内） | 目标位置 | 动作 |
|---|---|---|
| `src/app/api/runs/[id]/generate/route.ts`（SSE + 生成编排） | `backend/app/api/runs.py` + `backend/app/pipeline/*` | 迁移 |
| `src/app/api/runs/[id]/{answers,acknowledge,gate,events,artifact,export}` | 同名，加 `/api/v1` 前缀 | 迁移 |
| `src/app/api/runs/import/route.ts` | `backend/app/api/runs.py` | 迁移 |
| `src/app/actions/{auth,run,settings}.ts`（Server Action） | 后端 API + 前端调用 | 改造 |
| `src/core/{pipeline,generate,planning,domain,run,settings,auth}` | `backend/app/**` | 迁移 |
| `src/adapters/**`（Drizzle/SQLite/模型） | `backend/app/adapters/**`（SQLAlchemy / Pydantic） | 重写 |
| `src/core/canvas/**` | **留在 `frontend/src/core/canvas`** | 不动 |
| `src/components/**` | `frontend/src/components/**` | 不动 |
| `next.config.ts` 的 rewrite | 新增 `/api/:path*` → `http://127.0.0.1:8000/api/:path*` | 新增 |

## 3. 部署与同源规则

1. 浏览器只访问 `https://<域名>`（Next）。**FastAPI 不直接对外暴露**，仅监听 `127.0.0.1:8000`。
2. `next.config.ts` 里：

```ts
async rewrites() {
  return [{ source: "/api/:path*", destination: `${process.env.BACKEND_URL}/api/:path*` }];
}
```

3. `BACKEND_URL` 只走环境变量，默认 `http://127.0.0.1:8000`。
4. 两个进程由同一份 `docker-compose.yml` 拉起；`/api/v1/health` 用于就绪探针。
5. **SSE 必须直通**：rewrite 不得缓存、不得压缩（见 §6.2）。

## 4. 请求总则

### 4.1 认证

| 项 | 规则 |
|---|---|
| 机制 | HttpOnly cookie，名 `nexus_session`，值为不透明随机串 |
| 属性 | `Path=/; HttpOnly; SameSite=Lax; Secure`（本地开发可去 `Secure`） |
| 有效期 | 7 天，服务端存哈希，**不在 cookie 里放用户信息** |
| 校验 | 每个 `/api/v1/**`（除 `auth/*`、`health`）都要校验；失败返回 **401** |
| 归属 | 资源不属于当前用户时返回 **404**（不泄露 id 是否存在） |

### 4.2 错误信封

所有非 2xx 响应统一为：

```json
{ "error": { "code": "UNAUTHORIZED", "message": "未登录", "hint": "请先登录" } }
```

| HTTP | code | 场景 |
|---|---|---|
| 400 | `BAD_REQUEST` | 请求体不是合法 JSON、字段缺失 |
| 401 | `UNAUTHORIZED` | 无会话/会话过期 |
| 404 | `NOT_FOUND` | 运行不存在，或不属于当前用户 |
| 409 | `CONFLICT` | 状态不允许（例如没有规格就提交回答、重复确认） |
| 410 | `GONE` | 登记还在但文件丢失（产物不一致） |
| 413 | `TOO_LARGE` | 导入包超限 |
| 422 | `VALIDATION_FAILED` | 字段格式不对（`details` 里给逐条原因） |
| 429 | `RATE_LIMITED` | 登录/生成触发限流 |
| 500 | `INTERNAL` | 未预期错误，**不返回堆栈** |
| 502 | `UPSTREAM` | 模型侧失败（超时/限流/500） |

`message` 用中文给用户看，`code` 给程序判断。**前端不得按 `message` 做分支。**

### 4.3 数据类型约定

| 类型 | 规则 |
|---|---|
| 时间 | **毫秒时间戳整数**（`createdAt: 1730000000000`），UTC 语义，前端自己格式化 |
| 金额 | 元，`number`，最多 6 位小数（`costCny: 0.001234`）；**不传字符串** |
| ID | 运行 id 为 26 位以内的小写串；用户 id 为整数 |
| 枚举 | 小写下划线（`offPeak` 例外：保持现有 camelCase）——新增枚举一律小写 |
| 空值 | 缺省字段**不出现**，不要传 `null`；确实要表达"空"用 `null` 并写明含义 |
| 数组 | 无数据传 `[]`，不传 `null` |

### 4.4 幂等与并发

| 接口 | 规则 |
|---|---|
| `POST /runs` | 不幂等，但相同 `Idempotency-Key` 头 30s 内复用同一结果（防连点建出两条运行） |
| `GET /runs/{id}/stream` | **幂等**：已有产物直接回放，不重复计费 |
| `POST /runs/{id}/answers` | 幂等：同一 run 重复提交同一份答案不重复计费 |
| `POST /runs/{id}/acknowledge` | 幂等：重复确认返回 200 |
| `DELETE /runs/{id}/artifacts` | 幂等：没有产物时也返回 200 |

### 4.5 大小与超限

| 项 | 上限 |
|---|---|
| 请求体（JSON） | 1 MB |
| 导入包 | 20 MB |
| 单条事件 `delta` | 64 KB |
| SSE 单帧 | 256 KB |

## 6. SSE 契约

### 6.1 帧格式

```
data: {"kind":"text","delta":"<div"}\n\n
```

- **只用 `data:` 行，不设 `event:` 名** —— 事件类型在 `payload.kind`。理由：与现有实现一致，且前端一个 `onmessage` 就能接全部分支。
- 一帧一个 JSON 对象，**不得**把多个事件塞进一帧。
- 心跳：服务端每 15 秒发一个注释帧 `: ping\n\n`（浏览器不会触发 `onmessage`，但能保活）。

### 6.2 响应头

```
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache, no-store, no-transform
Connection: keep-alive
X-Accel-Buffering: no
```

`no-transform` 与 `X-Accel-Buffering: no` 都必须有 —— 任一层压缩或缓冲，用户看到的就是"卡住不动的流"。

### 6.3 生命周期

| 场景 | 行为 |
|---|---|
| 首次请求 | 从规格化开始跑；每产出一个事件立即 flush |
| 已完成的 run（有 html 产物） | **回放**：只发已有事件与 artifact，不调用模型、不计费 |
| 断点续跑（有 spec/arch/ui 产物但没跑完） | 复用已有产物，只跑缺的部分 |
| 门禁暂停 | 发 `phase(awaiting)` 后**关闭连接**，前端转为渲染 `GateView` |
| 完成 | 发 `artifact`（如有）与 `phase(done)` 后关闭 |
| 出错 | 发 `error` 后关闭，HTTP 状态仍是 200（流已开始） |

### 6.4 事件顺序（偏序，不是全序）

契约只保证这些**必须成立**的关系，其余顺序不作承诺：

1. `spec` 一定在第一个 `phase(spec)` 之后
2. `arch` 在 `spec` 之后，`ui` 在 `arch` 之后
3. `modules` 一定在 `phase(build)` 之后、`artifact` 之前
4. `usage` 与它所属的那次模型调用相邻（同一阶段内）
5. 最后一个事件一定是 `phase(done)` 或 `error`
6. 任何 `reasoning`/`text` 片段都不得跨越 `phase` 边界

前端**不得**依赖 "ts 严格递增" 以外的时序假设。

### 6.5 重连

浏览器 `EventSource` 自带重连。重连即重新 `GET /stream`，服务端按 §6.3 判定是回放还是续跑，**不会重复计费**。前端不得自行实现重连退避。

## 7. 事件清单

`kind` 是判别字段。下表 Status 列：`现状`=已实现，`计划`=契约已定、实现待做。

| kind | Status | 字段 |
|---|---|---|
| `phase` | 现状 | `phase: string`、`label: string`、`note?: "callback"` |
| `reasoning` | 现状 | `delta: string` |
| `text` | 现状 | `delta: string` |
| `spec` | 现状 | `spec: AppSpec`、`gate: SpecGate`、`fallback: boolean` |
| `arch` | 现状 | `arch: ArchSpec`、`check: ArchCheck`、`fallback: boolean` |
| `ui` | 现状 | `ui: UiSpec`、`check: UiCheck`、`fallback: boolean` |
| `modules` | 现状 | `batch: BuildBatchSummary`（**摘要，不含代码**） |
| `usage` | 现状 | `usage: TokenUsage`、`costCny: number`、`priceTier`、`model`、`latencyMs`、`truncated` |
| `check` | 现状 | `results: CheckResult[]`、`summary: CheckSummary` |
| `artifact` | 现状 | `artifact: Artifact` |
| `error` | 现状 | `message: string`、`hint?: string` |
| `tool` | 计划 | `name: string`、`args: object`、`result?: string`、`ok: boolean`、`latencyMs: number` |
| `retrieval` | 计划 | `query: string`、`hits: [{ source: string, snippet: string, score: number }]`、`latencyMs` |
| `cost` | 计划 | `stage: string`、`deltaCny: number`、`totalCny: number` |

三条硬规则：

1. **新增 kind 必须先改本文件**，前端遇到未知 kind 必须**忽略而不是崩溃**。
2. `phase` 的 `label` 是给人看的中文，**前端不得按 label 文本判断阶段**，判断一律用 `phase` 字段。
3. 事件里只放**可展示数据**，不放密钥、不放完整源码（代码走产物）。

## 8. 领域模型（关键字段）

> 完整字段以 `backend/app/models/*.py` 的 Pydantic 模型为准；本节列出**跨端共享**的部分，用于人工核对。

### 8.1 Run

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 运行 id |
| `prompt` | string | 用户原话，一字不改 |
| `stage` | enum | `spec`/`arch`/`ui`/`build`/`assemble`/`verify` |
| `status` | enum | `running`/`paused`/`done`/`failed`/`cancelled` |
| `totalCostCny` | number | 累计花费（元） |
| `usage` | TokenUsage | 累计 token |
| `createdAt`/`updatedAt` | int | epoch ms |
| `workflowVersion` | string | `v1` |

> **`paused` 与 `awaiting` 不是一回事**：`paused` 是运行状态（门禁停下、等用户回答）；`awaiting` 只是 SSE 的一个 `phase` 值。前端判断"要不要显示门禁表单"看 `status === "paused"`，**不要**看 phase。

单道工序（stage）另有自己的状态：`pending` / `running` / `passed`，与运行的 `status` 无关，不得混用。

### 8.2 AppSpec

| 字段 | 类型 |
|---|---|
| `prompt` | string（原话） |
| `goal` | string |
| `audience` | string |
| `scenarios` | string[]（按重要性排序） |
| `acceptance` | `{ id, text, kind }[]` |
| `scope` | `{ inScope: string[], outOfScope: string[] }` |
| `questions` | string[]（非空时门禁触发） |
| `model`/`generatedAt` | string / int |

### 8.3 Artifact / CostRecord

| 模型 | 字段 |
|---|---|
| `Artifact` | `id: number`、`runId: string`、`kind: "html"\|"json"`、`path: string`、`bytes: number`、`createdAt: int` |
| `CostRecord` | `runId`、`stage`、`model`、`inputTokens`、`outputTokens`、`cacheHitTokens`、`costCny`、`priceTier`、`latencyMs`、`createdAt` |

### 8.4 TokenUsage

`{ input: number, output: number, thinking: number, cached?: number }`
—— **thinking 计入 output 预算**，这条是全局不变量，前后端都不得改写含义。

### 8.5 GateView

```json
{
  "runId": "…",
  "status": "paused",
  "hasSpec": true,
  "spec": { "goal": "…", "audience": "…", "acceptance": [], "outOfScope": [], "questions": ["…"] },
  "gate": {
    "active": true,
    "pending": ["问题 1"],
    "answered": [{ "question": "问题 1", "answer": "…" }],
    "acknowledged": false,
    "overrideNote": null
  }
}
```

`hasSpec: false` 时 `spec` 与 `gate` 都为 `null`（运行还没跑到规格化）。**前端必须处理这个分支**，不能假定 spec 一定存在。

## 9. 类型生成与 CI 门禁

1. 后端 Pydantic 模型 → `GET /openapi.json`。
2. 前端执行 `pnpm gen:types` → `frontend/src/api/schema.d.ts`（`openapi-typescript` 生成）。
3. **禁止手写**与后端重复的 interface；前端只能 import 生成的类型。
4. CI 门禁（三条，缺一不可）：
   - `pnpm gen:types && git diff --exit-code frontend/src/api/schema.d.ts`（生成物必须与提交一致）
   - 后端 `pytest` 里有 OpenAPI 快照测试：字段删改即红
   - 前端 `tsc --noEmit`

**理由**：双语言项目里唯一会致命的是契约漂移。这条不做，"规格改了但事件没改"一定会重演。

## 10. 禁止清单

### 前端不得

1. 直连模型 API，或持有任何密钥（含 `NEXT_PUBLIC_*` 形式的密钥）
2. 自行推断运行阶段/门禁状态（只能读 `stage`、`status`、`GateView`）
3. 把运行状态写进 localStorage / 全局 store 当缓存（URL 是唯一视图状态）
4. 按 `error.message` 文本做分支（只能按 `error.code`）
5. 依赖文档未承诺的事件顺序（见 §6.4）
6. 在客户端做"是否需要门禁"这类业务判断

### 后端不得

1. 返回 HTML 片段给 React 渲染（除产物预览本身）
2. 依赖前端传来的派生数据（例如前端算好的 outline）
3. 在 SSE 里返回未在 §7 登记的事件类型
4. 返回堆栈、SQL、内部路径
5. 把 `timeLabel` 这类展示用的相对时间交给前端算（服务端是时间权威）
6. 直接信任 `answers[].question` 的内容与顺序 —— 一律以服务端 `pending` 为准，做子集校验

## 12. 变更流程

1. 改契约 → 先改本文件（含版本号与日期）→ 再改 Pydantic → 重新生成 TS → 跑门禁。
2. **字段只增不删**。要删：先标 `deprecated`（至少一个版本周期），两个端都不再读写后才删。
3. 新增 `kind` / 新增枚举值属于**向后兼容**；前端必须容忍未知值。
4. 破坏性变更（改字段含义、改路径）必须写进本文档的「变更记录」并同步 e2e。
