# 目录结构规定

> 版本 v3.0 · 2026-11-17（前端已迁移到 Vue 3 + Vite，构建产物由 FastAPI 托管）
> 配套文档：[`03-前后端分离契约书.md`](./03-前后端分离契约书.md)（接口、事件、数据层）
> 本文件管**代码放哪、谁能依赖谁**；契约书管**接口长什么样**。两者冲突时：接口以 03 为准，位置以 04 为准。

---

## 声明

1. **本文件是目录与依赖的唯一规定。** 新建文件前先在这里找到它的位置；找不到位置，说明这个文件不该存在，或者需要先改本文件。
2. **改动流程**：先改本文件（含版本号）→ 再动目录 → 再改代码。
3. **三条不可协商的铁律**：
   - **目录即契约**：工序 id 固定为 `plan / design / build / assemble / test / deliver`。
   - **依赖单向**：`api → pipeline → ai → domain`，反向 import 一律视为 bug。
   - **单一前端源码**：`web-vue/` 是唯一前端源码；`web/` 只放构建产物与旧静态兼容页，不再新增页面。
4. 本文件不定义接口细节。请求体、响应体、错误码、SSE 帧、事件字段，全部看契约书。

## 2. 前端结构（web-vue/）

```
web-vue/
├─ src/
│  ├─ main.ts                入口
│  ├─ theme.ts               主题与设计令牌
│  ├─ login/ register/ projects/ settings/ memory/
│  │                        每页一个目录：main.ts + *App.vue
│  ├─ welcome/               WelcomeApp.vue + welcome-long.ts
│  ├─ assist/                AssistApp.vue（辅助项目列表）
│  ├─ workspace/             辅助工作台
│  │  ├─ WorkspaceApp.vue
│  │  ├─ useWorkspace.ts
│  │  └─ components/         StageRail / PlanStage / CodeStage /
│  │                         CodeEditor / TestsPanel / DeliverPanel /
│  │                         FindingsPanel / CoachPanel
│  ├─ workbench/             主工作台
│  │  ├─ WorkbenchApp.vue
│  │  ├─ useWorkbenchStore/Tree/Run/Ui.ts
│  │  ├─ workbenchModel.ts / highlight.ts
│  │  └─ components/         TaskPanel / TaskDetail / CanvasPanel /
│  │                         CodePane / StatusBar / GateModal /
│  │                         MainAgentDialog
│  ├─ components/            SettingsApp 等共享业务组件
│  └─ types/                 api.ts / workbench-engine.ts / codemirror.d.ts
├─ package.json
├─ tsconfig.json             strict: true
└─ vite.config.js            多页面入口，输出到 ../web/vue-dist
```

### 前端规则

1. **一个页面一个目录**，页面私有组件与状态放在同目录，不塞进 `components/`。
2. **共享组件只在 `components/`**；跨页面复用的类型放 `types/`。
3. **状态分层**：主工作台用 `useWorkbenchStore`（数据）、`useWorkbenchRun`（SSE）、`useWorkbenchTree`（树布局纯函数）、`useWorkbenchUi`（界面状态）；辅助工作台集中在 `useWorkspace`。
4. **不改成 SPA**：保持多页面入口与现有 URL，FastAPI 按目录托管。
5. **构建产物由 FastAPI 托管**：`web/vue-dist` 缺失时自动回退到 `web/` 原静态页。
6. **类型检查是闸门**：`vue-tsc --noEmit` 必须零错误；允许增量 JS（`engine/tree.js`、欢迎页脚本），但不把 JS 改后缀冒充全量类型化。

## 3. 后端结构（backend/）

```
backend/
├─ app/
│  ├─ main.py                创建应用、挂路由、托管前端、缓存策略
│  ├─ config.py              环境变量（.env）
│  ├─ deps.py                依赖注入（会话、当前用户）
│  ├─ api/                   路由与业务接口
│  │  ├─ auth（features/auth）· runs · gate · memory · assist
│  │  ├─ rag · skills · usage · settings（features/settings）
│  │  ├─ agent/              辅助 Agent 工具循环与工具集
│  │  ├─ pipeline/           六道工序编排、阶段上下文、门禁、录制回放
│  │  ├─ runtime/            产物进程启动、端口、健康检查、回收
│  │  ├─ ai/                 模型客户端、结构化输出、成本、RAG
│  │  └─ tools/              文件读写等内部工具
│  ├─ domain/                纯 Pydantic 契约（spec / arch / ui / event / check / cost）
│  ├─ db/                    引擎、会话、SQLAlchemy 模型
│  ├─ ai/rag/                切块、向量、检索
│  ├─ shared/                时间、错误、密码、SSE、分页
│  └─ features/auth|settings 路由 + service + repo + schemas
├─ migrations/               Alembic
├─ tests/                    单元 + 集成
└─ data/workspace/           产物工作区（运行时生成）
```

### 每个目录"放什么 / 不放什么"

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `domain/` | 纯数据模型与业务规则 | 数据库、HTTP、框架代码 |
| `api/<功能>/` | 该功能的 `router.py` + `service.py` + `repo.py` | 跨功能的业务逻辑 |
| `api/pipeline/` | 工序编排、事件生成、门禁 | HTTP 路由、SQL |
| `api/ai/` | 模型客户端、成本、检索 | 业务状态 |
| `shared/` | 时间、错误、密码、SSE | 业务模型 |

## 4. 依赖方向

```
api → pipeline → ai → domain
        ↘ shared
db / config 被以上各层使用，但不能反向依赖 api
```

### 五条硬规则

1. `domain` 不 import 任何其它层。
2. `pipeline` 不 import `api`（编排不能依赖 HTTP）。
3. 功能模块之间不互相 import，公共逻辑下沉到 `shared` 或 `domain`。
4. 前端只通过 `/api/*` 通信，**不 import 后端代码**。
5. 事件格式只在 `app/domain/event.py` 定义一次，前端按 `kind` 消费。

### 自动检查

```powershell
cd 源码\backend
pytest -m "not integration"   # 单元测试
ruff check .                  # 规范
lint-imports                  # 依赖方向（import-linter）
```

## 5. 命名与粒度

| 对象 | 规则 | 例 |
|---|---|---|
| 页面目录 | 小写单词 | `workbench/`、`projects/` |
| Python 模块 | 小写下划线 | `run_service.py` |
| 事件 kind | 小写单词 | `phase`、`task`、`file`、`verdict` |
| 工序 id | 固定六个 | `plan / design / build / assemble / test / deliver` |
| 任务 id | `<道>-<序号>` | `t-build-api`、`t-test-2` |

## 7. 反例清单（明确不要做）

- ❌ 在 HTML 里写内联 `<style>` / `<script>`（除极小的主题引导）
- ❌ 页面直接 `fetch("/api/...")`，绕过统一取数出口
- ❌ 在 `domain/` 里 import SQLAlchemy
- ❌ 功能模块之间互相 import
- ❌ 新增目录 `utils/`、`helpers/`、`misc/`
- ❌ 在 `web/` 里新增页面而不改 `web-vue/`
- ❌ 把运行时产物（`data/workspace/*`）提交进仓库
