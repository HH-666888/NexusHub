# 目录结构规定

> 版本 v2.0 · 2026-11-08（Next.js 前端已废弃，改为 `web/` 静态站 + FastAPI）
> 配套文档：[`03-前后端分离契约书.md`](./03-前后端分离契约书.md)（接口、事件、数据层）
> 本文件管**代码放哪、谁能依赖谁**；契约书管**接口长什么样**。两者冲突时：接口以 03 为准，位置以 04 为准。

---

## 声明

1. **本文件是目录与依赖的唯一规定。** 新建文件前先在这里找到它的位置；找不到位置，说明这个文件不该存在，或者需要先改本文件。
2. **改动流程**：先改本文件（含版本号）→ 再动目录 → 再改代码。
3. **三条不可协商的铁律**：
   - **目录即契约**：目录名必须能对得上六道工序（`plan / design / build / assemble / test / deliver`）。
   - **依赖单向**：`features → pipeline → ai → domain`，反向 import 一律视为 bug。
   - **前端不引第三方库**：`web/` 只用原生 HTML/CSS/JS，不装框架、不引 CDN。
4. 本文件不定义接口细节。请求体、响应体、错误码、SSE 帧、事件字段，全部看契约书。

## 2. 前端结构（web/）

```
web/
├─ index.html                入口：已登录 → /projects/，未登录 → /welcome/
├─ common/                   跨页面复用的东西
│  ├─ app.css                设计令牌（颜色/间距/圆角/阴影）+ 通用组件
│  ├─ glass.css              玻璃态外观，只在 ?style=glass 时启用
│  ├─ auth.css               登录/注册两页共用
│  ├─ api.js                 唯一的 fetch 出口；返回 { ok, data, offline }
│  └─ demo.js                没有后端时的本地演示（localStorage）
├─ <page>/                   一个页面一个目录
│  ├─ index.html
│  ├─ style.css              页面私有样式（可选）
│  └─ main.js                页面私有脚本（必须最后加载）
└─ shots/                    截图，按迭代编号
```

### 前端的四条规则

1. **一个页面一个目录**，页面私有样式与脚本放在同目录，不内联、不塞 `common/`。
2. **共享资源只在 `common/`**，页面用 `../common/xxx.css?v=版本` 引用。
3. **脚本顺序**：依赖（`api.js`）在前，`main.js` 最后；`main.js` 里直接调用 `window.api`。
4. **带版本号**：`?v=YYYYMMDDx`。改完样式或脚本必须换版本号，否则浏览器用旧的。

## 3. 后端结构（backend/）

```
backend/
├─ app/
│  ├─ main.py                创建应用、挂路由、托管 web/、缓存策略
│  ├─ config.py              环境变量（.env）
│  ├─ db/                    引擎、会话、模型
│  ├─ domain/                纯领域模型（Pydantic），不依赖框架
│  ├─ features/              按功能切：auth / runs / settings / stream / gate / artifacts / runtime
│  ├─ pipeline/              六道工序与事件发生器（demo.py 是演示实现）
│  ├─ ai/                    模型调用、成本、语料（骨架）
│  └─ shared/                时间、错误、密码等基础设施
├─ migrations/               Alembic
├─ scripts/                  运维脚本
├─ tests/                    测试
└─ data/workspace/           产物工作区（运行时生成）
```

### 后端每个目录"放什么 / 不放什么"

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `domain/` | 纯数据模型与业务规则 | 数据库、HTTP、框架代码 |
| `features/<名>/` | 该功能的 `router.py` + `service.py` + `repo.py` | 跨功能的业务逻辑 |
| `pipeline/` | 工序编排、事件生成 | HTTP 路由、SQL |
| `ai/` | 模型客户端、成本、检索 | 业务状态 |
| `shared/` | 时间、错误、密码 | 业务模型 |

---

## 4. 依赖方向

```
features → pipeline → ai → domain
                    ↘ shared
db / config 被以上各层使用，但不能反向依赖 features
```

### 五条硬规则

1. `domain` 不 import 任何其它层。
2. `pipeline` 不 import `features`（编排不能依赖 HTTP）。
3. `features` 之间不互相 import，公共逻辑下沉到 `shared` 或 `domain`。
4. 前端只通过 `/api/v1/*` 通信，**不 import 后端代码**。
5. 事件格式只在 `app/domain/event.py` 定义一次，前端按 `kind` 消费。

### 自动检查

```powershell
cd 源码\backend
pytest -m "not integration"   # 单元测试
ruff check .                  # 规范
lint-imports                  # 依赖方向（import-linter）
```

## 5. 命名与粒度

| 对象 | 规则 | 例 |
|---|---|---|
| 页面目录 | 小写单词 | `workbench/`、`projects/` |
| Python 模块 | 小写下划线 | `run_service.py` |
| 事件 kind | 小写单词 | `phase`、`task`、`file`、`verdict` |
| 工序 id | 固定六个 | `plan / design / build / assemble / test / deliver` |
| 任务 id | `<道>-<序号>` | `t-build-api`、`t-test-2` |

## 6. 测试与脚本

| 位置 | 放什么 |
|---|---|
| `backend/tests/unit/` | 领域模型、事件、密码规则 |
| `backend/tests/integration/` | 需要 MySQL 的接口测试 |
| `backend/scripts/` | 一次性的运维脚本（种子、修复） |
| `tools/` | 与后端无关的本地工具（截图） |

## 7. 反例清单（明确不要做）

- ❌ 在 HTML 里写内联 `<style>` / `<script>`（除极小的主题引导）
- ❌ 页面直接 `fetch("/api/...")`，绕过 `common/api.js`
- ❌ 在 `domain/` 里 import SQLAlchemy
- ❌ 在 `features/` 之间互相 import
- ❌ 新增目录 `utils/`、`helpers/`、`misc/`
- ❌ 前端引第三方 UI 库或 CDN
- ❌ 把运行时产物（`data/workspace/*`）提交进仓库
