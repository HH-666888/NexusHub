## 三、本方案（Agent 工作流编排工具）对照得分点

### 已命中的
- Agent / 工作流设计 8% —— 方案核心就是它，且命题背景点名"Multi-Agent 系统编排"
- 大模型集成质量 8% —— 双模型（GPT 规划 + DeepSeek 执行）+ Function Calling 是实打实的集成深度
- 选题创新 10% —— "Agent 的 Agent""成本感知路由"确属未被满足的需求
- 技术方案创新 8% —— 质量/成本帕累托是差异化叙事
- 在线演示 / 端到端可见性天然强

### 当前缺口（按分值排序，全部是可补的）
| 缺口 | 丢分 | 补法（低成本高性价比） |
|---|---|---|
| 无 RAG | 6% | 对"当前项目代码库 + 依赖文档"做向量检索，让子 Agent 先检索再改码；顺带产出检索命中率对比数据 |
| 无多模态 | 5% | 截图/Figma 图 → 直接生成页面（视觉输入）；语音下需求（Web Speech API）；生成式 UI |
| 无 MCP / 工具集成 | 4% | 把"文件读写 / 执行命令 / 浏览器预览 / GitHub 提交"做成 MCP Server，前端可视化工具调用链 |
| 无 AI 安全与可控性 | 4% | 沙箱无害化 + 危险命令拦截 + 人工确认点（Human-in-the-loop）+ 输出过滤 + 超时兜底 |
| 后端重、前端轻 | 前端工程 10% | 前端必须是 React/Next + **TypeScript**，组件化拆分、懒加载、代码分割要能在文档里指出来 |
| "万能工具"定位 | 实用性 5% | 见下方风险 1 |

**只算 AI 技术深度这一项：现状约 16/35，补齐后可达 30/35；叠加前端 10% 与实用性 10%，总分差距是量级性的。**

## 四、必须直面的 5 个风险

1. **定位风险（最大）**：评分表里"场景真实性——问题定义是否清晰"占 5%，"选题创新"占 10%。"给所有人开发所有东西"是**平台叙事**，不是**问题定义**。评委对"万能工具"的默认反应是"这不就是 Cursor / Claude Code / Dify / n8n 吗"。→ 必须收窄成一句可验证的承诺。
2. **形态风险**：官网白纸黑字"前端 Web 应用为主要呈现形态，后端服务不作为重点考察对象"。本方案的核心资产（编排引擎、模型路由、Docker 沙箱）**全在后端**。→ 必须把后端能力翻译成前端可看见的东西：实时 DAG 拓扑、每个子 Agent 的思考流、token/成本实时面板、自主修复的前后对比 diff。
3. **原创风险**："严禁直接使用开源项目包装参赛"。→ 差异化必须**可量化**，不能只靠话术。
4. **时间风险**：距省赛作品提交截止 **28 天**（11-18）。另：**10-31 15:00 前**完成省赛缴费即可参加"作品赛预指导活动"（评委专业评分 + 修改建议 + 可二次修改），这是白送的评委反馈，**只剩 10 天**。
5. **可用性/成本风险**：在线演示要求"评审期间保持服务可用"，腾讯云单机跑 Docker 沙箱需要限内存/CPU、用完销毁、预览端口不裸奔；GPT + DeepSeek 双 API 自费，需要预算与降级策略。

## 五、建议的定位收敛（一句话版）

> **不做"什么都能生成的万能工具"，做"能自己把代码跑起来、把报错修掉、并告诉你每一分钱花在哪的自主交付 Agent"。**

差异化的三根支柱，且每根都能出数据：
1. **自主修复闭环**（Generate → Run → Read Error → Fix → Re-run）—— 证明"软件包不是一次生成出来的"
2. **成本感知模型路由**（贵模型只做规划与裁决，便宜快速模型做执行）—— 用同任务对比表证明"质量接近单模型基线，成本降一个量级"
3. **全过程可观测**（规划 DAG、子 Agent 思考流、成本仪表盘、人工确认点）—— 同时喂饱"AI 交互体验 3%"与"技术方案创新 8%"
