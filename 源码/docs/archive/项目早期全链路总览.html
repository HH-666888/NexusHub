分支② 项目定位（为什么选它）
产品：Agent工作流编排工具（老板Agent规划 + 员工Agent执行）
命中推荐方向：①Agent智能助手 · ④协同办公 · ⑦代码开发辅助

分支③ 技术架构（五层定型）
前端层：React/Vue + Monaco编辑器 + React Flow工作流画布 + SSE流式日志
编排层（核心）：自研引擎——任务分解/DAG调度/上下文/重试/人工确认点（赛题深度应用证明点）
模型层：GPT(规划决策·少量贵) + DeepSeek(执行·快便宜) + MiMo(可选)，Function Calling + MCP
执行层：Docker沙箱（你的腾讯云150.158.151.52当宿主）
数据层：MySQL + Redis + 文件系统
分支④ 执行层（Web为什么能跑代码）
原理：浏览器≠执行者，云端容器才是（像远程登录服务器）
链路5步：请求 → 主agent规划 → dockerode写码进容器 → docker exec跑命令 → SSE回传+iframe预览
安全3铁律：限内存CPU · 用完销毁 · 预览端口不外裸（后端代理+token）
分支⑤ 数据层（不换库，分层存）
MySQL主力5表：users账号 · sessions会话 · messages对话 · tasks任务树(parent_task_id存层级) · cost_records成本
Redis实时层：只学5命令 SET/GET/DEL/EXPIRE/HSET——任务实时状态/SSE心跳/限流
文件不入库：/workspace/{会话ID}/ 只存路径
结论：不用硬上PostgreSQL，MySQL 8 + Redis 够用
分支⑥ 最终效果（一句话→可运行软件包）
旅程6步：一句话 → 主agent规划 → 子agent并行执行 → 自主修复闭环 → 浏览器实时预览 → 交付软件包
核心真相：软件包不是一次生成，是"生成→运行→读报错→修复→再运行"循环出来的（=编排引擎价值）
能力边界：中小型项目稳定做到；大型需多轮迭代；依赖密钥的项目演示时避开
演示选型：数据看板类3–5分钟，必杀技=注入报错展示自修复
分支⑦ 形态合规（Web=网页版Codex）
Web含义：约束"浏览器访问的交付形态"，≠只能做展示网页
定位：网页版Codex（浏览器驾驶舱+云端执行），赛题认的就是这个形态，桌面版Codex反而不合规
演示合规点：评委用浏览器打开你部署在服务器上的站点即达标
分支⑧ 交付闭环（一个产出·多通道）
MVP三条主通道：①在线预览(网页内iframe直开) · ②在线源码浏览(Monaco) · ③ZIP下载(源码+README+启动脚本)
两条加分通道：④一键部署生成公网链接跳转 · ⑤GitHub导出
用户旅程：看效果 → 改代码 → 拿走软件包，全程不离开你的网页
