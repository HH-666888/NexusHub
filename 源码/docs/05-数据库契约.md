## 声明

1. **MySQL 是唯一真相源。** 运行状态、事件、成本、产物、会话、语料，全部在这里。文件系统只允许放两类东西：`content/playbook/*.md` 源文件，和导出时的临时文件。
2. **ORM 不是契约。** `db/models.py` 只描述存储形状；对外契约在 `domain/`（Pydantic）。
3. **只有 `features/*/repo.py` 与 `db/` 可以写 SQL。** 其它任何模块碰 SQLAlchemy 都算违规（见 04 §4.2 的 D5）。
4. **改表结构 = 改本文件。** 先改这里，再写 Alembic 迁移，再改 ORM 与 Pydantic。
5. 本文件不写业务规则。业务规则在 `pipeline/` 与 `features/*/service.py`。

## 1. 实例级设置

| 项 | 值 | 理由 |
|---|---|---|
| 版本 | MySQL **8.0.30+** | 需要 JSON 多值索引、`ngram` 全文解析器、`utf8mb4_0900_ai_ci` |
| 存储引擎 | InnoDB（唯一） | 事务与行锁；MyISAM 没有事务，禁用 |
| 字符集 | 库/表/连接三处 `utf8mb4` | 漏掉"连接"一处就会出乱码 |
| 排序规则 | `utf8mb4_0900_ai_ci` | 8.0 默认，中文比较正确 |
| 时区 | 连接固定 `time_zone='+00:00'`；业务时间存 **epoch 毫秒 BIGINT** | 不用 `DATETIME`，从根上消灭时区问题 |
| `sql_mode` | `STRICT_TRANS_TABLES,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION` | 禁止静默截断；写入超长必须报错 |
| 隔离级别 | `READ-COMMITTED` | 单写者场景足够，减少间隙锁 |
| `max_allowed_packet` | `64M` | 产物内容入库，需要容纳单个 HTML |
| `innodb_buffer_pool_size` | `512M`（演示机） | 库总量预计 <500MB |
| 字符集/时区在连接串里 | `?charset=utf8mb4` + 启动时 `SET time_zone='+00:00'` | 双保险 |

## 2. 表清单

| 表 | 作用 | 增长量级 | 保留策略 |
|---|---|---|---|
| `users` | 账号 | 个位数～几十 | 永久 |
| `sessions` | 会话（存 token 哈希） | 每次登录 1 行 | 过期即清（登录时顺带清） |
| `runs` | 一次构建 | 每次生成 1 行 | 永久 |
| `run_events` | 事件流（可回放的唯一依据） | 每次生成 200–700 行 | 永久（约 1–3KB/行） |
| `cost_records` | 每次模型调用一笔 | 每次生成 10–20 行 | 永久 |
| `artifacts` | 产物内容（HTML/JSON） | 每次生成 2–5 行 | 同 run 同名只留最新 |
| `settings` | 每用户配置 KV | 每用户 ≤3 行 | 永久 |
| `rag_documents` | 语料文档 | ≤100 行 | 随 `content/` 重建 |
| `rag_chunks` | 语料切块 + 向量 | 语料 <1 万行 | 随文档重建 |
| `idempotency_keys` | 建运行防连点 | 每次建运行 1 行 | 30 秒后清理 |
| `run_databases` | 每次运行建的库（产物用） | 每次全栈运行 1 行 | 随运行删除 |
| `run_runtimes` | 运行时的进程/容器记录 | 每次预览 1 行 | 随运行删除 |

**一次生成约 15–60KB（事件为主）。1000 次生成 ≈ 20–60MB。** 演示量级下毫无压力。

## 3. 表结构（DDL 为准）

### 3.1 users

```sql
CREATE TABLE users (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  username      VARCHAR(32)  NOT NULL COMMENT '登录名，唯一',
  display_name  VARCHAR(64)  NOT NULL COMMENT '界面显示名',
  password_hash VARCHAR(255) NOT NULL COMMENT 'argon2id 字符串，禁止明文/MD5',
  created_at    BIGINT       NOT NULL COMMENT 'epoch 毫秒',
  updated_at    BIGINT       NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_users_username (username)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

| 列 | 存什么 | 不存什么 |
|---|---|---|
| `username` | 3–32 字符，字母数字下划线 | 邮箱（本期不做邮箱登录） |
| `display_name` | 用户可见名，可与 `username` 相同 | — |
| `password_hash` | argon2id 编码串 | **绝不存明文、绝不存 MD5/SHA1** |

### 3.2 sessions

```sql
CREATE TABLE sessions (
  id         CHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL
             COMMENT 'sha256(token) 的十六进制；token 本身不落库',
  user_id    BIGINT UNSIGNED NOT NULL,
  expires_at BIGINT NOT NULL COMMENT 'epoch 毫秒',
  created_at BIGINT NOT NULL,
  PRIMARY KEY (id),
  KEY idx_sessions_user (user_id),
  KEY idx_sessions_expires (expires_at),
  CONSTRAINT fk_sessions_user FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

**关键**：cookie 里放的是随机 token，库里存它的 sha256。库被读走也拿不到可用的会话。

### 3.3 runs

```sql
CREATE TABLE runs (
  id               VARCHAR(26) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  user_id          BIGINT UNSIGNED NOT NULL,
  prompt           TEXT NOT NULL COMMENT '用户原话，一字不改',
  stage            VARCHAR(16) NOT NULL COMMENT 'spec|arch|ui|build|assemble|verify',
  status           VARCHAR(16) NOT NULL COMMENT 'running|paused|done|failed|cancelled',
  workflow_version VARCHAR(8)  NOT NULL DEFAULT 'v1',
  total_cost_cny   DECIMAL(12,6) NOT NULL DEFAULT 0.000000,
  input_tokens     INT UNSIGNED NOT NULL DEFAULT 0,
  output_tokens    INT UNSIGNED NOT NULL DEFAULT 0,
  thinking_tokens  INT UNSIGNED NOT NULL DEFAULT 0,
  created_at       BIGINT NOT NULL,
  updated_at       BIGINT NOT NULL,
  PRIMARY KEY (id),
  KEY idx_runs_user_time (user_id, created_at DESC, id DESC) COMMENT '游标分页专用',
  KEY idx_runs_status (status),
  CONSTRAINT fk_runs_user FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

| 列 | 规则 |
|---|---|
| `prompt` | 原文不改写、不 trim 内部空白；长度 1–2000 字（服务端校验） |
| `stage` / `status` | 用 `VARCHAR` 而不是 `ENUM` —— 加值不用改表 |
| `thinking_tokens` | **计入 output 预算**，这条是全局不变量 |
| `total_cost_cny` | 与 `cost_records` 汇总一致（同一事务里更新） |

**契约字段与存储列的映射**（不要混用）：

```
Run.usage  =  { input: input_tokens, output: output_tokens, thinking: thinking_tokens }
Run.totalCostCny  =  total_cost_cny
```

对外是嵌套对象 `usage`，存储是三个平列 —— 转换只允许出现在 `features/runs/repo.py`。

### 3.4 run_events

```sql
CREATE TABLE run_events (
  id         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  run_id     VARCHAR(26) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  seq        INT UNSIGNED NOT NULL COMMENT '同一次运行内从 1 递增',
  kind       VARCHAR(16) NOT NULL COMMENT 'phase|spec|arch|ui|modules|usage|check|artifact|error|tool|retrieval|cost|…',
  payload    JSON NOT NULL COMMENT '契约书 §7 的整条事件',
  created_at BIGINT NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_events_run_seq (run_id, seq),
  CONSTRAINT fk_events_run FOREIGN KEY (run_id) REFERENCES runs (id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

| 规则 | 说明 |
|---|---|
| **只追加，不更新、不删除** | 回放的唯一依据；删了就等于篡改历史 |
| `seq` 从 1 开始连续 | 单写者分配（单 worker），不需要分布式序列 |
| `payload` 放整条事件 | 与 SSE 帧**完全同一份 JSON**，回放与直播走同一条前端代码 |
| 批量写 | 一次 `INSERT` 多行，与前端 250ms/4000 字合并对齐 |
| 不含代码全文 | 代码在 `artifacts`；事件里只放摘要（`modules` 事件是摘要） |

> `payload` 里**必须有** `kind` 字段且与外层 `kind` 列一致。写入时由 `pipeline/events.py` 统一构造，禁止手拼。

### 3.5 cost_records

```sql
CREATE TABLE cost_records (
  id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  run_id          VARCHAR(26) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  stage           VARCHAR(16) NOT NULL,
  model           VARCHAR(48) NOT NULL,
  price_tier      VARCHAR(8)  NOT NULL COMMENT 'peak|offPeak',
  input_tokens    INT UNSIGNED NOT NULL DEFAULT 0,
  output_tokens   INT UNSIGNED NOT NULL DEFAULT 0,
  thinking_tokens INT UNSIGNED NOT NULL DEFAULT 0,
  cache_hit_tokens INT UNSIGNED NOT NULL DEFAULT 0,
  cost_cny        DECIMAL(12,6) NOT NULL,
  latency_ms      INT UNSIGNED NOT NULL,
  created_at      BIGINT NOT NULL,
  PRIMARY KEY (id),
  KEY idx_cost_run_time (run_id, created_at),
  CONSTRAINT fk_cost_run FOREIGN KEY (run_id) REFERENCES runs (id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

**一次模型调用 = 一行。** 这是"每一分钱花在哪"的原始凭证，不能被汇总值覆盖（历史上踩过 `usage` 被覆盖的坑）。

### 3.6 artifacts

```sql
CREATE TABLE artifacts (
  id         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  run_id     VARCHAR(26) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  kind       VARCHAR(8)  NOT NULL COMMENT 'html|json',
  name       VARCHAR(64) NOT NULL COMMENT 'spec.json|arch.json|ui-spec.json|manifest.json|plan.html|answers.json|ack.json|modules/<id>.json',
  content    LONGTEXT NOT NULL COMMENT '产物正文（决定：内容入库，不落磁盘）',
  bytes      INT UNSIGNED NOT NULL,
  sha256     CHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  created_at BIGINT NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_artifacts_run_name (run_id, name),
  CONSTRAINT fk_artifacts_run FOREIGN KEY (run_id) REFERENCES runs (id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

**两个决定**（都是为了让"备份/迁移=一个 dump"）：

1. **产物内容存库，不存磁盘。** 否则真相源有两个（DB + 文件系统），备份、迁移、导出全要处理两套。
2. **同一 run 同名产物只留最新一份**（`UNIQUE(run_id, name)` + 覆盖写）。历史版本不保留：**回放靠事件，不靠产物历史**；用户要重来就走"清空重跑"（删行）。

> `max_allowed_packet=64M` 是为了这条表。单产物上限 **1MB**（超过说明生成失控，直接判失败）。

### 3.7 settings

```sql
CREATE TABLE settings (
  user_id    BIGINT UNSIGNED NOT NULL,
  `key`      VARCHAR(32) NOT NULL COMMENT 'appearance|modelConfig',
  value      JSON NOT NULL,
  updated_at BIGINT NOT NULL,
  PRIMARY KEY (user_id, `key`),
  CONSTRAINT fk_settings_user FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

| key | value 形状 |
|---|---|
| `appearance` | `{ font, scale, accent, tint }`，全部有默认值 |
| `modelConfig` | `{ decideModel, executeModel, effort }`，**不含密钥** |

**密钥永远只从环境变量来**，不进库、不进前端。

### 3.8 rag_documents / rag_chunks

```sql
CREATE TABLE rag_documents (
  id         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  path       VARCHAR(255) NOT NULL COMMENT '相对 content/playbook 的路径',
  title      VARCHAR(128) NOT NULL,
  sha256     CHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  bytes      INT UNSIGNED NOT NULL,
  updated_at BIGINT NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_rag_doc_path (path)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;

CREATE TABLE rag_chunks (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  document_id BIGINT UNSIGNED NOT NULL,
  chunk_index INT UNSIGNED NOT NULL,
  heading     VARCHAR(255) NULL COMMENT '章节标题，用于在界面显示“依据：xxx §2”',
  text        TEXT NOT NULL,
  embedding   BLOB NOT NULL COMMENT 'FLOAT32 小端序，长度 = dim * 4',
  dim         SMALLINT UNSIGNED NOT NULL,
  model       VARCHAR(48) NOT NULL COMMENT 'embedding 模型名，换模型必须重建',
  PRIMARY KEY (id),
  UNIQUE KEY uk_chunk_doc_idx (document_id, chunk_index),
  FULLTEXT KEY ft_chunk_text (text) WITH PARSER ngram,
  CONSTRAINT fk_chunk_doc FOREIGN KEY (document_id) REFERENCES rag_documents (id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

| 项 | 规定 |
|---|---|
| 切块 | 512 字 / 重叠 64 字，按 `##` 标题边界切 |
| 向量 | `FLOAT32` 小端序存 `BLOB`，不用 JSON（体积 3–5 倍且要解析） |
| 检索 | ① numpy 精确余弦（语料 <1 万块，毫秒级）② `MATCH ... AGAINST` 全文召回 ③ 加权合并取 Top-3 |
| 重建 | 启动时比对 `sha256`，变了的文档整篇重建，未变跳过 |
| 引用 | 检索结果必须带 `path` + `heading` + `chunk_index`，界面显示"依据" |

**为什么不用第二个数据库**：语料 <1 万块时，精确余弦比近似索引更准，且省一个进程。规模上去再换 FAISS/Chroma，`ai/rag/retrieve.py` 接口不变。

### 3.9 idempotency_keys

```sql
CREATE TABLE idempotency_keys (
  user_id    BIGINT UNSIGNED NOT NULL,
  `key`      VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  run_id     VARCHAR(26) CHARACTER SET ascii COLLATE ascii_bin NULL,
  created_at BIGINT NOT NULL,
  expires_at BIGINT NOT NULL,
  PRIMARY KEY (user_id, `key`),
  KEY idx_idem_expires (expires_at),
  CONSTRAINT fk_idem_user FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

`POST /runs` 带 `Idempotency-Key` 时：30 秒内同 key 直接返回已建的 `run_id`（防连点建出两条运行 = 两次钱）。写入时顺手 `DELETE WHERE expires_at < now()`。

## 5. 事务与并发

| 规则 | 说明 |
|---|---|
| 一次模型调用的记账是**一个事务** | 插 `cost_records` + 更新 `runs.total_cost_cny/usage` 同时成功或同时失败 |
| 事件批量写是**一个事务** | 一批事件一次 `INSERT`，避免半批可见 |
| 不要长事务 | 模型调用（十几秒到几分钟）**绝不能包在事务里**；先调用，再记账 |
| 单写者 | 单 worker + asyncio，`seq` 与 `seq` 唯一索引兜底 |
| 预算闸门竞态 | 花费检查在内存里算，写入时再校验一次；超限直接 `failed`，不静默继续 |
| 建运行防重 | `idempotency_keys` 主键冲突即返回已有 `run_id`（不靠 SELECT 判存在） |

## 6. 备份与恢复

```bash
# 备份（评审期每天一次；演示前一次）
mysqldump --single-transaction --no-tablespaces --skip-triggers \
  -h127.0.0.1 -unexus -p nexus > backup/nexus-$(date +%F-%H%M).sql

# 恢复验证（必须真的演练一次，否则等于没做）
mysql -h127.0.0.1 -unexus -p nexus_restore < backup/nexus-2026-11-01-1200.sql
```

| 项 | 规定 |
|---|---|
| 备份范围 | 一个 dump 覆盖全部数据（**这是"产物入库"的直接收益**） |
| 恢复验收 | 恢复后能打开首页、能看到历史运行、能回放事件 |
| 迁移 | `alembic upgrade head`，一版一件事，可重复执行 |
| 种子 | `python -m app.seed`：建演示账号 + 默认外观 + 建 RAG 索引（不含任何密钥） |

## 7. 不存进数据库的东西（明确清单）

| 不存 | 存哪 |
|---|---|
| 模型 API 密钥 | 环境变量（`.env`，不进仓库） |
| 密码明文 | 不存；只存 argon2id 哈希 |
| cookie 原文 | 不存；只存 `sha256(token)` |
| 用户上传的原始文件 | 导入后解析入库，**临时文件立即删除** |
| 前端状态（选中的运行、展开的面板） | URL 参数 |
| 日志 | stdout（容器日志），不进库 |

## 8. 容量与清理

| 表 | 增长 | 清理策略 |
|---|---|---|
| `sessions` | 每次登录 1 行 | 登录时 `DELETE WHERE expires_at < now()` |
| `idempotency_keys` | 每次建运行 1 行 | 写入时删过期行 |
| `run_events` | 每次生成 200–700 行 | 永久保留（回放依赖） |
| `artifacts` | 每次生成 2–5 行 | 同名覆盖，不累积 |
| `rag_chunks` | 随语料 | 文档变更时整篇重建 |

**估算**：1000 次生成 ≈ 20–60MB；语料 1 万块 ≈ 40MB（含向量）。演示机 `innodb_buffer_pool_size=512M` 足够。

## 9. 变更流程

1. 改本文件（表结构/字段含义/索引）→ 版本号 +1。
2. 写 Alembic 迁移（一版一件事；MySQL DDL 非事务性，必须可重复执行）。
3. 改 `db/models.py`（ORM）与 `domain/`（契约）。
4. 跑：`alembic upgrade head` → `pytest tests/api` → 契约测试。

**禁止**：
- 直接改线上表、不写迁移
- 在迁移里做业务数据修复（数据修复单独写脚本，可回滚）
- 用 `SELECT *`（列可能有敏感字段，且会让契约漂移）
- 用 `ENUM`（加值要 `ALTER TABLE`，锁表）
