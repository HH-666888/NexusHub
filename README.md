# Nexus · 一个网页里的软件工厂

> 你在网页上打一句话，它自己走完六道工序，最后交给你一个**能运行、被验收过的软件包**。
> 全程看得见、随时拦得住、花了多少钱清清楚楚。

---

## 一、项目介绍

### 它解决什么问题

现在的 AI 编程工具本质是「对话式」的，有两个要命的问题：

1. **用户是过程的奴隶** —— 得陪着走，一轮一轮喂上下文，写偏了赶紧喊停重开
2. **它是黑盒** —— 跑到一半不知道在干什么、不知道花了多少钱、跑偏了没有后悔药

**长任务一旦在第八步失败，前面投入全废。**

所以真正要解决的不是「少打字」，而是 **长任务不失控**。拆成四个能力：

| 能力 | 含义 |
| --- | --- |
| **可观测** | 跑到第三十分钟，我知道它在干什么，每一步花了多少钱 |
| **可干预** | 任务图上任意节点能暂停、能改指令、能从那个点重跑 |
| **可恢复** | 崩了不从头开始 |
| **可预算** | 设成本上限，超了自动降档，而不是继续烧 |

### 用户

**第一场景**：学生与独立开发者 —— 有想法有需求，但缺工程能力或时间。
**远景**：所有需要把想法变成可运行软件的人。

## 二、技术架构

### 整体形态

**端口—适配器架构（六边形架构）**。依赖方向永远单向：

```
app/  ──▶  adapters/  ──▶  core/
（外壳）    （所有 IO）     （纯逻辑）
```

**内核不认识数据库、不认识 HTTP、不认识 Docker** —— 它只认识自己在 `core/ports/` 里定义的接口。

| 层 | 职责 | 约束 |
| --- | --- | --- |
| `core/` | 六阶段状态机、产物契约、双层 Agent、成本路由、失败归因、断点续跑与失效传播 | **纯逻辑，零 IO，可单元测试** |
| `adapters/` | 模型调用与成本记账、沙箱（本地进程 / Docker）、状态持久化、事件推送 | 实现 `core/ports/` 定义的接口，所有 IO 都在这里 |
| `app/` | Next.js 页面与 API 路由 | 只做编排与转发，不写业务逻辑 |

**为什么这样分层**：

1. **内核可单测** —— 不需要网络、不需要数据库就能验证归因、路由、契约校验
2. **沙箱可换** —— 本地开发用进程沙箱，线上用 Docker 沙箱，内核一行不改
3. **模型可换** —— 换供应商只改 `adapters/model/` 下一个文件

### 流程：六阶段确定性状态机

```
一句话
  │
  ├─① 规格化 ──────── 人工门禁（全流程唯一需要人的地方）
  ├─② 架构定型
  ├─③ 界面设计
  ├─④ 并行构建        ← 并行粒度是「模块」而非「文件」
  ├─⑤ 集成装配        ← 上下文最重的一刻，必须做上下文裁剪
  └─⑥ 验收与交付      ← 把①的验收标准翻译成可执行断言，闭环
```

**三条设计判断**：

1. **流程是确定性骨架，AI 是概率性肌肉。** 流程由代码推进，零 token；AI 只在每一步内部提供判断。
2. **阶段之间靠结构化产物契约衔接。** 分层多智能体最经典的失败模式是层间信息丢失 —— 产物必须结构化且可机器校验，否则上游错误可以「看起来对」。
3. **骨架线性，但带反馈回路。** 每个阶段都声明失败可以退回到哪里，因此它不是瀑布模型。

### 双层 Agent

每个阶段内部是一个自治小组：

```
阶段主 Agent（本阶段的规划 + 验收，永不写代码）
      ↓ 并行派发
执行 Agent × 1~N（本阶段的具体实现）
      ↓ 产出结构化产物
阶段主 Agent 验收 → 不过则局部重试
```

**三条铁律**：

- **阶段主 Agent 永不写代码** —— 保证最贵的模型只花在「判断」上，不花在「打字」上
- **验收者 ≠ 生产者** —— 写完某个模块的 Agent 不能是验收它的那个
- **阶段之间由代码推进，不由 Agent 决定** —— 否则复杂度和成本都是乘法级的

### 目录结构

```
源码/
├── src/
│   ├── core/                 内核：纯逻辑，零 IO，可单测
│   │   ├── pipeline/         六阶段状态机与阶段定义
│   │   ├── contracts/        阶段产物契约与校验器
│   │   ├── agents/           双层 Agent 抽象
│   │   ├── routing/          成本路由
│   │   ├── attribution/      失败归因四分类
│   │   ├── recovery/         断点续跑与失效传播
│   │   └── ports/            ★ 端口接口，内核只依赖这些
│   ├── adapters/             适配器：所有 IO
│   │   ├── model/            模型调用与成本记账
│   │   ├── sandbox/          本地进程 / Docker
│   │   └── store/            状态持久化
│   ├── app/                  Next.js 页面与 API
│   ├── components/           前端驾驶舱组件
│   └── config/               环境配置集中处
├── tests/unit/               内核单元测试
├── docs/                     设计与决策文档
└── data/                     运行时数据（不入库）
```

## 三、安装运行指南

### 环境要求

| 项 | 版本 |
| --- | --- |
| Node.js | ≥ 20（开发验证于 v24.18.1） |
| 包管理器 | npm（开发验证于 11.16.0）；pnpm 亦可 |
| Docker | 部署时需要；本地开发不需要 |

### 安装

```bash
cd 源码
npm install
```

### 配置环境变量

```bash
# 复制模板
cp .env.example .env.local      # Windows: copy .env.example .env.local
```

然后编辑 `.env.local`，填入模型密钥：

```
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_API_KEY=sk-你的密钥
```

> **`.env.local` 已被 `.gitignore` 忽略，绝不会进入公开仓库。**
> 依据赛题要求：「API 密钥等敏感信息不得出现在公开仓库中，须通过环境变量方式配置」。

### 启动

```bash
npm run dev        # 开发模式，默认 http://localhost:3000
npm run build      # 生产构建
npm start          # 生产模式启动
```

### 质量校验

```bash
npm run typecheck  # TypeScript 类型检查
npm run lint       # ESLint 规范检查
npm run test       # 单元测试
npm run verify     # 一次跑完以上全部 + 生产构建
```

### 环境变量一览

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | 模型接口地址 |
| `DEEPSEEK_API_KEY` | 无（必填） | 模型密钥 |
| `MODEL_DECIDE` | `deepseek-flash` | 决策级模型 |
| `MODEL_EXECUTE` | `deepseek-flash` | 执行级模型 |
| `SANDBOX_MEMORY_MB` | `1024` | 沙箱单容器内存上限 |
| `SANDBOX_CPUS` | `1` | 沙箱单容器 CPU 上限 |
| `SANDBOX_TIMEOUT_SECONDS` | `300` | 沙箱命令超时 |
| `MAX_PARALLEL_BUILD` | `1` | 并发构建数 |
| `RUN_COST_LIMIT_CNY` | `5` | 单次运行成本上限 |
| `DATABASE_PATH` | `./data/nexus.db` | 状态库路径 |
| `WORKSPACE_ROOT` | `./data/workspace` | 运行工作区根目录 |
